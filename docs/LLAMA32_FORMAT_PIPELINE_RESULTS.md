# L32-0029：全模格式 × 流水消融

固定 Llama 16 层、M64+15、cache80、无旋转、SP2mode8、FP32 residual mode1。全程同一组权重、量化参数与整数算法。B00 模块接口/常规调度；B10 原生格式/常规调度；B01 模块接口/协同流水；B11 原生格式/协同流水。保留所有组的 GEMM 内部双缓冲。

格式范围为每层两处 Norm 输出和 SwiGLU→Down 接口；流水范围为 QKV 后处理、Gate/Up/SwiGLU、O/Down epilogue 与 O→Gate 预取。首尾实现相同且计入端到端时间。该消融不代表移除全部硬件优化。

各组通过独立 layers0/7/15、连续3层、全16层末端输出与封存参考比对及完整生成 token/selected-logit 检查。FP32残差固定；模型质量未验收，本次不测PPL。5轮short后10轮formal，四组循环换序；repeat10主结果，repeat1辅助。所有轮次保留。

## 结果解释与保留故障

B11/B00的完整Host墙钟降低prefill11.6291%（95%CI11.0882%至12.2990%），decode2.0112%（1.6355%至2.3212%）。固定native格式时流水降低10.9546%/3.1790%。原生格式在协同流水中prefill降低0.3713%，decode增加0.2716%；prefill交互比1.00389，CI[0.99656,1.01413]跨1，不能宣称两因子总有显著协同。普通调度下prefill原生格式降低0.7575%，decode增加1.2062%。

当前B11 2161.744/45.1889token/s来自本次固定repeat10完整warm runtime。历史0018 2069.703/42.510并非同轮分母，不能将其差值算作新内核优化收益；本轮只比较同协议四格。固定源模型/数学合同，不做PPL或质量验收。

初次A1移植的3个B11检查均prefill正确、decode出现DSP异常。状态2为DSP_RUNNING而非BAD_HEADER；故障指令位于新增SwiGLU格式谓词，Llama decode绕过attention池初始化导致空上下文读取。提交6471702在SwiGLU派发前绑定当前上下文，未改算术/门槛。修复后selected0/7/15、chain3、chain16均逐位一致，完整frontend的生成token及selected-logit码与原参考一致。全部失败日志及两次仅诊断构建保留。

所有9600主计时profile按token位置HMX命令数一致；峰值/VTCM及无中间张量DDR/溢出检查通过。此为实现消融而非外部系统竞争比较，残差始终FP32。剩余已批准独立流水、SP2成本、decode共装、shape与FP向量softmax仍待完成。
