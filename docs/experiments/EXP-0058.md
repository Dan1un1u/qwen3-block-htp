# EXP-0058 — HVX vdeal V-carrier transpose

## Decision

EXP-0057 is locally adoption-eligible and becomes the provisional source parent for the next compatible optimization. The selected W4U8 baseline remains EXP-0055 until the user explicitly promotes a candidate.

## Profiling basis

After the exact vgather change, V packing still reports about 4.9k aggregate worker ticks per block. Each gathered vector is laid out as four contiguous 32-byte rows, while integer HMX consumes 32 adjacent four-row words. The current candidate still creates those words with a 32-iteration scalar loop.

## Hypothesis

The required lane mapping is a seven-bit rotation: output index bits contain the five channel bits followed by the two row bits. One byte `vdeal` rotates the source-index relationship by one bit, so five successive byte `vdeal` operations produce the exact 4-by-32 transpose. One vector store can then replace 32 scalar word stores.

## Candidate

Keep the EXP-0057 exact vgather, lookup table, scheduling, qparams, projections, Softmax, HMX, residual, and MLP paths unchanged. Replace only the scalar V-carrier transpose and store. The control and candidate are selectable in one binary.

## Gates

The final output and QK, probability, and AV audit boundaries must remain byte-exact to EXP-0057 and the independent reference. Formal runs require exactly 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one FastRPC execution unit, one HMX owner, and no QNN. V-pack work, Attention ledger, and complete Host wall must strictly improve at repeat one and repeat ten.

## Result

All correctness and physical gates passed. The five-stage `vdeal` transpose reduced V-pack work by 43.2% at repeat one and 43.6% at repeat ten. The additive Attention interval fell by 5.9% and 5.4%, while complete Host wall improved by 0.50% and 1.22%. EXP-0058 is locally adoption-eligible; the selected W4U8 baseline remains EXP-0055 until the user explicitly promotes a candidate.
