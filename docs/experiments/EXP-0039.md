# EXP-0039 — Phase-aware VTCM overlay and Gate/Up producer depth

## Approval and source

Approved by the user on 2026-08-29 to address the structurally small W4F16
advantage of the current Selected Baseline. The source is exactly
`W4F16-EXP0038-NORMS` at
`24917512fc35adfd22f97b5123473bb6a7518fd0`. This experiment does not reopen
the rejected EXP-0038 QKV or AV-to-O candidates and does not change the
Selected Baseline unless the user later promotes a passing result.

## Hypothesis

The EXP-0038 allocator monotonically reserves objects from all block phases at
once. In the selected `norms` mode the full row-major normalized tensor is no
longer live, while Attention scratch and MLP producer buffers have disjoint
lifetimes. The reported W4F16 peak is nevertheless 8,171,008 of 8,388,608
bytes, leaving too little space for a materially deeper Gate/Up producer ring.

The experiment first replaces this false simultaneous-liveness contract with
an explicit phase-aware overlay. Capacity recovery alone is not a speed claim.
Only after an overlay-only candidate proves identical arithmetic and physical
behavior may the recovered VTCM be used to increase bounded Gate/Up lookahead
between packed-W4 DMA, HVX expansion and HMX consumption.

## Fixed contract

- The Execution Unit is the real Qwen3-1.7B layer-14 complete block at `M=64`
  in one FastRPC invocation, measured at repeat one and repeat ten.
- The paired control is `W4F16-EXP0038-NORMS`; its projection mathematics,
  packed W4 values, per-channel scales, FP16 common operators, combined norm
  boundaries, Attention schedule and Crouton-native Batch-8 MLP remain fixed.
- Every candidate requests exactly 8,388,608 VTCM bytes, uses one HMX owner,
  and permits no QNN, intermediate DDR, spill/fill, extra FastRPC boundary or
  pre-expanded persistent weight artifact.
- Every candidate must be byte-exact with the paired control and pass the
  independent Implementation Reference. VTCM aliasing is permitted only for
  objects whose measured execution phases cannot overlap.
- Host wall is primary. The additive Gate/Up ledger interval is the local
  optimization boundary; DMA, HVX expansion and HMX waits are overlapping
  diagnostics and are not summed as latency.

## Stage A — Overlay without schedule change

Audit every VTCM object by allocation size and first/last use. Remove storage
that is provably dead in combined-norm mode and overlay disjoint Attention and
MLP phase arenas. Keep command order, buffer counts, prefetch distance and
worker ownership unchanged. The candidate must preserve byte-exact output,
zero intermediate DDR, the exact 8 MiB request, one HMX owner and no spill or
fallback. It must not regress complete Host wall before Stage B proceeds.

## Stage B — Spend capacity on Gate/Up lookahead

Use only the capacity recovered in Stage A to create a genuinely deeper
bounded producer/consumer plan for Gate and Up. Candidate selection must be
driven by the current critical path: packed-weight DMA, HVX expansion,
producer backpressure and HMX-ready wait. A storage-only ring or a ring that
does not expose additional concurrent work is not a passing result.

The local speed gate requires both the Gate/Up ledger interval and complete
W4F16 Host wall to improve strictly over the EXP-0038 control at repeat one
and repeat ten. Correctness or physical-contract failure stops the affected
candidate; a performance failure is retained as valid negative evidence and
does not alter the Selected Baseline.
