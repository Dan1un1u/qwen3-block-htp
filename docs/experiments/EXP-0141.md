# EXP-0141 — W4U8 O-projection batch-eight revalidation on ring3

## Decision and hypothesis

The user's continuing autonomous W4F16/W4U8 specialization loop authorizes
this bounded W4U8 experiment on 2026-09-01. It branches from EXP-0124 source
commit `95fadff5930d9081678ad99bb62ef84849ee1897` and selects that experiment's
ring3 cell as both the logical and physical parent. The parent already includes
the accepted W4U8 single-fence Gate/Up ring16 plan, four-output Down batching,
the frozen public common layer and the current integer Attention path.

EXP-0100 previously showed that issuing eight O-projection output tiles per HMX
command instead of four reduced O wall time by about 7% and halved its command
count, but its older complete-block lifecycle failed the repeat-one Host gate.
The current parent materially changes both the upstream QKV/Attention arrival
and the downstream MLP lifecycle. The hypothesis is that the proven local O
command reduction can now land on complete Host wall without disturbing the
ring3 producer/consumer schedule. This is a revalidation under a changed
execution lifecycle, not another blind batch-width sweep.

## Gates

Control is complete EXP-0124 ring3 with O batch four. Candidate changes only O
projection HMX batch width from four to eight output tiles. Q/K/V batch four,
QKV ring depth and worker assignment, weights, W4 values, qparams, U8
activations, Attention, residuals, Gate/Up ring16, Down batch four, public DDR
boundaries, FastRPC and QNN-free execution remain fixed.

Both cells must produce byte-exact output `69f22eeb035e5ec5`, zero maximum LSB
error, and zero existing input-norm, score, probability, AV, QKV operand and
W4 expansion audit mismatches. They must request exact 8 MiB VTCM, retain zero
intermediate DDR and spill/fill, one FastRPC Execution Unit, one HMX owner, and
identical weight bytes, HMX tile pairs, qparams and peak plan. Only O HMX/DMA
command grouping may differ, with sixteen four-tile commands becoming eight
eight-tile commands.

The candidate passes only if O projection and complete Host wall strictly
improve in ordinary and paired repeat-one and repeat-ten medians over five
rotated rounds, while Gate/Up and Down each regress by no more than 0.5% in
either ordinary or paired medians. PC-027 and PC-028 are mandatory. A local
pass remains pending user decision and cannot promote a Selected Baseline.

## Formal result and rejection

Formal evidence was collected on stable boot
`77ccafe0-8817-4976-bdae-15af5608d4ff` from source commits
`1904a6581642a115df3b84f79a27890c89958dcc` and validator-only follow-up
`0b472a9946570a473307ff6d4f06d6f39a0f5769`. Both cells produced output hash
`69f22eeb035e5ec5`, zero maximum LSB error and byte-identical input-norm,
score, probability and AV audit hashes. They retained exact 8 MiB VTCM,
identical 5,570,272-byte peak plans, zero intermediate DDR and spill/fill, one
FastRPC execution unit and one HMX owner.

The intended command reduction occurred exactly: O commands fell from sixteen
to eight per block, total HMX commands from 128 to 120, weight DMA descriptors
from 512 to 496, and O-related prefetch/overlap publications from 44 to 36.
O improved 7.267% ordinary and 6.907% paired at repeat one, and 7.531% ordinary
and 7.442% paired at repeat ten. Complete Host wall improved 0.615%/0.589% at
repeat one and 0.983%/0.826% at repeat ten.

The predeclared preservation gate nevertheless fails: repeat-ten Down ordinary
median regressed 0.810%, above the 0.5% ceiling, although its paired median was
+0.490%. Gate/Up improved at both repeats. Because gates may not be weakened
after seeing evidence, the candidate is rejected and EXP-0124 ring3 batch-four
remains the provisional parent. The local O gain and net Host gain remain valid
evidence but do not change a Selected Baseline.
