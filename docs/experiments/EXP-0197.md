# EXP-0197 — Direct-n decode LM-head batch-sixty-four

## Decision and purpose

EXP-0196 removes decode LM-head W4-to-S8 expansion and raises complete decode
to 41.403837 token/s.  Its packed-W4 batch-thirty-two path is now DMA-bound:
the LM-head weight-DMA lifetime is about 2.714 ms/token and observed DMA wait
is about 2.16 ms/token.  EXP-0197 tests whether filling each existing two-MiB
phase-dead expanded-weight slot with sixty-four packed-W4 output tiles reduces
command and descriptor overhead while retaining the same weight bytes and HMX
work.

## Bounded implementation

One binary compares direct packed-W4 LM-head groups of thirty-two and
sixty-four only during logical-M1 decode.  Because each legacy expanded-weight
arena is one MiB while a batch-sixty-four packed group is two MiB, the final
candidate carves two two-MiB slots plus activation, output and argmax storage
from Transformer-phase-dead VTCM between the resident-bias prefix and the
persistent KV-tail suffix.  Transformer kernels, quantization, vocabulary
traversal, resident bias table, M64 prefill and every tensor value are
unchanged.

Correctness requires byte-exact selected token IDs, selected U8 codes, output
hashes, audited hidden tensors and cache.  Physical evidence requires exact
8 MiB VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC, one HMX
owner, no QNN, zero decode LM-head expansion, unchanged weight bytes and HMX
tile pairs, and LM-head commands falling from 149 to 75.  Five rotated
193-step pairs must improve complete decode and LM-head wall before formal
testing.  Failure closes further LM-head batch-width search and returns the
loop to a different module-level hypothesis.
