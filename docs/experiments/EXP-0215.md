# EXP-0215 — Full-stack M64 prefill direct-W4 MLP integration

## Decision and purpose

EXP-0214 proved on real layer-14 M64 projections that HMX can consume the
reordered packed-W4 carrier directly and that deleting explicit HVX W4-to-S8
expansion materially lowers true projection wall time.  Under the user's
approved open-ended prefill loop, EXP-0215 applies that physical contract to
Gate, Up and Down across the complete W4U8 transformer stack while leaving
decode and all non-MLP prefill work unchanged.

The source parent is evidence-valid EXP-0214 at
`70dd554e507ab4705fb64d39f2708d8082e867ab`.  The direct control remains the
same complete M64 prefill path inherited from EXP-0211, where these MLP
projections stage packed W4, explicitly expand it to S8 with HVX and then feed
U8 x S8 HMX.  The candidate selects direct `weight.n` packed-W4 HMX only for
M64 Gate/Up/Down.

## Gates

Correctness requires byte-identical complete prefill hidden output, cache,
selected codes and tokens to the direct control.  Physical requirements remain
exactly 8 MiB VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC
execution unit, one HMX owner, no QNN and zero explicit W4-to-S8 expansion for
the candidate MLP projections.  Weight values, scales, qparams, output
encoding, Attention mathematics, KV-cache contract, decode path, LM head,
F16F16 and W4F16 may not change.

Performance ranks by alternating-order, directly measured complete prefill
Host wall and tokens/s.  Local counters explain the result but cannot replace
the token boundary.  A failed candidate is retained as negative evidence but
does not stop the user-authorized prefill loop; the next experiment must use a
new physical hypothesis.  No baseline is promoted without explicit user
approval.
