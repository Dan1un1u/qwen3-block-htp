# EXP-0149 — Real consecutive-layer vertical slice

## Decision and purpose

The user approved the staged single-layer, consecutive-layer, then full-stack
roadmap on 2026-09-01 and allowed continuation after EXP-0148.  EXP-0149 is the
required PC-034 gate: it executes Qwen3 layers 13, 14 and 15 consecutively as
one standalone DSP Execution Unit.  It proves that layer transitions and three
independent persistent caches are runtime-owned before the project considers
replicating all 28 layers.  It is an integration/correctness experiment with no
speed gate and no baseline promotion.

## Fixed scope

The source parent is EXP-0148 commit
`63575b8812f485936d35d8843c57aa41c9e2103c`.  A declared full-model teacher
supplies only the real hidden state entering layer 13 and the position metadata
for prompt positions 0-63 and decode positions 64-71.  The runtime must feed the
layer-13 output directly to layer 14 and the layer-14 output directly to layer
15 inside VTCM.  Host replay files, Host calls or DDR hidden-state buffers are
forbidden between those layers.  Each selected layer computes and appends its
own K/V; imported runtime K/V is forbidden.

The Prepared Decode Session retains the versioned 28-layer ABI from EXP-0148
and activates cache descriptors for layers 13, 14 and 15.  All three cache
lengths start at zero, reach 64 after prefill, and then advance in lockstep to
72.  Persistent per-layer K/V may reside in DDR and its traffic is reported by
layer.  Weights remain legal immutable DDR inputs and are streamed one layer at
a time; retired Attention and MLP VTCM regions must be overlaid between layers
instead of allocating three simultaneous block plans.

## Gates and stop conditions

Static audit first proves that the three-layer weight/package layout and phase
overlay fit the exact 8 MiB grant without hidden spill.  Correctness then uses
an independent three-layer implementation reference for F16F16, W4F16 and
W4U8.  It checks the final layer-15 output and every selected layer's cache after
prefill and after each consecutive decode step; W4U8 requires zero LSB and the
FP16 variants require no non-finite values, cosine at least `0.99999`, and the
composition-aware elementwise tolerance
`abs(actual-reference) <= 0.0625 + 0.002*abs(reference)`. Formal execution uses one FastRPC
invocation per three-layer prefill/decode step, one HMX owner, no QNN, zero
intermediate DDR and zero spill/fill.  Complete profiling reports the slice and
each layer separately, including per-layer persistent-cache traffic.

The experiment stops before formal performance collection if any layer
transition requires a Host roundtrip, hidden-state DDR spill, runtime K/V
import, replacement of the versioned cache ABI, or a change to the accepted
per-recipe block mathematics.  Passing EXP-0149 permits registration of a
separate full-transformer-stack experiment; it does not silently create one.

## FP16 composition diagnostic — 2026-09-01

Source commit `9ff5f30` adds diagnostic-only helpers that replay layers 13,
14 and 15 separately while feeding each captured DSP output into the next
layer's independent software reference. These helpers do not change the
resident three-layer implementation, its physical contract or the formal
gate.

The local-layer audit shows deterministic, small FP16 differences in both
F16F16 and W4F16. Replacing the independent software Attention/O boundary
with the captured DSP boundary reduces the layer-13 and layer-14 final-output
error to at most `0.0625`; layer 15 retains two `0.125` outliers in hidden
channel 1999, consistent with an additional Down-HMX accumulation-order
difference. A full scalar/serial schedule still reaches `0.1875` after the
three-layer prefill, so disabling the optimized schedule does not repair the
composed absolute-only gate.

Across the formal optimized captures, the inherited `max_abs <= 0.0625` gate
has 28 F16F16 and 20 W4F16 violations when the nine outputs and all six cache
tensors are considered. The violating values are only 3 FP16 ULP for F16F16
and 5 FP16 ULP for W4F16; minimum cosine remains above `0.9999975`, and there
are no non-finite values. A diagnostic, non-authoritative mixed tolerance
`abs(actual-reference) <= 0.0625 + 0.002*abs(reference)` passes every captured
output and cache. The maximum relative term actually required is `0.0008184`
for F16F16 and `0.0012377` for W4F16.

This evidence rules out W4/A8 quantization as the cause because F16F16 shows
the same behavior. It also rules out a random hardware fault or a broken layer
handoff: the differences are reproducible, local boundaries remain close,
W4U8 remains exact, and every physical gate still passes. The current
interpretation is expected non-associative HMX/HVX FP16 rounding accumulated
over consecutive layers. The user approved the composition-aware FP16 gate on
2026-09-01. EXP-0149 remains incomplete only until the three recipes are
formally revalidated and complete multi-round profiling evidence is collected.
