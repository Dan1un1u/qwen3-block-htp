# EXP-0171 — Row-selective W4U8 M1 SwiGLU publication

## Decision and purpose

The user authorized a continuous decode-optimization loop after explicitly
promoting EXP-0170. EXP-0171 uses the selected EXP-0170 implementation as its
immutable parent and targets the new largest decode module, Gate/Up plus
SwiGLU. In L64-L255 decode it consumes 16.875 ms/token, or 33.3% of complete
wall.

The structural diagnosis is specific to real decode. The protocol declares
`logical_m=1`, but projection/HMX carriers retain the hardware-native 64 by 32
spatial tile. Every Gate/Up activation task currently applies the exact LUT
SwiGLU to all 2,048 bytes of each output tile even though only spatial row zero
can affect the valid token, its cache append, later layers, final norm, LM head
or selected token. The previous Gate/Up tuning experiments were M64 and do not
test this row-utilization hypothesis.

## Direct control and candidate

One runtime-selectable binary provides:

* `full_tile`, the exact selected EXP-0170 behavior, processing all 64 rows;
* `decode_row4`, processing the first 128-byte HVX vector, or four physical
  rows, for each Gate/Up pair when and only when `logical_m=1` decode is active.

Four rows are used because they fill one 128-byte HVX vector while containing
the sole logical row. Rows 1 through 63 are padding and explicitly outside the
decode mathematical output contract. Prefill and every non-M1 path must retain
the full-tile implementation.

The candidate may change only decode Gate/Up activation-task element count,
dispatch, telemetry and experiment tooling. W4 values and scales, asymmetric
U8 qparams, LUT contents, valid-row arithmetic, weight DMA, W4-to-S8 expansion,
HMX commands and work, ring16/worker3/chain4 scheduling, Down and all other
modules are immutable. It may not initialize, copy or publish discarded rows
through DDR, add a second HMX owner, introduce QNN or modify cache state.

## Gates and evidence

Correctness requires byte-exact row-zero Gate/Up/SwiGLU values against the
full-tile control at representative layers, byte-exact valid hidden output,
cache contents, selected tokens and U8 codes over the complete M64 prefill plus
192-token L64-L255 decode sequence, all 193 independent integer-head checks,
and the retained transformer/cache regression. An audit must poison or vary
discarded rows and prove that valid rows remain invariant; discarded padding
itself is not compared.

The physical gate remains exact 8 MiB VTCM, one FastRPC call per pass, no QNN,
zero timed intermediate or full-logit DDR, zero spill/fill, one HMX owner,
unchanged projection weight bytes, DMA descriptors, HMX commands and tile work,
synchronized cache lengths and zero unattributed ticks. Telemetry must prove
that every M1 Gate/Up activation task uses one 128-byte vector and that prefill
uses the unchanged 2,048-byte path.

After a short correctness and five-pair gate, formal performance uses ten
rotated `full_tile`/`decode_row4` pairs, each with one M64 prefill and 192
continuous decode calls. Eligibility requires lower complete decode Host wall
and lower Gate/Up wall, with prefill preserved as a diagnostic. A failed
candidate is recorded and the autonomous loop proceeds to the next independent
hypothesis; it is never silently stacked.
