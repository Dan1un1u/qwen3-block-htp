# EXP-0159 — Compact delta journal for persistent W4U8 HMX-native KV cache

## Decision and purpose

The selected EXP-0157 W4U8 cache-native baseline eliminates complete-prefix
packing and EXP-0158 establishes the corresponding cache-lifetime principle
for both A16 recipes. Profiling nevertheless shows that W4U8 decode still
spends about 4.26 ms per full-stack token in cache conversion/update, issues
3,584 cache DMA descriptors and writes 1,892,352 cache bytes although one
logical 28-layer K/V append contains only 57,344 U8 bytes. On 2026-09-02 the
user approved the next optimization direction and authorized implementation.

## Fixed boundary

The immutable source parent is EXP-0158 commit
`264c911a65a341f00450855cf89b2d89bbd5f108`. Only the W4U8 persistent-cache
decode append ABI, bounded tail patch and corresponding cache consumer may
change. The same-binary direct control retains the selected per-token HMX tile
read-modify-write path.

The candidate keeps the populated M64 HMX K/V base carriers immutable,
appends each decode token's quantized K and V rows to a contiguous per-layer
delta journal, and patches the required tail lanes into VTCM-resident HMX
operands before QK and AV. K zero-point correction remains mathematically
identical and is rebuilt or updated inside VTCM. There is no logical cache
replica and no Host-side repack.

QK, Softmax and AV mathematics; quantization parameters; projection kernels,
schedules and W4 values; the selected prefill carrier-reuse path; F16F16 and
W4F16; and all legal DDR boundaries remain unchanged. The execution unit is
real Qwen3 layers 0-27, one M64 prefill followed by continuous decode positions
64-71, with one FastRPC invocation per full-stack step.

## Gates

The candidate must match the independent W4U8 implementation reference at
zero LSB for all nine full-stack outputs, all logical cache tensors and all
retained HMX carrier references. Every layer and decode step must append
exactly one current K/V token, perform zero complete-prefix pack and perform
zero DDR HMX tile read-modify-write.

The physical contract remains exact 8 MiB VTCM, zero intermediate DDR,
zero spill/fill, one FastRPC invocation, one HMX owner and no QNN. Continuous
decode Host wall must be strictly below the same-binary tile-RMW control;
prefill Host wall must be no more than 1% above control. A correctness,
structural, physical or speed failure, or a device reboot, stops the experiment.

Implementation proceeds through static/package audit, a single-layer smoke,
the complete 28-layer correctness and physical gates, and a rotated-pair
prefill/decode profile satisfying the complete profiling contract. Passing
does not promote the selected W4U8 baseline automatically.

## Decision state

Execution completed on 2026-09-02 at source commit
`4c27bea705c21835b7f444841096a9d6828048cd`. Ten rotated same-binary control
and candidate replays used real layers 0-27, M64 prefill and continuous decode
positions 64-71 without a device reboot. Formal evidence is retained at
`D:/llm_exp/results/qwen3-block-htp/exp0159/20260902T130337Z_4c27bea705c2_formal`.

All local gates pass. Every one of the nine full-stack outputs and every cache
reference is byte exact with maximum error zero LSB. Both layouts request and
acquire exactly 8 MiB VTCM, report zero intermediate DDR, zero spill/fill, one
FastRPC invocation per step, one HMX owner and no QNN. HMX command count,
U8xS8 tile-pair count and projection weight traffic are unchanged.

The candidate removes persistent HMX tile read-modify-write. Average decode
cache traffic changes from 7,798,784 read plus 1,892,352 written bytes and
3,584 descriptors to 4,272,128 read plus 57,344 written bytes and 1,792
descriptors. Cache conversion/update falls from 4,246.888 to 157.269 us and
append DMA falls from 446.136 to 129.977 us. Reconstructing the journal tail in
VTCM, however, raises QK-Softmax-AV from 7,222.933 to 10,081.517 us. The net
decode result is 51,746.930 to 50,249.834 us/token, a 2.979% speed increase;
prefill is preserved at 44,207.318 versus 44,080.182 us, a 0.288% increase in
speed.

The experiment is evidence-valid and locally passes, but adoption remains
pending because only the user may promote a Selected Baseline. On 2026-09-02
the user explicitly approved promotion in the message “同意晋升，继续下一步实验”.
EXP-0159 therefore replaces EXP-0157 as the Selected Full-Stack W4U8
Cache-Native Baseline. The next physical question is no longer the journal
write path; it is whether bounded tail reconstruction can be eliminated, made
incremental in resident VTCM, or overlapped with the existing Attention
schedule before testing longer cache segments.
