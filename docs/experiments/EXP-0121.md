# EXP-0121 — W4U8 ring16 Gate/Up HVX worker count

## Decision and scope

The user authorized a continuing W4F16/W4U8 recipe-specialization loop and
routine autonomous recovery. EXP-0121 branches from the locally passing
EXP-0120 ring16 candidate and changes only the number of persistent HVX workers
serving the W4U8 Gate/Up expansion and exact SwiGLU queue.

## Evidence and hypothesis

EXP-0092 found that reducing the original ring8 implementation from three to
two workers starved HMX, while a denser decoder with three workers increased
simultaneous HMX contention. That result closed simple tuning under the ring8
physical contract. EXP-0120 materially changes the contract: sixteen expanded
slots remove about 88% of expanded-slot wait and expose remaining HMX-ready
wait as a producer-throughput bottleneck. The hypothesis is that a fourth
persistent worker can now increase producer throughput without recreating the
old slot backpressure.

## Gates

Control and candidate are runtime selectable from one binary. Both use ring16,
batch-eight HMX, the original single-vector decoder, EXP-0112 single-fence
publication, identical queueing and exact arithmetic. The control dispatches
three persistent Gate/Up workers and the candidate four. Scratch storage is
reserved identically for four workers in both cells so worker count remains the
only timed variable.

Final output and existing stage audits must remain byte-exact. Exact 8 MiB
VTCM, zero intermediate DDR and spill/fill, one FastRPC unit, one HMX owner,
unchanged weights, DMA descriptors, HMX commands and tile pairs are hard gates.
The candidate is eligible only if Gate/Up and complete Host wall strictly
improve in ordinary and paired repeat-one and repeat-ten medians over five
rotated rounds. PC-027 and PC-028 are mandatory. Only the user may promote an
eligible candidate.

The runtime is fixed at source commit
`1a724b42c77b174fd772f44139b175ff1c964aed`; the final evidence validator is
`2ebfbb7a2388e576003d161e6803173f1d3d1143`. Formal evidence is archived at
`D:/llm_exp/results/qwen3-block-htp/exp0121/20260831T220137Z_1a724b42c77b_formal`,
with retained binaries at
`D:/llm_exp/models/qwen3-block-htp/exp0121/artifacts/1a724b42c77b/20260831T220137Z_formal`.
The device boot remained `77ccafe0-8817-4976-bdae-15af5608d4ff`.

Both cells preserve output hash `69f22eeb035e5ec5`, zero mismatches and zero
maximum LSB. Static and physical gates pass: both request and acquire exactly
8 MiB VTCM, use zero intermediate DDR and spill/fill, one FastRPC unit and one
HMX owner, and preserve weights, DMA descriptors, HMX commands and tile work.
Both cells reserve four-worker scratch, so the complete peak is identically
5,306,336 bytes and only the dispatched worker count differs.

The fourth worker reduces producer-slot wait about 63.4% and expanded-slot
wait about 12.0% at repeat ten, but it does not improve useful production.
Aggregate expansion work rises about 5.5%, HMX compute attribution about 34.0%
and HMX-ready wait about 25.4%. The resulting Gate/Up interval grows from
approximately 544.7 us to 714.6 us and complete Host wall from 1610.9 us to
1765.4 us. The extra HVX stream therefore converts queue backpressure into
HVX/HMX contention instead of shortening the critical path.

EXP-0121 is rejected and EXP-0120 ring16 with three workers remains the
provisional W4U8 source parent. Evidence hashes are: gate summary
`27e9ebae03fc60985372e527b52c5aec4f0d907502233fa789f93f62ca8e6115`,
complete profiling report

and evidence ledger
