# EXP-0175 — Decode W4U8 Gate/Up prequeued pair-ready publication

## Decision and purpose

EXP-0174 proved that publishing each completed Gate/Up pair can preserve the
mathematics and physical contract, but its callback performed queue locking and
multiple semaphore operations inside the only HMX owner. Gate/Up became about
10.3% slower. This experiment tests the narrower mechanism that EXP-0174 did
not test: move activation-task construction and queue publication off the HMX
critical path, leaving only a minimal pair-ready notification after an odd
output tile is stored.

## Bounded cells

The source parent is the eligible EXP-0173 LM-head batch-sixteen candidate. One
binary exposes the exact EXP-0173 batch-eight post-command control and two
M=1 decode candidates. The persistent HVX pool already owns five created and
locked workers, while the parent Gate/Up path dispatches only three. Candidate
mode preserves those three expansion workers and dispatches a fourth existing
pool worker as a deterministic SwiGLU consumer. It waits on pair readiness and
may consume completed pairs while HMX continues the command. The first smoke
test proved this mechanism deadlock-free and byte-exact, but one consumer
serialized work previously shared by three workers. Therefore the bounded
search also tests both remaining idle pool workers as two deterministic
consumers, partitioning pair indices without a shared claim. No transient
thread or new HVX lock is introduced. Batch-eight and batch-sixteen
notification variants are tested for both consumer counts. Expanded-weight
slots remain on the existing post-command release path so the HMX callback
does not manage producer semaphores.

The notification must establish visibility of the stored HMX output before the
SwiGLU worker reads it. It may not take the shared task-queue mutex, build queue
records, or release expanded slots on the HMX owner. The fourth and fifth
workers may not participate in W4 expansion; this keeps the parent's three-way
expansion budget unchanged and makes the additional variable explicit as one
versus two pair-ready consumers. Ring capacity, pair slots,
weight stream, qparams, HMX arithmetic and order, SwiGLU math, Down, all other
Transformer/cache stages, LM-head batch sixteen, token feedback, and the public
DDR contract are immutable. Prefill remains exactly on the parent path.

## Gates and evidence

Static and device evidence must prove the requested mode, pair notification and
consumption counts, byte-exact hashes and token sequences, exact 8 MiB VTCM,
one FastRPC/pass, no QNN, zero timed intermediate/full-logit DDR, zero
spill/fill, and zero ledger residual. A five-session rotated short gate compares
all cells over continuous real-token decode. A candidate advances only if both
Gate/Up plus SwiGLU wall and complete Host wall are lower than control. If no
candidate passes, stop without a 193-step formal run. A passing candidate must
then complete ten rotated 193-step control/candidate sessions, independent
reference and regression evidence before it can be eligible for promotion.
