# EXP-0104 — Quarter-tiled interleaved two-head U8 Q/K Norm-RoPE

## Decision and motivation

EXP-0103 proved that invariant hoisting can reduce Q/K Norm-RoPE work by about
4.2% and the QKV ledger by about 3.5% at repeat ten, but it failed the strict
repeat-one complete-Host gate. Its first true two-head implementation also
showed why naive interleaving is not viable: keeping both full 128-d SF32
pipelines live caused a 3,584-byte vector stack frame.

EXP-0104 tests a new register-tiling hypothesis. RoPE couples dimensions
`0..63` with `64..127`; each 64-lane half can in turn be processed as two
independent 32-lane pairs. The candidate processes one 32-lane pair from each
of two heads in an interleaved schedule, then processes the second pair. This
reduces live state per head while preserving genuine cross-head instruction-
level parallelism.

## Fixed contract and gates

This is a clean sibling from accepted EXP-0084. W4 weights, asymmetric-U8
qparams, gamma, batched reciprocal-square-root values, RoPE coefficients,
per-lane SF32 arithmetic order, rounding, causal Attention, projections,
residuals, MLP, DMA graph and HMX ownership remain fixed. Control uses the
accepted serial-inner paired task. Candidate changes only the Q/K Norm-RoPE
register tiling and two-head instruction schedule in the same binary.

The static gate requires a true two-head quarter-tiled helper with no vector
stack access or hot-path `memcpy`. A scalar-only ABI save frame is reported but
does not count as HVX spill. Audit-on control and candidate must be byte-exact
at Q/K Norm-RoPE, score, probability, AV and final output with zero mismatches
and zero maximum LSB.

Both cells request/acquire exactly 8 MiB VTCM, retain the 5,306,080-byte peak
plan, one FastRPC, one HMX owner, zero intermediate DDR and spill/fill, and the
same weight bytes, DMA descriptors, HMX commands and 49,408 U8-by-S8 tile pairs.
Five order-rotated rounds at repeat one and repeat ten require Q/K Norm-RoPE
work, QKV wall and complete Host wall to strictly improve by ordinary and
paired medians at both repeats. PC-027 and PC-028 close the experiment; a local
pass remains pending explicit user adoption.

## Result

Completed with a local gate pass at source commit
`c751d40d801c5a740dca5eca8c6f8b339c4f7063`.

The final helper is 1,076 bytes, contains the intended `vdeal(-64)` quarter
reconstruction, and has no HVX vector stack access. Its only frame is a 24-byte
scalar ABI save area. The candidate executes twelve paired Q/K tasks per block.
Control and candidate final output plus Input-RMSNorm, QK, probability and AV
audits are byte-exact with zero mismatches and zero maximum LSB.

The physical contract is unchanged: both cells request/acquire exactly 8 MiB
VTCM, use the same 5,306,080-byte peak plan, perform zero intermediate DDR and
spill/fill, retain one FastRPC and one HMX owner, and preserve 25,444,352 weight
bytes, 512 DMA descriptors, 176 HMX commands and 49,408 U8-by-S8 tile pairs per
block.

At repeat one, Q/K Norm-RoPE work improves 2.922% ordinary and 3.574% paired;
the QKV ledger improves 3.475%/2.638%; complete Host wall improves
0.116%/0.079%. At repeat ten, those improvements are 3.685%/3.585%,
3.170%/3.124%, and 0.518%/0.429%, respectively. Repeat-ten Q/K pool wait also
falls 19.863% ordinary and 20.010% paired.

EXP-0104 therefore has `local_gate=pass` and is locally adoption-eligible. It
remains `adoption_status=pending_user_decision`; only the user may promote it,
so the Selected Baseline remains EXP-0084.
