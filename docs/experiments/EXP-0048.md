# EXP-0048 — Native U8 projection boundaries around QKV and O

## Approval and parent

Approved by the user on 2026-08-29 after EXP-0047 showed that projection
activation packing contributes about 21.1k ticks per block to the current W4U8
path and that QKV plus O account for about 43.6% of the repeat-ten W4U8-minus-
W4F16 additive gap. The implementation parent is the EXP-0047 source head
`f8897405621b769f5e32a2690cea7399b215d59e`, whose runtime path reproduces
`W4U8-EXP0046-NATIVE-MLP-IO`. The source branch is
`codex/exp-0048-w4u8-native-qkv-o-boundaries`.

## Hypothesis and staged scope

The current W4U8 implementation constructs a U8 HMX activation carrier at
each projection boundary. Q, K, and V consume the same input-RMSNorm result,
yet the control path packs that logical activation repeatedly. The first
hypothesis is that input RMSNorm can directly scatter its quantized U8 result
once into the exact HMX activation layout and Q, K, and V can share that
carrier without changing arithmetic, qparams, HMX work, weights, or output
codes.

Stage A implements only this input-RMSNorm-to-shared-QKV carrier. It must pass
all correctness and physical gates and must strictly reduce projection-pack,
the combined QKV ledger, and complete Host wall at both repeat one and repeat
ten. If any Stage-A gate fails, the experiment stops and Stage B is forbidden.

Only after Stage A passes, Stage B may make the O projection publish its native
integer-HMX output layout directly to the post-Attention residual path. Stage B
must remove the corresponding O-output unpack while preserving the current
residual arithmetic and must strictly reduce the O-boundary ledger and complete
Host wall at repeat one and repeat ten. Gate/Up and Down native MLP boundaries,
integer Attention, W4 expansion, projection batch sizes, and all quantization
parameters remain fixed throughout.

## Fixed contract and gates

- The Execution Unit is the real Qwen3 layer-14 complete block at M=64.
- The direct control is the current W4U8 EXP-0046 runtime plan reproduced from
  the EXP-0047 source head. W4F16 is retained only as a contextual comparator;
  it is not part of the Stage-A or Stage-B single-variable speed gate.
- W4 values, per-channel scales, activation qparams, integer QK, log2 Softmax,
  integer AV, HMX command arithmetic, and all non-target schedules are fixed.
- Each admitted candidate must be byte-exact to the current W4U8 control and
  pass the independent implementation reference with maximum error 0 LSB.
- One FastRPC invocation per block execution unit, one HMX owner, exactly
  8 MiB VTCM requested and acquired, zero intermediate DDR, zero spill/fill,
  and no QNN path are mandatory.
- Seven interleaved paired rounds are required at repeat one and repeat ten on
  one stable boot. Host wall per block is the primary speed measure.
- Stage A passes only if projection-pack ticks, combined QKV ticks, and Host
  wall are each strictly lower than the paired control at both repeat counts.
- Stage B is admitted only after Stage A passes and then passes only if the O
  projection/output-boundary interval and Host wall are each strictly lower
  than Stage A at both repeat counts.
- The final report must satisfy PC-027: full additive ledger closure, separate
  overlapping DMA/HVX/HMX counters, physical-contract evidence, numerical
  evidence, paired statistics, and an explicit result for every gate.
- A local pass does not promote a baseline. Adoption remains a user decision.

## Stage A formal result and Stage B admission

Stage A passed on source commit
`c83caebfe08d4233882bbc15a733912de2d284e8`. Seven interleaved paired
rounds on stable boot `77ccafe0-8817-4976-bdae-15af5608d4ff` show that the
shared native QKV carrier reduces Host wall by 11.65% at repeat one and 12.41%
at repeat ten. The combined QKV ledger falls by 42.55% and 43.42%, while
projection-pack ticks fall by 99.96% at both repeat counts.

The final output remains byte-exact with hash `69f22eeb035e5ec5` and maximum
error 0 LSB. The independent integer QK, log2 Softmax, and AV reference has
zero mismatches. Exactly 8 MiB VTCM is requested and acquired; intermediate
DDR and spill/fill remain zero; HMX command count, U8xS8 tile pairs, weight
DMA descriptors, and weight bytes are unchanged. Input RMSNorm itself becomes
about 1.1% slower because native scatter is slightly costlier than a row-major
store, and QK-preparation pool wait rises by roughly 3.2 times, but neither
increase prevents a strict complete-block Host-wall win.

All Stage-A admission gates therefore pass and Stage B is authorized. The
authoritative Stage-A evidence is
`D:\llm_exp\results\qwen3-block-htp\exp0048\20260829T144134Z_c83caebfe08d_stage_a`;
the complete report is `full_profiling_report.md` in that directory. Stage B
must continue from this exact candidate and may change only the O-output to
post-Attention-residual boundary.

## Stage B formal result and experiment closure

Stage B completed on source commit
`61cd86fdabc3c3cf535bf13bfd7f5693fc502b8e`. Integer HMX now publishes the O
projection directly in native tile order. The fused post-Attention residual
gathers that layout and then emits the unchanged native U8 Gate/Up carrier.
The experiment deliberately keeps the telemetry ABI unchanged, so the moved
gather work appears inside `post_attention_residual_ticks`; the speed gate
therefore measures the complete `O projection + post-Attention residual`
boundary and cannot hide work by moving it between ledger rows.

Across seven interleaved paired rounds on the same stable boot, Stage B reduces
Host wall from 5.4430 to 5.1505 ms/block at repeat one, a 5.37% median-of-
medians improvement, and from 5.0307 to 4.7410 ms/block at repeat ten, a 5.76%
improvement. Paired-round median gains are 5.31% and 5.85%. The complete O
output boundary falls by 46.18% and 46.22%, and projection-unpack work falls
from about 6.58k ticks to zero. The residual row itself rises by about 53.4%
because it now owns the direct native-tile gather, while O projection falls by
about 66.8%; this redistribution is expected and is included in the boundary
gate.

The final output remains byte-exact to Stage A and the EXP-0046 control with
hash `69f22eeb035e5ec5` and maximum error 0 LSB. The independent integer QK,
log2 Softmax, and AV reference passes. HMX commands remain 1040/block, U8xS8
tile pairs remain 49,408/block, weight DMA remains 512 descriptors and
25,444,352 bytes/block, and VTCM peak remains 5,306,080 bytes under an exact
8 MiB request/acquisition. Intermediate DDR, spill/fill, QNN, and additional
HMX ownership remain absent.

Relative to the pre-EXP-0048 W4U8 candidate, the final two-stage result reduces
Host wall by 16.03% at repeat one and 17.38% at repeat ten. Both staged local
gates pass, making `W4U8-EXP0048-NATIVE-QKV-O` eligible for adoption. It remains
a pending candidate: the Selected Baseline is unchanged until the user
explicitly promotes it.
