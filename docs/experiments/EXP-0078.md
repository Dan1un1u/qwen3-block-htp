# EXP-0078 — Persistent-pool W4U8 Gate/Up expansion workers

## Parent and scope

EXP-0075 is the direct source control. EXP-0077 is retained as evidence that
advancing only the first linked DMA chain helps steady state but cannot amortize
the one-block MLP startup cost; its cross-phase prefetch mode is not inherited.
Preserve EXP-0075 Attention, residuals, qparams, numerical operators, tensor
layouts, Gate/Up and Down physical plans, exact 8 MiB VTCM, zero intermediate
DDR, one FastRPC Execution Unit and one HMX owner.

## Hypothesis

The complete block already creates five persistent HVX worker threads for
Input RMSNorm, Q/K preparation, Attention and residual work. The current W4U8
Gate/Up path nevertheless creates, locks, joins and destroys three additional
HVX expansion threads inside every block, while the persistent workers sleep.
Dispatching the unchanged Gate/Up expansion queue to exactly three of those
already-created and already-locked workers should remove per-block thread and
HVX-context startup/teardown without changing the DMA-expansion-HMX pipeline.

## Gates

The candidate may change only ownership of the three Gate/Up HVX expansion
consumers. It must use exactly three existing persistent-pool workers and must
not create, lock, unlock or destroy Gate/Up-specific HVX threads. The main DMA
producer, one HMX coordinator, external serialized HMX owner, queue protocol,
publication generations, expanded-slot lifecycle, W4 arithmetic, streaming
SwiGLU handoff and Down path remain unchanged.

Final output and audited boundaries must remain byte-exact to EXP-0075 and the
independent reference. Weight bytes, DMA descriptors, 176 HMX commands, 49,408
tile pairs, exact 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one
FastRPC Execution Unit, one HMX owner and no QNN dependency are mandatory. At
repeat one and repeat ten, Gate/Up ledger time and complete Host wall must
strictly improve in ordinary and seven-round paired medians. PC-027 and PC-028
closure are required before any adoption decision.

## Result

Implementation commit `7371914465dfb8929760803d5ff1856e398cb5e1`
reuses three already-created and already-locked complete-block pool workers for
the unchanged Gate/Up expansion queue. Formal evidence is retained at
`D:/llm_exp/results/qwen3-block-htp/exp0078/20260830T122815Z_7371914465df_formal`.
The candidate records one persistent dispatch and three persistent workers per
block, while Gate/Up transient thread count falls from three to zero. Down
continues to use the original six transient workers.

Final output and the audited Input RMSNorm, QK, probability and AV boundaries
remain byte-exact to EXP-0075, with zero mismatches and zero maximum LSB error.
Weight DDR bytes, 512 DMA descriptors, 176 HMX commands, 49,408 U8xS8 tile
pairs, exact 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one FastRPC
Execution Unit, one HMX owner and no QNN dependency are unchanged.

At repeat one, Gate/Up falls from 13,575 to 12,996 ticks (-4.27%, paired
-4.66%), and complete Host wall falls from 2,443,594 to 2,401,511 ns per block
(-1.72%, paired -2.15%). At repeat ten, Gate/Up falls from 13,536.1 to 13,017.2
ticks per block (-3.83%, paired -3.83%), and complete Host wall falls from
2,014,849.0 to 1,985,697.9 ns per block (-1.45%, paired -1.17%). HMX-ready wait
also falls about 4.6% to 4.8%, showing that persistent consumers reach the
unchanged expansion queue earlier rather than merely moving bookkeeping time.

## Decision

Correctness, physical-contract, persistent-worker execution and both repeat
speed gates pass. EXP-0078 is locally adoption-eligible and becomes the latest
eligible W4U8 candidate. It does not change the user-selected W4U8 baseline
without explicit promotion.
