# EXP-0041 — HVX W4U8 common operators

## Approval and source

Approved by the user on 2026-08-29 to continue from the accepted EXP-0040
streaming W4U8 block and implement the remaining common operators with HVX,
using the existing FP16/HVX suite as the structural reference. The exact
source parent is `4a07e11536171371b918dd0167c7f493cc9b2ab2`.
EXP-0040 is an accepted W4U8 provisional parent; this decision does not replace
the user-selected `W4F16-EXP0038-NORMS` baseline.

## Current boundary and hypothesis

EXP-0040 reduced the complete W4U8 MLP ledger from roughly 1.5 million ticks
to about 63 thousand ticks, but left the original scalar U8 common-operator
path unchanged. At repeat one, Input RMSNorm, Q/K Norm plus RoPE, the two
residual paths and Post-Attention RMSNorm account for roughly 2.54 million of
the remaining 3.33 million block ticks. These operators are therefore a more
important target than further MLP tuning.

The current W4U8 block still expands Q, K and V to FP16 before QK, Softmax and
AV. Consequently, the current Softmax has FP16 scores and probabilities even
though the surrounding projection boundaries are U8. Replacing that Softmax
with a true U8-input/U8-output algorithm would also require a declared score
qparam and coordinated integer QK and AV contracts. EXP-0041 does not hide
that larger Attention change inside a common-operator port.

## Fixed contract

- The Execution Unit remains the real Qwen3-1.7B layer-14 complete block at
  `M=64`, one FastRPC invocation, one HMX owner, and an exact 8 MiB VTCM
  request.
- EXP-0040's packed-W4 integer-HMX projections, exact U8 SiLU-by-Up LUT,
  Gate/Up and Down schedules, weights, qparams and output reference remain
  fixed.
- U8-native operators retain asymmetric U8 inputs and outputs and the existing
  qparams. Their implementation authority is the current scalar U8 arithmetic,
  not W4F16 or FP16 teacher accuracy.
- No intermediate DDR, spill/fill, QNN path, extra FastRPC invocation, hidden
  host computation or persistent pre-expanded tensor is permitted.
- This experiment guarantees local arithmetic implementation correctness, not
  full-model quantization accuracy, perplexity or question-answer quality.

## Stage A — U8 RMSNorm and residuals

Implement HVX versions of Input RMSNorm, Post-Attention RMSNorm, both U8
residual adds, and where profitable the Post-Attention Residual-plus-RMSNorm
handoff. Reuse the FP16 implementation's vector reduction, row scheduling and
fused-boundary structure, while preserving U8 dequantization, zero-point
handling, saturation and rounding. Compare each real-shape output against the
scalar U8 Implementation Reference before enabling it cumulatively.

## Stage B — U8 Q/K Norm plus RoPE

Implement the real 128-channel Q/K head operation with HVX vector loads,
zero-point-aware dequantization, vector sum-of-squares, the existing gamma and
RoPE coefficients, U8 requantization, and a vectorized U8-to-FP16 bridge for
the retained Attention island. Q and K outputs at the declared quantized
boundary must match their scalar U8 Implementation Reference.

## Stage C — Remove scalar Softmax without mislabeling it

Enable the already validated standard stable FP16/HVX causal Softmax for the
W4U8 block's retained FP16-HMX Attention island. This removes the scalar
Softmax bottleneck while preserving the current QK and AV numerical contract,
but it is explicitly a bridge implementation rather than a true U8 Softmax.
A true U8-input/U8-output Softmax remains deferred until integer QK and AV can
be introduced in one separately attributable Attention experiment.

## Gates

U8-native operators must match the scalar U8 Implementation Reference; the
FP16 Softmax bridge must satisfy its existing finite-output, causal-mask and
local numerical-error checks. Every cumulative candidate must retain exact
8 MiB VTCM acquisition, zero intermediate DDR and spill/fill, one HMX owner
and no QNN dependency. The final local performance gate requires complete
Host wall to improve strictly over EXP-0040 at repeat one and repeat ten.
