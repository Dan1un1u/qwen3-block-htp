# EXP-0168 — W4U8 batch-eight phase-overlaid LM-head pipeline

## Decision and purpose

The user approved applying the successful EXP-0166 W4F16 output-head ideas to
the completed EXP-0167 W4U8 token boundary. EXP-0167 spends about 13.175 ms in
its W4U8 LM head for both prefill and decode, versus about 6.702 ms for the
selected W4F16 head. Its W4U8 path batches four output tiles and issues 1,187
HMX commands, whereas the W4F16 path batches eight tiles and issues 594. This
experiment tests whether the gap is caused by a removable physical schedule
shortfall rather than integer-HMX arithmetic itself.

## Immutable control and allowed candidate

The direct control is completed EXP-0167 at
`9909ddf579cf465064f548b1b69845772b13a044`. The candidate may change only the
W4U8 LM-head output-tile batch, phase-overlaid VTCM allocation, compressed and
expanded weight slot geometry, bias/requant carrier residency, weight/bias DMA
prefetch, HVX W4-to-S8 expansion, HMX consumption order and associated waits.
It should first attempt batch eight and a coarse two-slot pipeline analogous to
EXP-0166, while retaining the integer-specific bias/requant carrier.

Embedding, final RMSNorm and argmax mathematics; all W4 codes, scales and
qparams; transformer layers 0-27; Attention, MLP and KV-cache implementation;
prompt, tokenizer and token-feedback loop; and every F16F16/W4F16 path are
immutable. The candidate may not materialize full logits in DDR.

## Gates and evidence

One binary exposes control and candidate so ten complete sessions can be run in
rotated order. Every session contains one M64 prefill and fifteen continuous
decode tokens. Correctness requires the exact EXP-0167 selected tokens and U8
maximum codes, an independent integer audit, and the existing 193-step
EXP-0163 transformer/cache regression. Semantic quality remains disabled.

The physical gate remains one FastRPC invocation per pass, standalone cDSP with
no QNN, exact 8 MiB VTCM, zero inter-layer or timed full-logit DDR, and zero
spill/fill. The local performance gate requires strict improvement in paired
median direct prefill token/s, decode token/s and complete 16-pass Host wall.
LM-head wall, HMX command count, weight and bias DMA, HVX expansion, HMX
lifetime and exposed waits are mandatory diagnostics. The selected EXP-0166
W4F16 head is a structural target, not the direct adoption comparator.

## Implementation result

The selected mode 9 implementation preserves mode 8 in the same binary as the
direct control. It doubles the integer-HMX output batch from four to eight
tiles, reducing LM-head commands from 1,187 to 594. The complete 1,215,488-byte
bias/requant carrier is loaded once into transformer-phase VTCM that is dead
after final RMSNorm. Two compressed and two expanded weight slots then run an
asynchronous next-group W4 DMA, a four-context HVX W4-to-S8 expansion, and the
previous integer-HMX command as one coarse pipeline. Full logits remain in
VTCM and only the selected token crosses the DSP boundary.

An attempted additional overlap between argmax and the following HMX command
was not retained: the extra output slot and simultaneous VTCM traffic increased
HMX lifetime enough to erase the expected saving. This is evidence that the
selected pipeline is limited by shared on-chip scheduling, not merely by an
unhidden scalar argmax.
