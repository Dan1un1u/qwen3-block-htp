# EXP-0107 — Common interleaved Gate/Up-SwiGLU-Down pipeline

## Decision and motivation

The user approved a bounded public-optimization phase before recipe-specific
work. EXP-0106 shows that Gate/Up remains the largest wall-time component in
F16F16, W4F16 and W4U8. The W4 paths already produce Gate and Up in matched
groups and hand each completed pair to a streaming SwiGLU worker, while the
F16F16 path completes the full Gate projection before beginning Up. This
experiment tests whether aligning F16F16 with the existing group-interleaved
producer-consumer schedule is a valid common physical plan.

## Candidate

Add a runtime-selectable F16F16 `gate8_interleaved` projection mode. It
alternates one eight-output-tile Gate command and the matching eight-output-
tile Up command, double-buffers weight DMA across the command sequence, writes
the existing Crouton-native Gate/Up carriers, and publishes each Up group to
the unchanged HVX SwiGLU stream. The Down projection consumes the same native
carrier and remains owned by the same HMX worker. W4F16 and W4U8 retain their
already interleaved implementations and are remeasured as parity controls from
the same binary.

The candidate does not introduce a second HMX owner, split the FastRPC unit,
change math, qparams, weights, tensor shape, output layout, VTCM request, or
allow intermediate DDR. It does not attempt simultaneous Gate/Up and Down HMX
execution because the project contract has one HMX ownership domain.

## Gates

The execution unit remains the real Qwen3 layer-14 M=64 complete block. Every
cell must preserve the accepted output hash and independent numerical audit,
request exactly 8,388,608 VTCM bytes, use zero intermediate DDR and spill/fill,
one FastRPC invocation, one HMX owner and no QNN.

F16F16 must strictly improve both the combined Gate/Up-plus-SwiGLU ledger and
complete Host wall in ordinary and paired repeat-one and repeat-ten medians.
W4F16 and W4U8 must preserve their runtime plans and remain within one percent
of their EXP-0106 controls. A result that helps only an isolated counter but
regresses complete Host wall is rejected. Formal evidence must include the
same-source three-recipe module table and explicit stream publication,
consumption, DMA and HMX-command telemetry.

## Result

Completed with valid formal evidence on source commit
`c2fa6aaaf89e47b43181a27f9a7d3f7baf299a7e`. The F16F16 hypothesis passed:
the interleaved path reduced Gate/Up plus streaming SwiGLU by 7.54% at repeat
one and 8.40% at repeat ten, while complete Host wall improved by 2.59% and
4.31%. Paired medians agreed in all four target cells. Final output and the
independent audit remained byte-exact with zero mismatch and zero maximum LSB.

The declared all-recipe local gate nevertheless failed. W4F16 and W4U8
control/candidate cells execute identical runtime plans and had identical
physical counters, but the independent W4U8 repeat-one Gate/Up ordinary
median differed by +1.352%, exceeding the one-percent parity limit by 0.352
percentage points. Its paired median was +0.798%. The identical W4U8 complete
Host measurements also differed by -1.114% ordinary and -2.127% paired at
repeat one. Repeat-ten Gate/Up ordinary and paired values were +0.278% and
+0.032%. This is consistent with measurement noise rather than a candidate
code-path change, but the predeclared gate is not relaxed after seeing data.

Formal results are retained at
`D:/llm_exp/results/qwen3-block-htp/exp0107/20260831T142754Z_c2fa6aaaf89e_formal`.
The F16F16 candidate is technically promising but is not a Selected Baseline
without an explicit user decision. EXP-0106 remains the accepted public
baseline and the source parent for the independent QKV-carrier experiment.

## Adoption decision

On 2026-08-31 the user explicitly accepted the F16F16 interleaved component
for the public-layer consolidation. The original `local_gate: fail` is not
rewritten: the exception is limited to the identity-proven W4 parity cells,
while the causal F16F16 candidate passed every declared speed, correctness and
physical check. EXP-0109 is responsible for integrating and formally
revalidating the component before baseline promotion.
