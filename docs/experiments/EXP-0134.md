# EXP-0134 — W4F16 Gate/Up actual fourth expansion context

## Decision and hypothesis

The EXP-0129 worker-count experiment created and locked a fourth pool worker,
but Gate/Up preparation still hardcoded two pool expansion workers. Worker 2
was correctly reserved for the streaming SwiGLU consumer, while worker 3
remained idle during W4-to-FP16 expansion. EXP-0134 tests the missing physical
hypothesis rather than repeating the old worker-count flag.

The control retains main + workers 0/1 expansion and worker 2 streaming. The
candidate creates worker 3 and dispatches main + workers 0/1/3 for expansion,
while worker 2 remains exclusively assigned to streaming SwiGLU. For a
16-region group this changes the intended expansion split from 6/5/5 to
4/4/4/4. Dynamic claim-one, region-32, DMA8, scale cache, batch-eight HMX,
arithmetic, carriers, and output remain unchanged.

## Gates

The candidate must never dispatch expansion work to reserved worker 2 and must
wait every selected expansion worker before publishing the group. Both cells
must produce byte-exact output `f18b9abbe1487231`, pass expansion audits,
request exactly 8 MiB VTCM, retain zero intermediate DDR/spill, one FastRPC
unit, one HMX owner, no QNN, and identical weight/DMA/HMX work. The declared
worker-count difference is allowed. Gate/Up plus SwiGLU and complete Host wall
must strictly improve in ordinary and paired repeat-one and repeat-ten medians.
Formal closure requires PC-027 and PC-028; only the user may promote a Selected
Baseline.
