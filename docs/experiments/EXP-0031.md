# EXP-0031 — GQA-group Attention pipeline

## Approval and status

Approved by the user on 2026-08-28 after reviewing the formal EXP-0030
critical path and the `htp-ops-lib` KV-head worker schedule. This experiment
starts from EXP-0030 source commit
`3bb967d60c6c91b51f26bf426510f0af99885be7`. It does not accept EXP-0030 or
promote a Selected Baseline.

## Motivation

The EXP-0030 W4F16 streaming candidate takes 3.019 ms per complete block at
repeat ten. Its QK Norm plus RoPE interval is 6.185 thousand ticks and its
Attention interval is 7.169 thousand ticks. Standard FP16 Softmax alone takes
5.314 thousand ticks, while QK and AV HMX together take only 1.183 thousand
ticks. QK Norm, RoPE, and Softmax currently execute serially on one HVX
context. They therefore account for the largest clearly parallelizable shared
critical path after the gated-MLP work.

Qwen3-1.7B uses sixteen Q heads and eight KV heads, so one independent GQA task
contains two Q heads and one K/V head. The reference Hexagon implementation
assigns work by KV head and lets worker-local HVX processing overlap serialized
HMX ownership. EXP-0031 tests that scheduling structure in the project-owned
runtime without importing its online-Softmax mathematics or changing the
current block arithmetic.

## Fixed contract

- The Execution Unit remains one complete real Qwen3-1.7B layer-14 block at
  `M=64` in one FastRPC invocation. Formal timing retains repeat one and repeat
  ten.
- F16F16 and W4F16 retain the exact EXP-0030 projection, streaming MLP,
  residual, RMSNorm, weight, scale, and output contracts. W4U8 remains outside
  this experiment.
- QK RMSNorm, RoPE, causal masking, score scaling, standard FP16 exponential,
  Softmax reduction order within each row, QK HMX, and AV HMX arithmetic remain
  unchanged. No LUT, log2 approximation, or alternate quantization is allowed.
- Every mode requests and receives exactly 8,388,608 VTCM bytes. Q, K, V,
  scores, probability, Attention output, and worker scratch remain in VTCM or
  accelerator state. Intermediate DDR, spill/fill, extra FastRPC calls, QNN,
  and QAIRT are hard failures.
- HMX retains one serialized ownership domain. Multiple HVX workers may publish
  HMX requests, but direct concurrent HMX programming is not permitted.
- Candidate output must remain byte-identical to its paired EXP-0030 control,
  in addition to passing the existing Implementation Reference and non-finite
  checks.
- Equivalent-scope Host wall is primary. The Block Timing Ledger remains
  exclusive and closed. HMX, HVX, worker work, queue wait, and ready wait are
  diagnostic intervals and may not be summed as latency.

## Ordered milestones

### A — Multi-worker QK Norm and RoPE

Partition the existing head-row work among the calling context and persistent
HVX workers. Each `(tensor, row, head)` task preserves the exact current
sum-of-squares reduction, reciprocal square root, gamma multiplication, RoPE
instruction sequence, and stores. Q and K tasks are disjoint. Retain this mode
only if it reduces the QK Norm/RoPE interval and does not regress complete-block
Host wall for both projection variants.

### B — Multi-worker standard FP16 Softmax

Partition the existing independent `(Q head, row)` Softmax tasks among the same
persistent HVX workers. Preserve one-vector-per-row masking, maximum reduction,
`qhmath_hvx_exp_vhf`, sum reduction, reciprocal, and FP16 output sequence.
Scores and probability remain in their existing VTCM allocations. Retain this
mode only if it reduces Softmax and complete Attention intervals without a
complete-block Host-wall regression.

### C — GQA-group heterogeneous pipeline

Create eight generation-tagged GQA tasks. A worker processes two Q heads and
one K/V head through QK Norm/RoPE, requests the unchanged QK HMX commands,
executes standard Softmax after score readiness, then requests the unchanged AV
HMX commands and writes its disjoint output channels. A single central HMX
owner serializes all QK and AV commands while non-conflicting HVX work proceeds
on other groups. Worker scratch must be proven by explicit peak-live VTCM
accounting.

The full online FlashAttention algorithm is not part of this milestone. At
`M=64`, the complete score and probability tensors total only 262,144 bytes and
already reside in VTCM, so the tested hypothesis is heterogeneous scheduling,
not removal of off-chip quadratic traffic.

### D — Complete-block selection gate

Evaluate the immutable EXP-0030 control, the retained A+B candidate, and the
GQA pipeline candidate for both F16F16 and W4F16. Collect audit-on correctness
and alternating audit-off repeat-one/repeat-ten timing in one stable boot. The
selected local candidate must reduce the combined QK Norm/RoPE plus Attention
exclusive interval and must not regress complete-block Host wall for either
variant at either repeat count. W4F16 must remain strictly faster than F16F16.
No fixed percentage target is imposed. The faster valid candidate may be A+B
even if milestone C is correct but slower.
