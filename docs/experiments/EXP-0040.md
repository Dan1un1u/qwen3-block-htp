# EXP-0040 — Port the proven W4U8 integer-HMX MLP into the latest block

## Approval and source

Approved by the user on 2026-08-29 after EXP-0039 showed that additional
W4F16 Gate/Up VTCM lookahead does not shorten the steady-state critical path.
The source parent is the user-selected `W4F16-EXP0038-NORMS` baseline at
`24917512fc35adfd22f97b5123473bb6a7518fd0`; the rejected EXP-0039 candidate
is not inherited.

## Existing substrate

This experiment does not repeat integer-HMX bring-up. EXP-0002 through
EXP-0005 proved U8-by-S8 HMX tiles, multi-tile accumulation, real Qwen3
projection shapes and packed-W4-to-S8 expansion. EXP-0019 selected a
two-producer 32-K-tile streaming plan for paired Gate/Up and retained the
96-tile coarse plan for Down. EXP-0021 composed those projections into a
zero-intermediate-DDR W4U8 MLP. EXP-0022 proved a complete real layer-14 W4U8
block but retained serial per-output projection staging, scalar U8 common
operators and an FP16 Attention island.

## Hypothesis

The historical W4U8 projection arithmetic is already effective, but the
complete-block implementation never inherited its best DMA/HVX/HMX schedule
or the later Crouton-native MLP boundary. Porting that known substrate into the
latest block should preserve compressed W4 transport, remove complete
row-major Gate/Up materialization, and expose an actual W4U8 MLP advantage
without changing Attention or the remaining U8 common-operator algorithms.

## Fixed contract

- The target is the real Qwen3-1.7B layer-14 `M=64` middle-block workload and
  its retained Block Package. Full-model execution remains out of scope.
- W4U8 uses the existing byte-identical signed W4 `[-7,7]` values,
  per-output-channel scales, asymmetric U8 activation qparams, precomputed
  weight-sum/zero-point correction, integer HMX and independent Implementation
  Reference.
- Formal execution uses one FastRPC Execution Unit, one HMX owner, the fixed
  8 MiB Prepared Runtime Session, zero intermediate DDR, zero spill/fill, no
  QNN and no pre-expanded persistent weight artifact for the packed candidate.
- Attention, RMSNorm, Residual, Q/K Norm, RoPE and Softmax mathematics and
  schedules remain unchanged in the complete-block integration. This
  experiment changes only the W4U8 Gate/Up, SwiGLU handoff and Down MLP path.
- Host wall is primary. Exclusive MLP ledger intervals are local attribution;
  DMA, HVX expansion and HMX counters may overlap and are diagnostic.

## Stage A — Latest-layout W4U8 MLP gate

Use the real captured post-attention-normalized U8 input and compare three
equivalent MLP scopes: an Expanded-S8 U8 control, the packed-W4 U8 candidate,
and the selected W4F16 MLP as a reported cross-numerical reference. Expanded
S8 and packed W4 must use the same U8 input, S8 HMX carrier values, HMX bias
and requant tables, output qparams, tile order and HMX command schedule.

The packed candidate reuses the accepted EXP-0019 physical plans: bounded
two-HVX 32-K-tile streaming for paired Gate/Up and 96-tile coarse publication
for Down. Integer-HMX Gate/Up output remains in U8 Crouton order; HVX applies
the existing fixed-point SiLU-by-Up contract to bounded tile generations and
writes directly into the final Down activation layout. No complete row-major
Gate, Up or Middle tensor may be materialized.

Stage A passes only if packed W4 and Expanded S8 are byte-exact against the
same Implementation Reference, all residency and physical gates pass, and
packed W4 strictly improves both the complete MLP Host wall and the declared
projection interval at repeat one and repeat ten. Failure stops before full
block integration.

## Stage B — Complete-block integration

Only after Stage A passes, select the packed W4U8 MLP inside the current real
block while leaving every non-MLP W4U8 path unchanged. The complete output
must remain byte-exact with the pre-integration W4U8 control and its independent
reference, and the physical contract must remain zero-intermediate-DDR.

Report repeat-one and repeat-ten complete-block latency against the paired
old-W4U8 control and the selected W4F16 baseline. Strict improvement over the
old-W4U8 control is required for local adoption; comparison with W4F16 is a
target and characterization, not a stop condition for this first integer
integration experiment.

## Stage A formal result — 2026-08-29

The implementation at source commit
`2b187f7cb8678fb293db2b2e33bd64dfd4eeea1b` uses raw nibble-to-S8 HVX
unpacking, integer U8-by-S8 HMX, an exact 65,536-entry U8 SiLU-by-Up LUT using
HVX `vgather`, and a two-stage per-output-channel requantization.  The HMX
stage uses an independently characterized rounded power-of-two conversion;
HVX applies the remaining small integer multiplier.  Packed W4 and Expanded
S8 are byte-exact against the same independent integer reference.  Both use
exactly 8 MiB of acquired VTCM, report zero intermediate DDR, zero spill/fill,
one HMX owner and no QNN dependency.  No complete row-major Gate, Up or Middle
tensor is materialized.

The retained W4U8 numerical comparison is reported rather than gated.  The
final Down result has mean absolute error `0.5264` U8 LSB and `96.01%` of
elements within two LSB of the retained W4U8 capture.  The selected W4F16
capture is also retained as an upstream-inclusive cross-numerical reference;
its poor final cosine is consistent with the already-recorded fact that the
current full W4U8 path is not precision-usable and is not a Stage A stop
condition.

Eleven order-rotated pairs show that the fixed two-worker contract fails.  At
repeat one, packed W4 reduces median Host wall by `7.40%` but increases the
declared projection interval by `10.85%`.  At repeat ten, packed W4 is `8.28%`
slower in Host wall and `12.35%` slower in the projection interval.  Therefore
the approved Stage A gate is `fail` and Stage B is not authorized.

The same formal matrix retained a diagnostic common three-worker schedule for
both variants.  It passes every speed criterion: packed W4 reduces Host wall
by `25.62%` at repeat one and `25.11%` at repeat ten, while reducing the
projection interval by `26.64%` and `26.84%`, respectively.  This is not an
adopted contract change.  It demonstrates that the U8 requantization/LUT work
changes the shared HVX queue balance: with two workers, expansion and
activation consumption block one another; a third worker restores overlap and
allows compressed weight transport to dominate the comparison.
