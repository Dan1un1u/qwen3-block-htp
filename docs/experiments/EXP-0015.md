# EXP-0015 — Reuse HMX, VTCM, and power resources across projection runs

## Approval

Approved on 2026-08-27 by the user's continuing instruction to optimize the
standalone W4 path until it provides useful acceleration.

## Objective

Remove the dominant fixed runtime envelope that remains after EXP-0014. In the
accepted experiment evidence, the W4 gate/up pipeline plus linked output DMA
cost about 7.27K qtimer ticks and down about 4.89K, while total DSP time is
about 56K ticks for both. The remaining roughly 48K ticks are dominated by
per-invocation power votes, HMX and VTCM resource acquisition/release, thread
and synchronization lifecycle, cache boundary work, and RPC service overhead.

The candidate adds an explicit prepared FastRPC session. `prepare` acquires the
2 MiB VTCM region, HMX resource, and persistent performance/power votes once;
multiple `run` calls reuse those resources; `release` gives them back. Each
measured CLI invocation performs one unmeasured warm-up run followed by one
measured run in the same session. The transient control performs the same two
runs but acquires and releases resources inside each run. Prepare and release
wall costs are reported separately so steady-state speed cannot hide cold
startup cost.

## Fixed contract

EXP-0014 linked 2-D output DMA remains enabled. Gate/up W4 uses the
eight-compressed/seven-expanded linked-chain-four plan; down W4 uses the
four/eight contiguous-batch-two plan. Expanded-S8 uses linked-chain-two for
gate/up and batch one for down. Weight bytes, W4 values and per-channel scales,
asymmetric U8 activation and zero-point correction, integer HMX work, six-HVX
W4 expansion, tensor shapes, DDR graph boundaries, 2 MiB VTCM size, output
format, clocks, and mathematical reference remain unchanged. No intermediate
tensor may be added to DDR and no QNN or QAIRT component may be introduced.

Persistent resources are scoped to one FastRPC session and must be released on
normal close and every error path. They do not imply control over firmware
arbitration and cannot be described as a whole-model runtime.

## Gates

All four patterns, both shapes, both storage formats, and both lifetime modes
must remain byte-exact with the independent Host reference after the warm-up
and measured runs. Physical projection counters must be identical between
transient and persistent modes. Persistent mode must show the same 2 MiB VTCM
pointer and HMX resource context across both runs, with no worker fallback,
timeout, resource, power, DMA, synchronization, close, or device-boot failure.

Formal timing records repeat one and repeat ten in rotated order. Hot measured
Host wall decides the local gate: persistent W4 must improve both repeat-one
shapes and must not regress either repeat-ten shape. Prepare and release costs,
the number of runs needed to amortize them, and an identically optimized
Expanded-S8 comparison are mandatory reported evidence. The user alone may
accept the experiment or promote a baseline.

## Result

Completed on source commit
`23369a66c23443dbed6153fa6fab6a8ee3b2f054`. The formal matrix contains 224
records: 32 correctness records, 96 repeat-one timing records, and 96
repeat-ten timing records. Every measured output is byte-exact with the
independent Host reference and with its warm-up output. There was no worker
fallback, descriptor timeout, resource error, graph/backend fallback, device
reboot, or QNN dependency. Prepared warm-up and measured runs retained the
same 2 MiB VTCM address and HMX context identifier, and all resources were
released successfully.

For packed W4, prepared-session repeat-one Host wall median is 1.079 ms for
gate/up and 0.882 ms for down. Relative to the otherwise identical transient
resource path, this improves hot invocation latency by 79.73% and 82.40%.
Repeat-ten improves by 56.19% and 60.41%, so the result remains beneficial
after the projection work dominates a larger fraction of the call.

The strict fair-storage comparison also passes. Under the same prepared
session, packed W4 is 12.45% faster than Expanded-S8 for gate/up and 19.34%
faster for down at repeat one; at repeat ten the advantages are 21.88% and
25.42%. The W4 variant therefore preserves its compressed-weight benefit
after the common resource-lifecycle bottleneck is removed.

Median prepare plus release cost is about 3.17--3.22 ms and is reported
outside the hot invocation. Even when charged to a single W4 invocation, the
formal comparison remains faster than reacquiring resources inside every run,
with a calculated break-even of one run. FastRPC session open and close cost
roughly 36--39 ms and 6--8 ms respectively; those common process/session costs
are excluded from both hot modes and must be amortized by a real block runtime,
not described as kernel speedup.

The local performance gate passes. Adoption remains pending because only the
user may promote a Selected Baseline.
