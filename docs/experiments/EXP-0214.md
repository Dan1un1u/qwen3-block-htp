# EXP-0214 — M64 prefill direct-W4 HMX projection gate

## Decision and purpose

The decode loop stopped after EXP-0212 and EXP-0213 both improved local QKV
attribution but reduced end-to-end throughput. EXP-0214 begins the required
prefill loop from the fastest evidence-valid pending source parent, EXP-0211.

The current M64 W4U8 projection path reads packed W4 from DDR, expands it to an
S8 HMX carrier with HVX, and then executes U8 x S8 HMX. The candidate instead
uses the already validated HMX direct-N packed-W4 contract for M64 activation
rows, so HMX consumes reordered W4 directly. The first gate targets a real
middle-layer projection shape before adoption across the full transformer.
It must eliminate explicit W4-to-S8 expansion rather than merely reclassify it.

## Gates and decision state

The candidate must be byte exact to the existing W4U8 M64 implementation for
the same packed weights, biases, qparams and input. Tensor shapes and physical
row count remain M64. Physical gates are exact 8 MiB VTCM, zero timed
intermediate DDR, zero spill/fill, one HMX owner, no QNN, direct packed-W4 HMX
input, and zero explicit expansion for the target projection.

The micrograph gate compares true wall latency in rotated runs and requires
the candidate to be faster. If direct-W4 does not produce the expected M64
speedup, the user requires an immediate stop and discussion before continuing.
If it passes, the next experiment will adopt the contract across all prefill
transformer projections, measure complete token-in/token-out prefill tok/s,
and continue the prefill optimization loop without an autonomous stop gate.
Approved and registered on 2026-09-05 under the current loop authorization;
evidence is now complete and valid.

## Result

The formal gate used ten alternating-order pairs at repeat1 and repeat10 for
both the real layer-14 Gate/Up pair and Down projection.  Direct packed-W4 HMX
was faster in every median comparison: Gate/Up measured 1.198x at repeat1 and
1.392x at repeat10; Down measured 1.311x and 1.702x respectively.  Candidate
expansion count was exactly zero, while the control retained explicit HVX
W4-to-S8 expansion.

Both cells used identical inputs, W4 values, scales, bias and output qparams.
Their FNV-1a checksum over every M64 output byte was identical in all rotated
runs.  The retained M64 package predates the native-HMX conversion reference
used by the EXP-0187 M1 formal gate, so its older software-postscale bytes are
retained as a disclosed diagnostic rather than treated as byte authority.
Both cells nevertheless report the same diagnostic mismatch count.  All DSP,
DMA, timeout and resource checks pass; VTCM is exactly 8 MiB, there is no timed
intermediate DDR tensor, and the backend remains standalone FastRPC/cDSP with
one HMX owner and no QNN.
