# EXP-0184 — HVX single-row native K-tail update

## Decision and purpose

EXP-0183 proves that caching seven of eight mutable K-tail carriers in the
prepared-session VTCM reduces QK-Softmax-AV by 9.043%, but its scalar per-head
scatter raises cache carrier maintenance by about 642 us/token and makes full
decode 0.498% slower.  EXP-0184 retains that useful residency structure and
tests the missing physical primitive: one HVX center/sum/vscatter operation for
the newly appended 128-byte K row at an arbitrary HMX output lane.

## Controlled change

The source parent is rejected-but-evidence-valid EXP-0183 commit
`6db6a59a2f15385163a189b0bd952814a90fa895`; direct performance control remains
the locally eligible EXP-0182 VTCM V-tail path.  The candidate keeps the EXP-0183
K13 external segmented-v4 DDR journal, seven cached heads, one fallback head,
827,904-byte K atlas and all Attention math unchanged.  Only the per-row cached
K update changes from scalar byte loops to an exact HVX vector center, signed
sum and vscatter at the active output lane.  The compact correction word and
segment seal remain byte-identical.

## Gates

Static and audit gates require the new HVX helper to be selected only for K13,
exact K carrier comparison against the established HVX full-tail reconstruction,
34-step hidden/token/code equality across a segment seal, padding-poison
invariance, exact 8 MiB VTCM, zero timed intermediate DDR, zero spill/fill, one
FastRPC and no QNN.  Five rotated 17-step pairs must lower both cache carrier
update and complete decode Host wall in 5/5 pairs before a ten-pair 193-step
formal run.  Only the user may promote a passing result.
