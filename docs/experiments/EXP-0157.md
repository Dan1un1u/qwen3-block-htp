# EXP-0157 — Reuse prefill HMX carriers for persistent W4U8 KV cache

## Decision and purpose

EXP-0156 proved that persistent HMX-native W4U8 K/V cache decode scales from one
to all 28 Qwen3 transformer layers, but its one-time M64 prefill latency
regressed from `53,750.625 us` to `91,917.735 us`.  The user approved a focused
repair on 2026-09-02.  This experiment tests whether the HMX K and V carriers
already produced for QK and AV can initialize persistent cache storage without
performing a second elementwise carrier construction.

## Fixed boundary

The immutable parent is EXP-0156 commit
`5cec25408a33ed5a670bc5e97761296bc874bdc3`.  Only W4U8 prefill cache
initialization and the required VTCM lifetime/DMA handoff may change.  Decode
cache update and consumption, projection kernels, Q/K Norm and RoPE, QK HMX,
Softmax mathematics, AV HMX, O projection, MLP, activation and weight qparams,
W4 values and persistent cache ABI remain unchanged.

The direct control is the same full-stack HMX-native W4U8 path with duplicate
post-Attention carrier construction.  The candidate must preserve or directly
DMA the already-built prefill K and V HMX carriers before their VTCM storage is
reused, and initialize only the unused padded capacity tile.  It may not use a
row-major intermediate or hide repacking in Host code or DDR.

The execution unit remains real Qwen3 layers 0 through 27, one M64 prefill and
continuous decode positions 64 through 71, with one FastRPC call per full-stack
step.

## Gates

All nine full-stack outputs, all logical K/V cache states and retained physical
HMX cache carriers must match the independent W4U8 reference exactly.  Candidate
prefill must report zero duplicate full-carrier construction and candidate
decode must retain zero complete-prefix K/V pack operations for every layer.

The physical contract remains exact 8 MiB VTCM, zero intermediate DDR, zero
spill/fill, one FastRPC call per stack step, one HMX owner and no QNN.  Formal
rotated-pair M64 prefill Host wall must be strictly below the EXP-0156
HMX-native control.  Continuous decode Host wall must not regress by more than
2% relative to the same direct control; a difference within measured noise is
treated as preserved rather than a new decode improvement.

Any correctness, structural or physical failure, device reboot, prefill
non-improvement or decode regression beyond the gate stops the experiment for
discussion.  Passing does not promote a baseline automatically.

## Result

The experiment completed on source commit
`0a3557d075dc4c2b3e4a0d9e05910acb3cf4bf6b`.  Ten rotated direct-control and
candidate pairs completed on the same device boot.  All nine full-stack
outputs, logical cache states and retained HMX-native carrier checks matched
exactly.  Exact 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one
FastRPC call per full-stack step, one HMX owner and no QNN were preserved.

The candidate reuses the K carrier consumed by QK and the V carrier consumed
by AV, copying their two populated M64 tiles with aligned HVX vectors and
initializing only the unused padded-capacity tile before the normal persistent
cache DMA.  Across all 28 layers, duplicate prefill carrier builds fell from
28 to zero and `4,014,080` existing carrier bytes were reused.  Cache carrier
conversion fell from `47,480.651 us` to `152.812 us`; append DMA was
`402.005 us`.

M64 prefill Host wall fell from `91,730.443 us` in the same-binary duplicate
control to `44,334.818 us`, a `51.67%` latency reduction and `2.069x` speedup.
This is also `17.52%` lower latency than the EXP-0156 row-major result of
`53,750.625 us`.  Prefill throughput is `1,443.561 tok/s`.

Continuous decode remained unchanged within noise: `51,854.603 us/token` for
the direct control and `51,830.592 us/token` for reuse (`-0.046%`).  The
candidate sustains `19.294 tok/s`, `62.59%` faster than the unchanged EXP-0154
W4F16 decode comparator.  Every decode step retains zero complete-prefix pack
and exactly 28 current-token incremental updates.

All local gates passed and the evidence is valid.  Adoption remains pending;
no baseline was promoted automatically.  Formal evidence is retained at
`D:/llm_exp/results/qwen3-block-htp/exp0157/20260902T061809Z_0a3557d075dc_formal`.

## Adoption

On 2026-09-02 the user accepted the recommendation to promote EXP-0157 as the
Selected Full-Stack W4U8 Cache-Native Baseline.  This promotion applies to the
28-layer prefill/continuous-decode execution scope and does not replace the
separate single-block recipe-fastest or frozen public-common baselines.
