# EXP-0086 — Rebalance the latest W4U8 Down pipeline

## Decision and motivation

The user approved this experiment on 2026-08-31 by asking to continue with the
next recommended direction after EXP-0085. The direct parent is the accepted
EXP-0084 fair-comparison source state, not rejected EXP-0085. In its latest
repeat-ten module comparison, W4U8 Gate/Up is about 41.8% faster than W4F16,
while W4U8 Down is only about 3.6% faster. Down still occupies roughly 317.7 us
or 16.4% of the W4U8 complete-block wall, so the compressed-weight benefit is
not being expressed as strongly as it is in Gate/Up.

The latest Down implementation already includes the accepted generation-safe
single HMX command from EXP-0050 and the five-persistent-plus-one-transient HVX
worker topology from EXP-0079. Its two equal 96-K-tile chunks, however, were
chosen before that latest worker topology. EXP-0086 tests whether the current
producer and consumer rates now require a different first-chunk boundary or
prefetch distance.

## Fixed contract

The Execution Unit is the real Qwen3-1.7B layer-14 complete block at M=64. The
direct control is `W4U8-EXP0084-FAIR-CANONICAL`; F16F16 and W4F16 remain
contextual PC-028 comparators. Down arithmetic, asymmetric-U8 qparams,
per-channel W4 values and scales, activation and output layouts, total K work,
HMX tile pairs, DMA bytes, Gate/Up, Attention, residuals and all other block
stages are fixed.

Every formal run uses one FastRPC, exactly 8,388,608 acquired VTCM bytes, one
serialized HMX owner, zero intermediate DDR, zero spill/fill and no QNN. The
current five persistent plus one transient Down expansion workers are fixed in
the first experiment so that chunk-boundary attribution is not mixed with
another worker-lifecycle change.

## Serial milestones

### Stage A — audit-only Down timeline

Add disabled-by-default timestamps for first compressed-weight DMA
publication, first expanded region, first HMX start, each chunk-ready event,
HMX readiness waits, final HMX completion and output publication. This trace
must not run in ordinary performance mode. If the control shows no repeated
HMX starvation, producer tail or chunk-boundary gap, implementation stops and
the negative evidence is discussed with the user.

### Stage B — bounded pipeline gate

Keep 192 total K tiles and search first-chunk sizes 64, 80, 96, 112 and 128,
with only compatible prefetch-distance choices. The control is the existing
96+96 split. Candidate and control must remain byte-exact, preserve all
physical work and retain zero intermediate DDR. A candidate advances only if
both the Down ledger and complete Host wall improve in an interleaved repeat-
one micro gate.

### Stage C — formal comparison

The selected candidate, if any, runs seven interleaved paired rounds at repeat
one and repeat ten. Local pass requires strict ordinary and paired median
improvements in both the Down ledger and complete Host wall, plus complete
PC-027 timing-ledger closure and the PC-028 three-recipe module table. No local
pass becomes a Selected Baseline without explicit user promotion.

## Stage A result

The audit-only `96/96` control showed first HMX start at 174 ticks, last
expanded chunk readiness at 5,528 ticks and HMX completion at 5,561 ticks.
The maximum individual continuation wait was one tick. Thus the second chunk
does not repeatedly starve HMX and the producer tail is already hidden. The
remaining plausible opportunity was to reduce the roughly nine-microsecond
first-HMX-start latency, which justified the bounded asymmetric split search
without changing arithmetic or worker topology.

## Stage B result and decision

Each candidate was measured against a fresh adjacent `96/96` control for five
alternating-order paired rounds at repeat one and repeat ten. Positive values
mean the candidate is faster.

| Split | r1 Down ordinary | r1 Down paired | r1 Host ordinary | r1 Host paired | r10 Down ordinary | r10 Down paired | r10 Host ordinary | r10 Host paired |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 64/128 | -1.00% | +0.18% | +1.81% | +1.58% | +1.35% | +0.93% | +0.92% | +0.88% |
| 80/112 | -0.66% | -0.88% | -1.90% | -0.79% | +0.20% | -0.02% | +2.18% | +1.96% |
| 112/80 | -0.37% | -0.64% | -0.32% | -0.17% | -0.95% | -0.96% | -0.05% | -0.21% |
| 128/64 | -0.72% | -1.07% | +1.52% | +3.87% | -0.52% | -0.75% | -0.29% | -0.41% |

`64/128` was the closest candidate, but its repeat-one Down ordinary median
regressed by 1.00%; its paired value of only +0.18% is noise-level rather than
a strict robust win. No candidate passed all Down and complete-Host cells, so
the seven-round Stage C promotion run was not entered.

All five splits retained output hash `69f22eeb035e5ec5`, zero mismatches, zero
maximum LSB, 49,408 U8xS8 HMX tile pairs, zero FP16 HMX tile pairs, exactly
8,388,608 acquired VTCM bytes, zero intermediate DDR and zero spill/fill. The
device boot stayed fixed, every ordinary record had zero unattributed ledger
ticks, and the PC-027 and PC-028 report gates passed.

EXP-0086 therefore closes with valid evidence, `local_gate=fail` and
`adoption_status=rejected`. The experiment disproves asymmetric Down chunk
rebalance as a robust improvement under the current five-persistent-plus-one-
transient HVX and single-HMX-owner pipeline. EXP-0084 remains the selected
W4U8 baseline.
