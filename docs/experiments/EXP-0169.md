# EXP-0169 — W4U8 real continuous-decode KV-length scaling attribution

## Decision and purpose

The user approved a diagnosis-first decode and KV-cache experiment after
promoting EXP-0168. The selected EXP-0168 W4U8 token-generation baseline is the
immutable implementation under test. Its published result covers only cache
lengths 64 through 78, so it cannot determine whether longer decode is limited
by the fixed projection/LM-head floor or by historical-cache consumption in
QK, Softmax and AV.

## Immutable implementation and allowed instrumentation

The source parent is EXP-0168 commit
`bcf327142e451ed25c84f32d13e802230397d65a`. Transformer, Attention, MLP,
embedding, final RMSNorm, LM head, argmax and KV-cache kernel mathematics,
physical layouts and schedules are immutable. Model weights, W4 codes, scales,
activation qparams, prompt and token-feedback semantics are also immutable.

Only the Host generation loop's runtime step count, a capacity-257 archive,
RoPE/expected-token publication needed for positions 64 through 255, untimed
audit capture, and offline length-bucket summarization may change. These changes
must not alter any timed DSP kernel or add a timed DDR boundary.

## Execution and evidence

Every Prepared Session performs one real M64 prefill followed by 192 continuous
greedy decode calls, ending with cache valid length 256. Ten formal sessions are
required. Decode results are summarized for cache-length buckets 64-95, 96-127,
128-159, 160-191, 192-223 and 224-255, with exact Host wall and direct tokens/s.
Per-module and per-layer ledgers must remain closed so fixed projection cost can
be separated from QK-Softmax-AV, cache carrier, append DMA, mutable-tail and
32-token segment-seal costs.

Correctness requires the first 16 token IDs and U8 maximum codes to remain exact
to EXP-0168, all 193 captured final-hidden states to produce the same integer
LM-head result in an independent reference, and the existing EXP-0163 193-step
transformer/cache regression to remain exact. Semantic quality is not gated.
The physical gate remains exact 8 MiB VTCM, one FastRPC invocation per pass,
standalone cDSP with no QNN, zero timed inter-layer or full-logit DDR, zero
spill/fill, synchronized monotonic cache lengths and zero unattributed ticks.

This is characterization, not an optimization candidate: there is no speed or
baseline-adoption gate. The experiment completes only when it identifies the
cache-length slope and any segment-boundary discontinuities strongly enough to
choose the next implementation hypothesis.

## Decision state

Approved by the user and completed on 2026-09-04 from source commit
`f4722419596931035583e98e4b5a304b528d1cd2`. The formal evidence is retained
at
`D:/llm_exp/results/qwen3-block-htp/exp0169/20260904T_exp0169_f472241_formal`.
All required implementation, lifecycle, physical, stability, ledger and
regression gates pass. This characterization does not change the selected
EXP-0168 baseline.

The directly measured 192-token decode average is 59.948 ms/token or 16.681
token/s. Throughput falls from 18.034 token/s at cache lengths 64-95 to 15.441
token/s at lengths 224-255. Complete Host wall increases by 62.208 us per added
cache token, while the QK-Softmax-AV interval increases by 63.567 us. The
apparent small difference is measurement covariance in independently fitted
series; all other additive intervals are flat within noise.

The length-dependent cost is not projection, LM-head, cache append, QK HMX or
AV HMX. Between the first and last buckets, QK-Softmax-AV grows by 9.838 ms and
the recorded dynamic U8 Softmax work grows by 9.665 ms. The decode-only
`qbh_attention_u8_requant_softmax_dynamic` path performs three scalar passes
over every valid score row: maximum, log2-weight sum, then probability and
scatter. The previously optimized four-row HVX shuffle path applies to M64
prefill and is not used by M=1 decode. It is therefore the dominant long-cache
slope.

Cache DDR reads increase by 59,385 bytes per added token across all 28 layers,
closely matching the segmented carrier's expected payload of 59,136 bytes:
57,344 logical U8 K/V bytes plus 1,792 bytes of amortized K correction blocks.
Equivalently, each layer reads one 67,584-byte physical K/V segment per 32
additional tokens, so `67,584 / 32 * 28 = 59,136` bytes per token. The 0.42%
fitted difference comes from tail and segment phase. Regular append writes are
exactly 57,344 bytes per token. Every 32 tokens, sealing writes 1,892,352 bytes
and adds about 2.0-2.2 ms Host wall for the first five comparable boundaries;
this is a real sawtooth but only about 65 us/token when amortized and is not
the dominant length slope.

The next high-confidence hypothesis is a decode-specific HVX Softmax over
32-byte cache tiles, preserving the exact EXP-0168 log2/LUT mathematics and the
existing segmented-cache and HMX contracts. It should replace three scalar
element loops with vector tile passes and publish probability directly in the
AV HMX activation layout. It must be evaluated separately before any baseline
promotion.
