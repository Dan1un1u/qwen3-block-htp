# EXP-0148 — Real layer replay and full-stack-compatible decode session

## Decision and purpose

The user approved EXP-0148 on 2026-09-01 as the first step beyond synthetic
shape characterization.  It establishes a versioned, layer-indexed Prepared
Decode Session and proves a real layer-14 replay consisting of one prefill that
builds an initially empty cache followed by consecutive decode steps that reuse
and extend the same state.  This experiment is a substrate/correctness gate,
not a recipe-fastest baseline promotion.

## Fixed scope

The source parent is EXP-0147 commit
`8052d42c347667ddd37a9555486d918569960b1d`; the selected M64 kernels and the
F16F16, W4F16 and W4U8 recipe mathematics remain unchanged.  A declared
full-model teacher supplies real layer-14 input hidden states and position/RoPE
metadata for a prompt of 64 tokens plus eight following decode positions.  The
runtime may import those layer inputs, but it must compute Q/K/V and append K/V
itself.  Precomputed K/V may exist only as independent validation evidence.

The session ABI must be capable of describing all 28 transformer layers even
though EXP-0148 executes only layer index 14.  It records ABI version, recipe,
layer count, active layer, cache capacity, valid length, K and V format IDs,
element type, offsets and strides.  A cache layout may be changed behind those
descriptors during later optimization; consumers may not assume the EXP-0147
logical head-major carrier is canonical.

## Stages and gates

Stage A audits the teacher/replay source and generates immutable replay evidence
for positions 0 through 71.  The trace must prove that each input is the hidden
state entering layer 14 at the declared position.  Recycling the existing M64
fixture or using the previous synthetic K/V snapshot fails this stage.

Stage B implements Prepared Decode Session lifecycle and state semantics.  An
empty session runs prefill positions 0 through 63, producing cache length 64.
Eight separate decode run invocations consume replay inputs 64 through 71,
append one K/V entry per invocation, and leave lengths 65 through 72.  Cache
prefixes, appended entries and block outputs are checked after every step.
Reset-and-repeat timing is permitted only as a separately labelled diagnostic.

Stage C validates all three recipes.  F16F16 establishes the simplest replay
correctness control; W4F16 proves FP16-cache compatibility; W4U8 proves the
integer path.  Each uses an independent recipe-specific software reference.
W4U8 integer boundaries require zero LSB mismatch and FP16 paths retain their
existing tolerance.  Teacher-level model accuracy is diagnostic and does not
replace implementation correctness.

Stage D proves the physical contract: exactly 8 MiB VTCM requested/acquired,
one FastRPC invocation per prefill or decode step, one HMX owner, no QNN/CPU
fallback, no intermediate DDR or spill/fill, and explicit persistent-cache DDR
traffic.  The cache is the only legal persistent DDR state.  The result reports
prefill and every decode step with the complete profiling ledger; there is no
speed gate in EXP-0148.

The experiment stops for discussion if a genuine replay source cannot be
produced, if runtime K/V must be imported, if cache state cannot persist across
calls, if the ABI is intrinsically single-layer, or if an intermediate hidden,
score or probability tensor must cross the Host/DDR boundary.  Passing EXP-0148
authorizes registration of a separate two-to-three consecutive-layer vertical
slice; it does not itself authorize full-stack replication.
