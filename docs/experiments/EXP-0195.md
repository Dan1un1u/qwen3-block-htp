# EXP-0195 — Direct-n decode Gate/Up batch-thirty-two

## Decision and purpose

EXP-0194 is the fastest evidence-valid decode candidate at 38.651475 token/s.
Its largest remaining module is Gate/Up plus SwiGLU at about 7.56 ms/token.
EXP-0190 and EXP-0191 showed monotonic end-to-end gains from Gate/Up batch four
to eight and sixteen.  EXP-0195 tests batch thirty-two, halving the remaining
Gate/Up command count from 672 to 336 per token.

Each 32-tile packed-W4 group is exactly 1 MiB and fits an existing phase-dead
Expanded-S8 slot.  Each bias group is 4 KiB.  The first implementation reused
the current layer's consumed Input- and Post-Attention-RMSNorm gamma regions,
but the Post-Norm alias produced timing-dependent long-sequence output.  The
correct implementation places both bias slots in the 16 KiB RoPE region after
Attention has completed; the next layer reloads that region before use.

## Gates

One binary compares Gate/Up batch sixteen with batch thirty-two.  Decode QKV
remains EXP-0194 batch eight; O, Attention, cache, row-four SwiGLU, Down
DMA2/HMX2, LM head and M64 prefill remain unchanged.  Weights, scales, qparams,
tile pairs and projection arithmetic may not change.

Correctness requires byte-exact hidden hashes, tokens and cache state.  Physical
gates remain exactly 8 MiB VTCM, zero timed intermediate DDR, zero spill/fill,
one FastRPC, one HMX owner, no QNN, unchanged weight bytes and HMX tile pairs,
direct commands 2,464 to 2,128 and weight DMA descriptors 5,226 to 4,554.
Five short rotated pairs must improve complete decode token/s and Gate/Up wall
before ten formal pairs.

## Decision state

Approved and started on 2026-09-05 under the user's decode optimization loop.
Implementation and formal validation completed on 2026-09-05.  Evidence is
valid and the local gate is **pass**.  It is the fastest W4U8 decode candidate
at 39.102150 token/s, but remains pending explicit user promotion.

## Formal result

The repaired five-pair short gate produced byte-exact 193-step signatures in
all pairs and improved decode from 38.757156 to 39.190560 token/s.  Ten formal
rotated pairs then all favored the candidate:

| Metric | Batch16 control | Batch32 candidate | Change |
|---|---:|---:|---:|
| Decode throughput | 38.606195 token/s | 39.102150 token/s | +1.284652% |
| Decode Host wall | 25.9026 ms/token | 25.5741 ms/token | -1.268% |
| M64 prefill | 1275.550 token/s | 1270.068 token/s | unchanged implementation |
| Gate/Up projection | 7.0951 ms/token | 6.7912 ms/token | +4.475% speed |
| Gate/Up plus SwiGLU | 7.5836 ms/token | 7.2797 ms/token | +4.175% speed |

Gate/Up HMX commands fall from 672 to 336 per token, total direct-n commands
from 2,464 to 2,128, and weight DMA descriptors from 5,226 to 4,554.  HMX tile
pairs remain 1,699,840 and weight DDR reads remain 866,032,640 bytes per token.
Every token/hash pair is exact.  Exact 8 MiB VTCM, zero timed intermediate DDR,
zero spill/fill, one FastRPC invocation, one HMX owner, no QNN, and zero timed
transformer W4-to-S8 expansion all pass.

The initial gamma-alias build at `d156cf8` was deliberately not accepted: its
four-step audit happened to pass, but all five 193-step pairs diverged and the
candidate varied across repeats.  Moving the bias slots to dead RoPE storage
removed the race and provides the retained evidence at `5e94019`.
