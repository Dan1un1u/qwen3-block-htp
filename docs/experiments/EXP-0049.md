## Hypothesis and bounded scope

The EXP-0048 Gate/Up path still reports about 44.7k additive ticks and about
31.8k overlapping expanded-slot-wait ticks. The wait counter alone is not
proof that more VTCM capacity helps: EXP-0039 already showed that a deeper ring
without a changed consumer schedule does not improve the complete critical
path. The new hypothesis is therefore narrower: current integer-HMX submission
and readiness granularity makes the expanded-slot producer wait behind a fine-
grain consumer cadence. Coarsening compatible Gate/Up work into a larger HMX
submission may reduce command, publication, and readiness overhead; only then
may extra expanded slots or bounded producer lookahead expose useful overlap.

The direct control is `W4U8-EXP0048-NATIVE-QKV-O`. The bounded search may test
Gate/Up HMX batch sizes four and eight, expanded-slot counts two and four, and
producer lookahead one and two, with no more than six candidates. A ring-depth-
only result is diagnostic and cannot be adopted. QKV, Attention, O, Down,
RMSNorm, residuals, tensor layouts outside Gate/Up, W4 values/scales, activation
qparams, and numerical arithmetic remain fixed.

## Implementation audit and bounded search

The source audit found that EXP-0048 submitted two synchronous HMX-worker
commands for every Gate/Up output tile: the first command performed two
streaming accumulation regions and the second command only stored the finished
U8 output. With 384 Gate/Up output tiles, this created 768 worker wake-ups even
though only 384 independent HMX accumulations existed. The first EXP-0049
candidate fused the final store into the accumulation command and immediately
reduced the Gate/Up pipeline from roughly 44.0k to 31.1k ticks in smoke runs.

The second step submitted consecutive output tiles to the single HMX owner as
one command. A batch of four reduced Gate/Up commands to 96/block. A batch of
eight reduced them to 48/block. The original planning note mentioned testing
two or four expanded slots, but implementation audit showed that the EXP-0048
control already used seven. Batch eight needs eight slots because holding only
seven would make the eighth tile reuse the first slot before the in-flight
batch can release it. The eighth slot was therefore added only together with
the changed batch-eight consumer cadence; this is not the ring-depth-only
hypothesis rejected by EXP-0039. Peak Block VTCM remains unchanged because the
Down plan is still the larger overlapping phase allocation.

Seven paired diagnostic rounds selected batch eight. Batch four and batch
eight are indistinguishable at repeat one within measurement noise, while
batch eight is 0.74% faster at repeat ten and lowers the Gate/Up pipeline by a
further 3.1%:

| Candidate | Repeat-1 Host wall | Repeat-10 Host wall | Repeat-1 Gate/Up | Repeat-10 Gate/Up |
|---|---:|---:|---:|---:|
| Batch 4 | 3.536 ms | 3.152 ms | 13.144k ticks | 13.406k ticks |
| Batch 8 | 3.537 ms | 3.128 ms | 13.021k ticks | 12.989k ticks |

## Formal result and closure

EXP-0049 completed on source commit
`b37d208d262d5a45365d6efe32c03786a5c3a2d3`. The formal control is the exact
archived EXP-0048 binary at
`61cd86fdabc3c3cf535bf13bfd7f5693fc502b8e`; the candidate changes only the
Gate/Up HMX consumer cadence. Seven interleaved paired rounds were collected at
repeat one and repeat ten on stable boot
`77ccafe0-8817-4976-bdae-15af5608d4ff`.

| Metric | Repeat-1 control | Repeat-1 candidate | Change | Repeat-10 control | Repeat-10 candidate | Change |
|---|---:|---:|---:|---:|---:|---:|
| Host wall | 5.141 ms | 3.524 ms | -31.46% | 4.726 ms | 3.126 ms | -33.87% |
| Invocation | 90.532k ticks | 59.728k ticks | -34.03% | 89.636k ticks | 58.640k ticks | -34.58% |
| Gate/Up additive row | 44.697k ticks | 13.590k ticks | -69.60% | 44.727k ticks | 13.738k ticks | -69.28% |
| Gate/Up pipeline | 44.029k ticks | 12.930k ticks | -70.63% | 44.077k ticks | 13.084k ticks | -70.32% |
| Expanded-slot wait | 31.722k ticks | 7.126k ticks | -77.54% | 31.763k ticks | 7.156k ticks | -77.47% |
| HMX-ready wait | 6.877k ticks | 8.782k ticks | +27.70% | 6.937k ticks | 8.793k ticks | +26.76% |

The increased HMX-ready wait is expected: one longer worker command now waits
inside the batch for streamed regions that have not yet been published. That
local wait is more than offset by eliminating 720 Gate/Up worker hand-offs and
removing producer backpressure. The complete critical path therefore falls by
about one third even though a subordinate wait counter rises.

The physical and mathematical invariants close the attribution. HMX U8xS8
tile pairs remain 49,408/block, weight DMA remains 512 descriptors and
25,444,352 bytes/block, all projection/Attention qparams and W4 values remain
unchanged, and the final output remains byte-exact with hash
`69f22eeb035e5ec5`, zero mismatches and maximum error 0 LSB. Exactly 8 MiB
VTCM is requested and acquired; peak plan size remains 5,306,080 bytes;
intermediate DDR read/write, spill/fill, QNN, graph splitting and additional
HMX ownership remain absent.

Both repeat-one and repeat-ten local gates pass. The candidate
`W4U8-EXP0049-GATE-UP-BATCH8` is eligible for adoption but remains pending;
the Selected Baseline is unchanged until the user explicitly promotes it. The
authoritative evidence is
