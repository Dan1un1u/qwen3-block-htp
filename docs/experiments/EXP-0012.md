# EXP-0012 — Publish linked User-DMA descriptors independently

## Approval

Approved by the user on 2026-08-27 under the continuing request to increase the
standalone Packed-W4 speedup over the project's own Expanded-S8 path.

## Objective

Retain the high transfer efficiency observed for EXP-0011 batch four without
its four-slot publication barrier. A contiguous batch-four W4 transfer reached
47.5 GB/s for gate/up and 57.4 GB/s for down, but could not publish the first
bundle until the whole 130--395 KB transfer completed. It also waited for all
four compressed slots before starting the next batch. Those group barriers
raised producer wait and HMX ready-wait enough to erase the bandwidth gain.

The candidate creates a hardware-linked User-DMA descriptor chain containing
one descriptor per output bundle. It issues one `dmstart` for two or four
descriptors, observes each descriptor's hardware completion state in order, and
publishes that bundle's HVX expansion tasks immediately while later descriptors
continue. This separates DMA start amortization from bundle publication
granularity.

## Fixed contract

Both real shapes remain in scope. Gate/up keeps 64 K tiles per HMX publication;
down keeps 96. Raw signed W4, per-output integer scale in HMX conversion,
asymmetric U8 zero-point correction, six HVX workers, four compressed slots,
eight expanded slots, integer HMX, output saturation, DDR boundaries, clocks,
and power votes are unchanged. The EXP-0011 batch-one and contiguous batch-two
paths remain controls. Expanded-S8 receives an analogous linked-chain-two path
so the final storage comparison remains fairly searched.

One chain descriptor corresponds to exactly one existing bundle and writes one
existing ring slot. No weight may be cached across repeats. Descriptor
completion is the only new publication signal; HMX work, HVX arithmetic,
logical bundle count, and output math must remain identical. Runtime evidence
must distinguish DMA descriptors from `dmstart` instructions and count per-
descriptor completions.

## Gates

A bounded chain-completion timeout is mandatory during bring-up; on timeout or
DMA error the run returns a failure rather than spinning indefinitely. All four
patterns and both shapes must remain byte-exact with the independent Host
reference. There may be no fallback, QNN dependency, hidden DDR intermediate,
resource, power, DMA, or synchronization failure, or device reboot.

Formal timing uses repeat-10 Host wall latency in rotated order. The local gate
requires the fastest linked W4 plan to beat EXP-0011 contiguous batch two for
both shapes. The same matrix reports the fastest linked or unlinked S8 plan;
beating it for both shapes is the stretch target. DMA starts, descriptor
completions, weight bandwidth, producer wait, HMX ready-wait, and pipeline time
explain the result but do not replace Host wall latency.

## Result

Completed with valid evidence but failed the two-shape local performance gate.
The formal matrix contains 224 records: 56 correctness runs and 168 rotated
repeat-10 timing runs. All outputs are byte-exact with the independent Host
reference and mutually equivalent. All 256 descriptors in each repeat-one
shape completed, the bounded timeout count stayed zero, HMX execution and
stream counts were unchanged, and the device boot ID remained stable. There
was no worker fallback, QNN dependency, resource, power, DMA, or synchronization
error.

Linked chain two is the fastest linked W4 plan for both shapes. For down it
reduced Host wall median from the EXP-0011 contiguous-batch-two control of
6.308 ms to 6.197 ms, a 1.76% improvement. For gate/up it regressed from
8.024 ms to 8.124 ms, or 1.24%. The local gate required improvement for both
shapes and therefore failed. The linked candidates still beat the fairly
searched Expanded-S8 controls by 12.07% for gate/up and 18.84% for down.

The result separates the two effects of descriptor-level publication. Down has
only 640 logical weight bundles per repeat-10 run; linked chain two lowered its
weight-stage median from 24.2K to 22.2K ticks and HMX ready-wait from 5.7K to
4.9K. Gate/up has 1,920 bundles. Its per-descriptor completion polling and
publication overhead raised weight-stage time from 32.0K to 33.7K ticks and
HMX ready-wait from 15.8K to 21.8K, so the finer signal was not free.

Chain four did not win. It reached 40.7 GB/s for gate/up and 65.6 GB/s for
down, but a four-slot compressed ring cannot overlap one four-bundle group with
the next. Producer wait rose to 31.6K and 11.3K ticks respectively, while HMX
ready-wait rose to 45.5K and 21.1K. Adoption remains pending; this experiment
does not replace the successful EXP-0011 projection candidates.
