# EXP-0026 — HVX FP16 residual paths

## Approval and status

Approved by the user on 2026-08-28 after EXP-0025 closed the complete-block
timing ledger and showed that the two residual stages dominate the estimated
audit-free W4F16 block. This is an optimization experiment. It does not accept
EXP-0024, promote a Selected Baseline, or change EXP-0023's role as the
Provisional Source Parent.

## Objective and hypothesis

Replace the two scalar FP16 residual additions in the real Qwen3-1.7B layer-14,
`M=64` block with an HVX SIMD implementation. Establish a performance mode in
which full-tensor numerical audits do not execute inside the timed steady-state
invocation, while retaining separate correctness invocations with all audits
enabled.

EXP-0025 measured 470,922.8 ticks of residual addition after subtracting the
two residual audits, about 66.22% of its estimated audit-free W4F16 envelope.
The hypothesis is that a contiguous FP16 elementwise add over `[64, 2048]` can
be expressed as 128-byte HVX vector loads, FP16 vector addition, and vector
stores without scalar per-element work, extra synchronization, or an additional
VTCM/DDR boundary.

## Ordered milestones

### A — Audit-free timing control

Add a runtime mode that disables all full-tensor numerical audit scans during
timed invocations. Prove that scalar audit-on and scalar audit-off executions
produce identical output byte hashes for each Project Variant. Use audit-off
scalar results as the only performance control.

### B — Standalone HVX residual add

Implement one shared HVX FP16 residual function and use it at both block
residual sites. Compare scalar and HVX paths in the same artifact set and on the
same boot. The local gate requires finite and implementation-reference-valid
output, exact audit-off scalar/HVX output hash equality when FP16 arithmetic is
unchanged, lower combined residual ticks, and non-regressing complete-block
Host wall latency for both F16F16 and W4F16. Repeat-ten Host wall per block is
primary; no fixed percentage speed threshold is imposed.

If this gate fails, stop before any fusion and discuss the evidence with the
user.

### C — Conditional post-attention residual plus RMSNorm fusion

Only after milestone B passes, test a fused first residual and post-attention
RMSNorm path. The fused path must still materialize the FP16 post-attention
residual in VTCM because it is required by the final residual connection. It may
combine residual generation with the RMS square accumulation, then perform the
normalization scaling pass. It must preserve the FP16 residual boundary and
existing RMSNorm numerical contract.

The final residual has no following RMSNorm inside this Execution Unit and is
not silently fused across the block boundary. A future projection-epilogue
fusion is outside this experiment.

Retain the fusion only if it is numerically valid and strictly improves fresh
repeat-ten complete-block Host wall latency over the standalone HVX residual
candidate for both Project Variants. Otherwise retain milestone B alone.

## Implementation

The retained source head is
`24bd753fe2c13e268dc82cb3d5cf8ac821cff93a`. Protocol ABI version 5 adds an
explicit numerical-audit switch and three selectable residual modes: the old
scalar control, one shared standalone HVX FP16 add used at both residual sites,
and a conditional first-residual-plus-post-RMSNorm fusion. Timed runs turn all
full-tensor numerical audits off symmetrically; separate correctness runs keep
them on.

The standalone residual hot loop operates on four 128-byte HVX vectors per
iteration and uses native FP16 vector add, with the same FP16 materialization
boundary in VTCM. The fused candidate combines the first residual write with
the RMS sum-of-squares scan, then performs the existing normalization scale
pass. It still materializes the post-attention residual for the final skip
connection. The final residual remains a standalone HVX add.

## Residual result

The primary repeat-ten medians are:

| Project Variant | Scalar Host wall | HVX Host wall | HVX change | Scalar residual ticks | HVX residual ticks | Residual change |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| F16F16 | 38.5623 ms | 13.6920 ms | -64.494% | 473,886.5 | 189.4 | -99.9600% |
| W4F16 | 37.4702 ms | 12.5978 ms | -66.379% | 473,362.0 | 189.3 | -99.9600% |

This is a real inference-kernel improvement, not the audit-mode correction.
The scalar and HVX performance controls both run with audits disabled. Each
scalar residual consumes about 236,000 ticks, whereas each standalone HVX
residual consumes about 94--95 ticks. The original residual bottleneck is
therefore removed without adding an intermediate memory boundary.

The fused first residual plus post-RMSNorm path reduces that local pair from
about 969.6--969.7 ticks to 919.0--919.1 ticks. Its complete-block Host wall is
13.6892 ms for F16F16 and 12.5949 ms for W4F16, respectively 0.0203% and
0.0225% below standalone HVX. This narrowly satisfies the experiment's strict
formal rule of improving both Project Variants, so the selected local
candidate is `hvx_fused_post_norm`. The margin is near run-to-run noise and is
not evidence of a material block-level fusion gain; standalone HVX accounts
for essentially all of the improvement.
