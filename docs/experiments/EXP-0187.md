# EXP-0187 — Decode-native M1 projection and pipeline feasibility gate

## Decision and purpose

The user approved an initial validation of a decode-native architecture after
EXP-0185 established the selected W4U8 token-generation baseline.  Existing
evidence shows that one M1 decode step streams the same complete compressed
weight set as M64 prefill and reports nearly the same HMX tile-pair count, while
aggregate weight-DMA and HMX time are approximately additive in the complete
decode wall.  This experiment determines whether the dominant limitation is a
fixed M64-like HMX work granularity, insufficient DMA/HVX/HMX overlap, or both.

The source and direct control are the accepted EXP-0185 commit
`537650293920eb62c3cc49833df613246e8fb0b9`.  EXP-0186 is rejected and is not a
source parent.  M64 prefill remains unchanged and diagnostic only.

## Bounded execution

The first phase adds an untimed audit mode for a real Qwen3 middle-layer M1
projection path.  It records closed DSP intervals for compressed-weight DMA,
W4-to-S8 HVX expansion, HMX execution, readiness waits and their unions and
overlaps, alongside the existing command, tile-pair, byte and VTCM counters.
The same audit is run for M64 only to establish physical-work ratios; audit
instrumentation is never used for performance ranking.

After the audit identifies the limiting mechanism, one bounded decode-only
candidate may change either the M1 HMX physical mapping or the cross-projection
DMA/expand/HMX schedule.  It may not change weights, scales, qparams,
projection mathematics, Attention, cache, nonlinear operators, LM head, M64
prefill, F16F16, W4F16 or the one-HMX-owner contract.  No full-stack rollout is
allowed until this representative gate lowers equivalent-scope M1 wall time.

Correctness requires byte-exact valid M1 outputs against EXP-0185 and the
independent integer reference.  Physical requirements remain exactly 8 MiB
VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC execution unit,
one HMX owner and no QNN.  Failure to reduce physical M1 work or to convert
additional overlap into lower equivalent-scope wall is a stop condition and is
reported before any broader integration.

## Decision state

Approved by the user on 2026-09-04 with the instruction to begin the initial
validation experiment.

The initial representative gate is complete and evidence-valid.  Its local
gate is **pass**, while project adoption remains **candidate**: no full-model
baseline is promoted by this result alone.

## Physical audit result

The existing U8 HMX projection keeps the physical spatial tile at 64 rows.
For a synthetic 2048-to-6144 projection, changing only the number of logically
valid rows from 64 to 1 left pipeline work effectively unchanged: the prior
packed-W4 path measured about 210k pipeline ticks at both M1 and M64, while the
new direct-n path measured about 50--51k ticks at both M1 and M64.  Therefore
the public spatial-mask interface does not provide a true one-row HMX command.

The bounded candidate instead changes the weight-side physical contract.  It
reorders each signed W4 32-by-32 tile into the HMX `weight.n` carrier and feeds
that carrier directly to integer HMX.  The empirically verified input-nibble
lane order is `0,4,1,5,2,6,3,7`.  Activation U8, per-channel scales, output
qparams and projection mathematics remain unchanged.  This removes all timed
HVX W4-to-S8 expansion from the candidate.

## Formal real-layer result

The formal gate uses actual layer-14 post-Attention-normalized and SwiGLU
activations, actual W4 weights, per-channel scales and HMX bias words.  Ten
paired rotations were run in alternating order for repeat1 and repeat10.  The
valid M1 output is byte-exact against both the old HMX path and an independent
integer-accumulation plus native-HMX-conversion reference.

| Projection | Repeat | Existing path host wall | Direct-n host wall | Speedup | Existing pipeline | Direct-n pipeline |
|---|---:|---:|---:|---:|---:|---:|
| Gate+Up pair | 1 | 1.770 ms | 1.517 ms | 1.166x | 15,257.5 ticks | 10,244.5 ticks |
| Gate+Up pair | 10 | 8.984 ms | 6.283 ms | 1.430x | 147,394.5 ticks | 101,564.5 ticks |
| Down | 1 | 0.898 ms | 0.685 ms | 1.312x | 6,707.5 ticks | 3,262.0 ticks |
| Down | 10 | 4.101 ms | 2.387 ms | 1.718x | 63,891.0 ticks | 32,013.5 ticks |

All 80 formal device runs reported zero mismatch, zero DMA timeout and zero
streaming timeout.  The direct-n cell reported zero W4 expansion, retained the
exact 8 MiB VTCM allocation, used one HMX owner and one FastRPC execution unit,
and created no timed intermediate DDR tensor.  M64 prefill and all non-MLP
operators were untouched.
