## Question and comparison semantics

This is a characterization experiment, not a new optimization and not a
baseline-promotion experiment. It asks why the current fastest W4U8 path is
still slower than the selected W4F16 baseline, and which complete-block stages
and overlapping DMA, HVX, and HMX intervals dominate that gap.

The primary comparison is current-best versus current-best on one source
commit and one device boot. W4F16 reproduces the selected
`W4F16-EXP0038-NORMS` runtime plan; W4U8 reproduces
`W4U8-EXP0046-NATIVE-MLP-IO`. Because the two variants intentionally use
different activation arithmetic, Attention implementation, layout boundaries,
and tuned schedules, this result must not be described as an identical-plan
single-variable comparison. The shared W4 values and scales must nevertheless
be proven byte-identical before timing conclusions are admitted.

## Fixed contract and completion gates

- The Execution Unit is the real Qwen3 layer-14 complete block at M=64.
- Both variants are built from the same source commit, packaged together where
  supported, deployed together, and measured on one stable device boot.
- W4F16 uses the selected EXP-0038 `norms` plan, including its accepted
  projection, Attention, MLP, and Crouton-boundary settings. W4U8 uses the
  complete EXP-0046 plan, including integer Attention, QKVO batch four, and
  native MLP input/output boundaries.
- Each variant must independently pass its declared implementation reference,
  output-hash stability, and numerical diagnostics. Cross-variant byte equality
  is neither expected nor required.
- One FastRPC invocation per block execution unit, one HMX owner, exactly
  8 MiB VTCM, zero intermediate DDR, zero spill/fill, and no QNN path are
  mandatory for both variants.
- Seven interleaved paired rounds are required at repeat one and repeat ten on
  one stable boot. Host wall per block is the primary latency measure.
- There is no speed gate and no automatic adoption decision. Completion means
  that correctness and physical gates pass and the PC-027 report fully closes
  the additive block ledger plus overlapping projection, Attention, MLP, DMA,
  HVX, HMX, readiness, slot-pressure, and lifetime diagnostics.
- The report must separate mutually exclusive ledger rows from overlapping
  engine-work counters, quantify every W4U8-minus-W4F16 gap, and identify which
  hypotheses are supported, rejected, or still unobservable.
