# EXP-0129 — W4F16 Gate/Up fourth HVX expansion worker

## Decision and hypothesis

The continuing user-approved W4F16/W4U8 specialization loop authorizes this
bounded W4F16 experiment. It branches from EXP-0127's selected W4F16 control,
which includes the accepted carrier-only QKV specialization and the current
Gate/Up fence plan. It does not modify the frozen Public Common Layer or
promote a baseline.

At repeat ten, the current three-worker Gate/Up path retains about 10.98
thousand HMX-ready-wait ticks per block. Its W4-to-FP16 expansion is materially
heavier than the W4U8 decoder, so EXP-0121's rejected W4U8 fourth-worker result
does not by itself settle this W4F16 balance. The candidate adds one bounded
HVX expansion worker while preserving the same region-32 publication, DMA8
prefetch, scale cache, batch-eight HMX consumer, arithmetic and output.

## Gates

The two runtime cells use three and four W4F16 expansion workers. They must be
byte-exact with output `f18b9abbe1487231`, pass the existing expansion audit,
request exactly 8 MiB VTCM, retain zero intermediate DDR/spill, one FastRPC
Execution Unit, one HMX owner, no QNN, and identical weight bytes, DMA
descriptors, HMX commands, tile pairs and peak plan. Only worker occupancy and
its overlap/wait consequences may change.

The candidate passes only if Gate/Up plus SwiGLU and complete Host wall both
strictly improve in ordinary and paired repeat-one and repeat-ten medians.
Formal closure requires PC-027 and PC-028. Only the user may promote a
Selected Baseline.
