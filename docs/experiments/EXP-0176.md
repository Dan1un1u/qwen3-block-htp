# EXP-0176 — Decode W4U8 O-projection HMX batch-eight

## Decision and purpose

The selected EXP-0173 baseline spends about 4.83 ms of each full-stack decode
token in the 28 O projections. Earlier M=64 block evidence showed that changing
only O-projection HMX grouping from four to eight outputs reduced O wall by
about 7.5% and complete block wall by about 1%, but that experiment was
rejected by an old Down-preservation sub-gate. PC-029 now correctly ranks an
eligible token-boundary candidate by direct full-stack throughput and treats
module movement as diagnosis rather than an independent veto. M=1 continuous
decode is also a different execution regime from that earlier M=64 gate.

EXP-0176 therefore revalidates the mechanism on the current selected W4U8
token-generation baseline. The control retains O batch four. The sole
candidate uses O batch eight only for logical-M=1 decode; M=64 prefill remains
byte-identical on batch four. The expanded O carrier is enlarged only as needed
for eight output tiles. Q/K/V grouping, Attention, residuals, Gate/Up, SwiGLU,
Down, cache state, RMSNorm, embedding, LM-head batch sixteen, weights, qparams,
and arithmetic are immutable.

## Gates and evidence

Static and device evidence must show the requested O batch, command count,
unchanged HMX tile work, byte-exact hashes and token sequence, exact 8 MiB
VTCM, one FastRPC/pass, no QNN, zero timed intermediate/full-logit DDR, zero
spill/fill, and zero ledger residual. Five rotated 17-step sessions provide the
short gate. Under PC-029, lower complete decode Host wall is the performance
gate; O wall and downstream timing remain mandatory diagnostics but are not
separate vetoes. A failure stops without the 193-step formal run. A passing
candidate must complete ten rotated 193-step pairs plus independent reference
and regression evidence before becoming promotion-eligible.
