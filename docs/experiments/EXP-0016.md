# EXP-0016 — Evaluate gate and up projections in one DSP invocation

## Approval

Approved on 2026-08-27 by the user's continuing instruction to optimize the
standalone W4 path until it provides useful acceleration.

## Objective

Remove a larger boundary cost than persistent worker creation can address. The
EXP-0015 evidence leaves only about 1.4K qtimer ticks of unattributed DSP setup
per W4 run after activation staging and output DMA, while Host wall still pays
roughly 0.5--0.6 ms beyond measured DSP work. Qwen3 gate and up projections
share the same `[64, 2048]` activation and have identical output width. The
candidate concatenates their independent weights and outputs into one
`M=64, K=2048, N=12288` physical projection and evaluates it through one
Host-to-DSP run invocation.

The control executes two distinct `M=64, K=2048, N=6144` projections inside
the same Prepared Runtime Session and measures their combined Host wall. The
candidate must therefore save a real invocation and input-stage boundary, not
merely compare against session open or resource acquisition.

## Fixed contract

Both gate and up use the EXP-0015 prepared resource session, 2 MiB VTCM,
linked 2-D output DMA, asymmetric U8 activation with zero-point correction,
the selected gate/up weight-DMA/HVX/HMX schedule, and the same independent
Host reference. Gate and up weights remain distinct; concatenation may only
change their physical N-axis placement. Packed W4 and the byte-identical
Expanded-S8 control receive the same paired representation and measurement
procedure. HMX tile-pair work, per-output-channel scale, stored bytes,
quantized outputs, clocks, DDR graph boundaries, and output ordering remain
auditable.

The paired output is `[gate_channels, up_channels]`. The experiment does not
apply SiLU, multiply gate and up, run down projection, add a DDR intermediate,
or claim a complete MLP. The VTCM plan must remain within the same 2 MiB
request and no QNN or QAIRT component may be introduced.

## Gates

All inherited patterns and both storage formats must remain byte-exact with
the independent Host reference. Splitting the paired output into its two 6144
channel halves must match the outputs from the two separate control calls.
There may be no worker fallback, timeout, resource error, graph/backend
fallback, or device reboot. Runtime counters must prove the expected doubled
N-axis HMX and weight work without changing K tiling or arithmetic.

Formal timing uses rotated repeat-one and repeat-ten records. Primary latency
is paired candidate Host wall versus the sum of two separate measured calls
inside one prepared session. The local gate requires paired W4 to improve both
repeat-one and repeat-ten latency. Expanded-S8 receives the same gate and its
paired W4 comparison is reported separately. Prepare, release, session open,
and session close remain outside the compared hot boundary and are reported
for audit. The user alone may accept the result or promote a Selected Baseline.

## Result

Completed with valid evidence and a local gate pass on 2026-08-27. Source
commit `457d48778eacbbc9f8f0460a49a6c8c0d245c7e5` produced 176 formal records:
16 correctness records, 80 rotated repeat-one timing records, and 80 rotated
repeat-ten timing records. All device outputs were byte-exact against the
independent Host reference, and the paired output was byte-identical to the
two-call control after canonical channel ordering. There was no fallback,
timeout, resource error, graph/backend fallback, or device reboot.

For packed W4, the paired invocation reduced median Host wall from 1.657 ms to
1.422 ms at repeat one, an improvement of 14.14%. At repeat ten it reduced the
combined median from 6.583 ms to 6.191 ms, an improvement of 5.95%. The same
structural change improved Expanded-S8 by 8.13% and 4.92%, respectively. In the
paired candidate itself, packed W4 was 17.85% faster than Expanded-S8 at repeat
one and 20.88% faster at repeat ten.

The paired candidate and two-call control performed the same total weight,
output, and HMX work. The gain therefore comes from removing one Host-to-DSP
run boundary and one activation staging pass, not from reducing projection
arithmetic. The candidate still writes the complete 12,288-channel gate/up
output across the graph boundary and does not include SiLU, gate multiplication,
or the down projection. This is a successful local execution-unit optimization,
not a complete MLP result and not a Selected Baseline. Adoption remains pending
the user's decision.
