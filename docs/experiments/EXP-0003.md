# EXP-0003 — Standalone multi-tile U8×S8 projection probe

## Approval

Approved by the user on 2026-08-27 by requesting continuation of the proposed
multi-tile projection experiment after EXP-0002 passed its substrate gate.

## Objective

Extend the proven Integer HMX Tile Probe into one complete Projection Probe
without QNN. The experiment must establish mathematically correct cross-K
accumulation, cross-N output assembly, explicit VTCM buffer ownership, and an
auditable data-movement and HMX dependency plan before any Qwen3-shaped
projection is attempted.

## Fixed arithmetic scope

The projection shape is `M=64, K=128, N=96`. Asymmetric U8 activations use
zero point 128 and signed S8 weights use zero point 0. The implementation must
accumulate four K=32 contributions in S32 before one saturated U8 conversion;
it must produce three N=32 output tiles. The complete projection therefore
contains twelve HMX activation/weight tile pairs.

The authoritative Host reference evaluates the complete row-major expression
`clamp(sum_k((activation[m,k] - 128) * weight[k,n]), 0, 255)` without sharing
the DSP packing or tiling implementation. Identity-like, signed, structured,
and saturation-boundary patterns must all match byte-for-byte.

## Physical-plan scope

Shared rpcmem is the Native Boundary, not an HMX operand store. The complete
activation is staged once into four project-owned K tiles in VTCM and reused
across all N tiles. Two VTCM weight-bundle slots must form a producer/consumer
double buffer; the third N tile must reuse the first slot only after HMX has
finished consuming it. Physical output tiles must be assembled into one
row-major boundary output. Buffer fill, wait, reuse, and HMX execution counts
must be recorded. DMA or HVX staging and all waits must be explicit rather
than delegated to QNN or an opaque graph compiler.

Timing must separate at least operand staging, the HMX projection core, output
assembly, and full Host wall time. These measurements characterize the first
physical plan; this experiment has no speed threshold and cannot be called an
optimized projection.

## Hard gate

The V79 DSP build must retain identifiable integer-HMX activation, weight,
accumulator, bias, and saturated-output instructions. One FastRPC invocation
must produce an exact 64×96 output for all four deterministic patterns, report
twelve HMX tile-pair executions per projection repeat, use the declared VTCM
buffers, and return valid stage timings. Host and DSP artifacts must have no
QNN or QAIRT execution dependency.

A stalled FastRPC process must not be killed because forced FastRPC teardown
previously triggered a device kernel panic. A diagnostic stall stops the
experiment for inspection; no automatic retry or reboot loop is permitted.

Passing establishes only a correct multi-tile Projection Probe. It is not a
Qwen3 projection, performance candidate, or Selected Baseline.

## Result

The gate passed on source commit
`a5791f8f6f46f7745d9608a2f799ffa252827da9`. The final implementation stages
the 64x128 activation once as four resident VTCM tiles, streams all four K
tiles through one integer-HMX `deep:cm` dot-product for each N tile, and uses
two producer/consumer weight slots for the three 32-channel output tiles.
Static evidence contains the U8 activation load, S8 weight load, accumulator
clear, bias load, saturated U8 output store, User DMA start/wait instructions,
and no QNN or QAIRT dynamic dependency.

Eight formal device runs covered identity, signed, structured, and saturation
boundary patterns at repeat counts 1 and 1000. Every run returned DSP, DMA,
and synchronization status 0 with byte-exact output, for a total of zero
mismatches. Each 1000-repeat run executed 12,000 logical HMX tile pairs, 3004
DMA submissions, 6008 DMA waits, and 2998 weight-slot reuses without a device
restart or a stale-buffer failure.

Across the four 1000-repeat runs, pipeline time ranged from 214,467 to 222,198
qtimer ticks and averaged 219,957.25 ticks. HMX compute averaged 54,330.25
ticks, while weight staging averaged 146,830.25 ticks. This establishes a
correct and auditable first Physical Plan, but also shows that sustained
projection time is currently dominated by staging and consumer wait rather
than the integer HMX core. There was no speed threshold, so this observation
does not make the probe an optimized projection or Selected Baseline.

Bring-up exposed two decisive low-level contracts. First, four independent
ordinary `:cm` loads do not implement a K=128 dot product; the four K tiles
must be expressed as one continuous `deep:cm` stream before the single output
conversion. Second, `dmwait` status 0 alone was insufficient to publish the
completed VTCM write to the HMX worker. An explicit barrier between DMA wait
and semaphore publication was required; without it, the same buffers produced
apparently random saturated output despite successful resource and DMA status.
