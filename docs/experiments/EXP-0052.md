# EXP-0052 — W4U8 independent Q/K preparation head scheduler

## Approval and parent

Approved by the user on 2026-08-30 after asking to continue optimizing QKV
because its repeat-ten ledger share remained anomalously larger than the MLP
share. The implementation parent is the latest accepted local W4U8 candidate,
EXP-0050 source commit `67c112e298b49e96cbaa1a78b5223dad54040c42`.
EXP-0051 is a rejected sibling and is not inherited. The source branch is
`codex/exp-0052-w4u8-qk-prep-head-scheduler`.

## Evidence-driven hypothesis

EXP-0051 attribution shows that the apparent QKV interval is not dominated by
QKV matrix multiplication. At repeat ten, complete QKV is 17,688.7 ticks, but
the final wait for the three Q/K preparation HVX workers is 10,832.7 ticks.
QKVO DMA-expand-HMX lifetime is 9,277.3 ticks and overlaps the preparation
work.

The current preparation scheduler claims one GQA group per worker. A worker
normalizes the group's two Q heads and then blocks until its K head is ready.
With three workers, groups zero through two can therefore hold all workers at
the K boundary while later Q heads are already available. The remaining Q
heads cannot use the projection interval and become a join tail.

EXP-0052 replaces only this scheduling order with independent head tasks. The
sixteen sequentially published Q heads are consumed first; the eight K-head
tasks follow. Because Q and K projections themselves publish in increasing
head order, workers can continue claiming available Q work instead of waiting
on an unavailable K that belongs to an early GQA group. The same Q/K Norm,
RoPE and native K-carrier functions, qparams, bytes and per-head outputs are
retained.

## Fixed contract and gates

- The Execution Unit is the real Qwen3 layer-14 complete block at M=64.
- The direct control is `W4U8-EXP0050-DOWN-COMMAND-FUSION`. EXP-0051 head-pair
  commands are disabled; QKV remains batch four with 32 commands per block and
  complete-block HMX commands remain 256.
- QKV projection, Attention, O, Gate/Up, Down, all weights, qparams,
  arithmetic, tensor layouts, and publication order are immutable.
- The prepared result for every GQA group must contain the same two normalized
  and rotated Q heads and the same normalized/rotated packed K carrier.
- One FastRPC invocation, one HMX owner, exactly 8 MiB VTCM, zero intermediate
  DDR, zero spill/fill, and no QNN path are mandatory.
- Final output must be byte-exact to EXP-0050 and the independent
  implementation reference must report zero mismatches and maximum error
  0 LSB.
- The candidate passes only if `attention_qk_norm_pool_wait_ticks`, complete
  QKV additive ticks, and complete Host wall are all strictly lower than the
  paired control at repeat one and repeat ten.
- Formal selection uses seven interleaved paired rounds on one stable boot and
  closes every PC-027 profiling field. A local pass creates only a candidate;
  baseline promotion remains a user decision.

Formal results will be retained under
`D:/llm_exp/results/qwen3-block-htp/exp0052`; binaries under
`D:/llm_exp/models/qwen3-block-htp/exp0052`.

## Implementation

Source commit `f2d07a2727f316ad641ce2e7b423be804a6a3c1a` adds one
candidate mode while retaining the EXP-0050 control in the same binary. The
candidate atomically claims task IDs 0 through 23: IDs 0 through 15 are Q
heads in projection publication order and IDs 16 through 23 are K heads. Each
task calls the unchanged native U8 Q/K Norm-RoPE routine; each K task also
builds the unchanged signed carrier and zero-point correction for its GQA
group. Telemetry counts 24 logical tasks per block in both modes.

The first complete collection at
`D:/llm_exp/results/qwen3-block-htp/exp0052/20260829T164255Z_0f1be03b6e6e_formal`
is excluded from formal evidence. All device samples completed, but the new
validator incorrectly required diagnostic audit DDR writes to be zero. Audit
mode intentionally exports 524,288 bytes for correctness inspection; only
the audit-off performance runs are subject to the zero-intermediate-DDR gate.
The validator boundary was corrected and a new complete run was collected
rather than reusing the excluded result.

## Decision and interpretation

The local gate passes and EXP-0052 is eligible to be used as the latest W4U8
candidate. It is not the Selected Baseline because promotion remains a user
decision.

The original 31.7% QKV ledger share was therefore not evidence that QKV HMX
math had become the block's largest true compute load. More than 10.8k of its
roughly 17.7k ticks were a join tail caused by group-owned HVX preparation
workers. Removing head-of-line blocking cuts that wait by roughly 16% to 18%
and QKV wall by roughly 10% while QKVO HMX lifetime, weight expansion, traffic,
commands and arithmetic remain effectively fixed. After the fix, repeat-ten
QKV is about 15.96k ticks, while Gate/Up plus Down is about 20.44k ticks; the
expected MLP-dominant ordering is restored at the additive-ledger level.

The complete PC-027 table is retained in
`docs/experiments/EXP-0052-PROFILING.md`. The Selected Baseline remains
`W4F16-EXP0038-NORMS` until explicit user promotion.
