# EXP-0103 — Interleaved two-head U8 Q/K Norm-RoPE kernel

## Decision and motivation

The accepted EXP-0084 already assigns two adjacent Q or K heads to one HVX
task, batches 16 rows through one vector reciprocal-square-root call, and
shares preconverted RoPE coefficients. Inside that paired task, however, the
two heads still execute the complete SF32 gamma, normalization, RoPE and
requant chain serially. Formal repeat-ten evidence attributes about 28.5k
overlapping work ticks to the W4U8 Q/K Norm-RoPE path versus about 6.3k for the
W4F16 FP16 worker path, while W4U8 retains roughly 1.2k pool-join ticks.

EXP-0103 first tested a genuinely paired HVX microkernel. That direct design
was rejected at the static gate because the compiler allocated a 3,584-byte
vector stack frame. The measured candidate therefore preserves the paired-task
boundary and exact per-head arithmetic order while hoisting shared input-zero-
point and output-encoding setup. It preserves the existing batched rsqrt,
shared RoPE cache, Q/K task pairing and projection/Attention schedule.

## Fixed contract and gates

This is a clean sibling from accepted EXP-0084. Packed W4 weights, U8 qparams,
row/head order, gamma, RoPE coefficients, reciprocal-square-root values,
per-head floating operation order, rounding, output packing, projection
commands, Attention, residuals and MLP remain fixed. Control uses the existing
serial-inner-pair helper; candidate uses the interleaved two-head helper in the
same binary. No arithmetic reassociation, approximate fixed point or qparam
change is allowed in this experiment.

Audit-on control and candidate must be byte-exact at Q/K Norm-RoPE outputs,
score, probability, AV and final block output with zero mismatches and zero
maximum LSB. Compiler/static evidence must show the candidate paired helper,
shared norm/output vector constants and no vector stack spill in the hot loop.

Both cells request/acquire exactly 8 MiB VTCM, keep the same peak plan, one
FastRPC and one HMX owner, and perform zero intermediate DDR and spill/fill.
Weight bytes, DMA descriptors, HMX commands and 49,408 U8-by-S8 tile pairs are
unchanged. Five order-rotated rounds at repeat one and repeat ten require
Q/K Norm-RoPE work, QKV wall and complete Host wall to strictly improve by
ordinary and paired medians at both repeat counts. PC-027 and PC-028 close the
experiment. A local pass remains pending explicit user adoption.

## Result

Completed as a valid negative experiment at source commit
`66a9cb6162f85a48622cb54a8414a74ebfeace91`.

The simultaneous two-head implementation did not reach the device: its 3.5 KiB
stack frame demonstrated that keeping both full SF32 head pipelines live
exceeded the available vector-register schedule. The replacement candidate
compiled to a 540-byte helper with no `allocframe` or vector stack access,
versus 704 bytes for the control helper. It shares invariant conversion setup
without changing the per-head arithmetic order.

Correctness and physical gates passed. Control and candidate are byte-exact at
the final output and established Input-RMSNorm, QK, probability and AV
boundaries with zero mismatches and zero maximum LSB. Both request/acquire
exactly 8 MiB VTCM, use the same 5,306,080-byte peak plan, perform zero
intermediate DDR and spill/fill, and retain one FastRPC, one HMX owner,
25,444,352 weight bytes, 512 DMA descriptors, 176 HMX commands and 49,408
U8-by-S8 tile pairs per block.

The local kernel effect is real. Q/K Norm-RoPE overlapping work improves
4.450% ordinary/4.405% paired at repeat one and 4.217%/4.217% at repeat ten.
The additive QKV ledger improves 3.838%/3.732% and 3.462%/3.334%, while
repeat-ten Q/K pool wait improves 22.946%/23.196%. Complete Host wall at repeat
ten improves 0.847% ordinary and 0.875% paired across five consistently positive
pairs.

The strict gate nevertheless fails because repeat-one Host wall changes
+8.616% by ordinary median, despite a -1.510% paired median. Repeat-one Host
samples retain large run-order variance, and the contract requires both
ordinary and paired medians at both repeats. EXP-0103 therefore has
`local_gate=fail` and `adoption_status=rejected`; the Selected Baseline remains
EXP-0084. Reopening requires a paired-kernel hypothesis that shortens a larger
critical interval and passes both repeat counts, not another constant-hoist
variant.
