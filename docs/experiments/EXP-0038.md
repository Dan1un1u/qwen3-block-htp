# EXP-0038 — Crouton-native projection boundaries

## Approval and source

Approved by the user on 2026-08-29 as one serial long-running experiment that
must validate three independently attributable directions: Crouton-native QKV,
Crouton-native AV-to-O, and direct RMSNorm-to-Projection Crouton stores. The
source starts from the fastest valid EXP-0036 implementation commit
`a959219dfa95d6b7b1b45aa18d4e03f3d60d656c`, not from the failed EXP-0037
Q-Batch-4 candidate. This source choice does not promote a Selected Baseline.

## Evidence basis

EXP-0037 reduced local Q projection wall by 3.2 to 3.4 percent but delayed the
QK Norm-RoPE consumer enough to regress QKV and complete Host wall. Therefore
the next optimization unit is the producer-consumer boundary from projection
HMX output through Norm-RoPE into Attention, not an isolated Q command count.
EXP-0036 separately proved that deleting a row-major producer-consumer boundary
with a Crouton-native handoff can improve the complete block.

The current implementation also materializes AV output as row-major
Attention-concat before immediately repacking it for O, and materializes both
Input-Norm and Post-Attention-Norm output as row-major before packing for their
next projections. These are independent physical-boundary hypotheses and must
remain independently selectable even when tested serially.

## Fixed contract

- The Execution Unit is the real Qwen3-1.7B layer-14 complete block at `M=64`
  in one FastRPC invocation, measured at repeat one and repeat ten.
- Controls are the fastest valid EXP-0036 F16F16 plan and the EXP-0036 W4F16
  Crouton-native SwiGLU Batch-8 plan.
- W4 values, per-channel scales, projection arithmetic, FP16 RMSNorm, RoPE,
  standard stable Softmax, AV, residual and MLP mathematics remain unchanged.
- Every variant requests exactly 8,388,608 VTCM bytes, uses one HMX owner, and
  permits no intermediate DDR, spill/fill, QNN, QAIRT or additional FastRPC
  Execution Unit.
- Each candidate must be byte-exact with its paired control and pass the
  independent Implementation Reference. Layout changes are not numerical
  permission.
- Host wall is primary. Exclusive ledger intervals are additive; DMA, HVX and
  HMX work counters remain overlapping diagnostics.

## Serial milestones

### Stage A — Crouton-native QKV handoff

Keep Q/K/V projection order and Batch-2 HMX scheduling unchanged. Write Q/K/V
projection results into a Crouton-native physical representation, consume Q/K
Norm-RoPE without a complete row-major Q/K materialization, and construct the
QK/AV HMX operands directly. Attention may still begin only after QKV for this
stage so the layout boundary is isolated from a new global HMX schedule.

The speed gate is the combined QKV plus QK-Norm-RoPE plus Attention interval
and complete Host wall, not Q projection alone. Both must strictly improve at
repeat one and repeat ten for F16F16 and W4F16.

### Stage B — Crouton-native AV-to-O handoff

Starting from the fastest valid Stage-A parent, write each AV HMX result into
its final O-projection Crouton activation position and invoke O with that
activation already prepared. Eliminate row-major Attention-concat and the O
activation repack. The relevant Attention-plus-O interval and complete Host
wall must strictly improve at both repeat counts for both numerical variants.

### Stage C1 — Input RMSNorm direct Crouton store

Starting from the fastest valid preceding parent, preserve the exact Input
RMSNorm reduction and value conversion but write normalized FP16 elements into
the QKV HMX activation layout. Remove the row-major normalized materialization
and Q activation pack. Input-Norm-plus-QKV and complete Host wall are the local
speed boundaries.

### Stage C2 — Post-Attention Residual-RMSNorm direct Crouton store

Preserve the fused residual and RMSNorm arithmetic while writing normalized
FP16 values directly into the Gate/Up activation Crouton layout. The
Post-Attention-Residual/Norm-plus-Gate-Up interval and complete Host wall are
the local speed boundaries.

## Continuation and evidence rule

Failure of one local speed gate discards only that candidate. The next
independent milestone resumes from the fastest valid preceding implementation;
the user explicitly requested that all three directions be validated in this
serial loop. Numerical or physical-contract failure stops the affected
candidate, preserves its diagnostic evidence, and continues only after the
control state is restored and verified.

## Formal result

The experiment completed on source implementation commit
`db791a430631eaba8f90bf3d0e8914c4998a15f5`; the stricter evidence validator is
commit `24917512fc35adfd22f97b5123473bb6a7518fd0`. The formal matrix contains 224
records from one stable device boot and is stored at
`D:\llm_exp\results\qwen3-block-htp\exp0038\20260828T193721Z_db791a430631`.
All candidates retained the exact 8 MiB VTCM request, one FastRPC Execution
Unit, one HMX owner, zero intermediate DDR, zero spill/fill and no QNN runtime.
F16F16 output remained byte-exact at hash `704252c89780e695`; W4F16 remained
byte-exact at `f18b9abbe1487231`. The direct Q, K and V HMX operands were also
byte-exact against an audit-only row-major shadow path with zero mismatches.

Stage A implemented the full Crouton-native QKV boundary. Per block it kept all
three projection outputs in Crouton order, skipped 128 projection-output
unpack tiles, produced 24 QK operands and eight AV weights directly, and
removed the corresponding row-major materialization. Its declared boundary
improved for F16F16 by 0.16% at repeat one and 1.26% at repeat ten, and for
W4F16 by 4.13% and 3.76%. W4F16 Host wall also improved by 1.06% and 0.46%, but
F16F16 repeat-ten Host wall regressed by 0.57%. Because the contract forbids a
regression in either numerical variant, Stage A failed its speed gate. The
important diagnosis is that the boundary removal works locally and is useful
for W4, but does not provide a stable cross-variant complete-block gain.

Stage B wrote all sixteen AV head outputs directly into the canonical O
activation Crouton positions and skipped all sixteen row-major AV unpacks. The
Attention-plus-O boundary improved by 1.32% to 1.97% at repeat one and by
1.41% to 1.63% at repeat ten. Nevertheless repeat-ten Host wall regressed by
0.56% for F16F16 and 0.23% for W4F16, so AV-to-O failed its speed gate. The
saved copy/repack work is too small to dominate runtime variance and adjacent
scheduling effects.

Stage C1 made Input RMSNorm write the QKV activation Crouton layout directly.
The Input-Norm-plus-QKV interval improved by 1.36% to 2.24%, but repeat-ten
Host wall regressed by 0.37% for F16F16 and 0.40% for W4F16. Input Norm alone
therefore failed the strict speed gate even though the local boundary improved.

Stage C2 made the fused Post-Attention Residual-RMSNorm write the Gate/Up
activation layout directly. Its declared boundary improved by 1.17% to 2.04%
and all four Host comparisons were non-regressing: F16F16 changed by -0.72%
and -0.001%, while W4F16 changed by -0.16% and -0.19%. It passed its local
gate, although the repeat-ten F16 result is effectively neutral and must not be
overstated.

The cumulative `norms` mode enables C1 and C2 together without QKV or AV-to-O.
It was byte-exact and passed all primary comparisons. F16F16 Host wall improved
by 1.44% at repeat one and 0.33% at repeat ten; W4F16 improved by 0.61% and
0.58%. The combined declared boundary improved by 1.48% to 2.00%. An additional
eleven-round paired W4F16 confirmation produced median Host changes of -0.48%
at repeat one and -1.05% at repeat ten.

Overall EXP-0038 is recorded as `local_gate: fail` because the user requested
all three directions and QKV plus AV-to-O did not pass their strict gates.
Evidence remains valid, Post Norm and combined Norms retain their individual
local passes.

## Adoption and baseline promotion

On 2026-08-29 the user explicitly promoted the fastest valid W4F16 plan as the
first Selected Baseline. Its canonical identifier is
`W4F16-EXP0038-NORMS`. It selects the W4F16 variant and
`crouton_boundary_mode=norms` on implementation commit
`db791a430631eaba8f90bf3d0e8914c4998a15f5`. QKV Crouton-native and AV-to-O
Crouton-native remain disabled; their failed local gates are not adopted into
the Baseline. Input Norm is accepted only as part of the measured combined
Norms configuration, while Post Norm alone is superseded by that combination.

The selected runtime also retains the EXP-0036 Crouton-native Batch-8 MLP,
EXP-0031 GQA/QKV-overlap Attention pipeline, adaptive W4F16 expansion schedule,
fixed 8 MiB VTCM session, one HMX owner and zero-intermediate-DDR contract. The
Project Status record is the authoritative baseline pointer. EXP-0038 keeps its
overall `local_gate: fail`, because baseline adoption of one passing variant
does not rewrite the negative results of the other milestones.
