# EXP-0164 — W4F16 deterministic end-to-end token-generation boundary

## Decision and purpose

The user promoted EXP-0163 and approved completion of the model's input and
output boundaries on 2026-09-03. The existing runtime already executes all 28
Qwen3 transformer layers with persistent cache state, but its Host package
injects offline-generated embeddings and checks offline reference outputs. It
therefore does not yet prove that real token IDs can enter the runtime and
generated token IDs can feed the next decode step.

EXP-0164 first establishes this closed loop for W4F16 because the corresponding
mllm W4A16 model and tokenizer are known to produce usable text. W16A16 may be
used as a diagnostic cross-check if W4F16 fails, but it is not required as a
second implementation. W4U8 is deliberately deferred until the W4F16 boundary
is proven so model-boundary bugs cannot be confused with the known unresolved
W4U8 quantization-accuracy problem.

## Execution boundary

The source parent is the selected EXP-0163 commit
`63de1de7028c5a478f4494c4e64993d34deac503`. The first implementation accepts a
real tokenizer-produced prompt of at most 64 tokens, performs embedding lookup,
executes layers 0-27 with the accepted W4F16 full-stack and cache contracts,
applies final RMSNorm, streams a per-output-channel W4 LM-head through HMX, and
performs deterministic greedy argmax. The selected token is fed back through
embedding for continuous decode in the same Prepared Runtime Session.

The original Qwen3 model at `D:/llm_exp/models/Qwen3-origin` is the sole source
for tokenizer, embedding, final norm, LM-head and generation metadata. The
model declares a 151936-token vocabulary and tied logical input/output
embeddings; runtime physical formats may differ but must retain source hashes.

## Gates

An independent Host implementation must reproduce the packed W4F16 final
RMSNorm, tiled LM-head and greedy selection. Untimed audit mode may emit full or
selected logits as an explicit output boundary. The first generated token and a
continuous 16-token sequence must match the independent implementation. Existing
per-layer hidden and KV-cache checks remain in force.

The W4F16 output must decode to stable, non-empty readable text for fixed
prompts known to be supported by the original model. Original BF16 teacher and
the known mllm W4A16 behavior are accuracy diagnostics; disagreement alone does
not override an exact implementation-reference pass, but unusable W4F16 text
stops before W4U8 integration and triggers diagnosis.

Formal execution requires exactly 8 MiB VTCM, one FastRPC invocation per
prefill or decode pass, no QNN, zero inter-layer hidden/logit DDR traffic, and
zero spill/fill. Legal DDR boundaries are persistent packed weights and cache,
input token IDs, the selected output token, and explicitly labelled untimed
logit-audit output. Full-logit materialization is forbidden in the timed greedy
path. Speed is reported with a complete profiling ledger but is not an
adoption gate for this correctness-first experiment.
