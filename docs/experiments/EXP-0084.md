# EXP-0084 — Cross-recipe common-schedule parity backports

## Decision and motivation

The user approved this experiment on 2026-08-30 after identifying that the
current F16F16, W4F16 and W4U8 headline comparison mixes quantization effects
with unequal optimization maturity. The existing table is useful as a
current-best engineering status, but it is not sufficient evidence for the
causal speed effect of one numerical recipe.

EXP-0084 pauses W4U8-only optimization and backports only scheduling ideas
whose physical meaning exists on the FP16 activation paths. It then measures
all three recipes from one source commit and one binary. Rejected W4U8
experiments are not inherited. EXP-0079 supplies the unchanged W4U8 control;
EXP-0038 supplies the selected W4F16 contract and the fastest valid paired
F16F16 control.

## Fixed physical and numerical contract

The Execution Unit is the real Qwen3-1.7B layer-14 complete block at M=64.
Every formal run uses one FastRPC invocation, exactly 8,388,608 acquired VTCM
bytes, one HMX owner, zero intermediate DDR, zero spill/fill and no QNN or
QAIRT path. Weight values, per-channel W4 scales, activation values, FP16
RMSNorm/RoPE/Softmax/SiLU mathematics, U8 qparams, integer Attention and all
tensor boundaries remain fixed unless the milestone explicitly changes only
the task topology used to produce the same bytes.

F16F16 and W4F16 receive the same candidate grid, sample count, selection
rule and repeat-one/repeat-ten gate. A shared optimization may be called
common only if it is byte-exact and non-regressing for both FP16 recipes.
Recipe-specific best plans may still differ after equal-budget tuning, but
that distinction must remain visible in the final report.

## Serial milestones

### Stage A — FP16 Q/K Norm-RoPE head pairs

Replace the current sixteen independent Q-head tasks plus eight independent
K-head tasks with eight Q-pair tasks plus four K-pair tasks. Reuse invariant
gamma, RoPE table and loop state while preserving the complete computation of
each head. Projection commands, Q/K readiness generations, GQA Attention,
standard stable FP16 Softmax and all HMX scheduling remain unchanged.

The gate requires byte-exact output and strict non-regression of Q/K-prep
work, the complete QKV ledger interval and Host wall for both F16F16 and
W4F16 at repeat one and repeat ten.

### Stage B — FP16 Input RMSNorm persistent-pool rows

Partition the existing FP16 Input RMSNorm into disjoint row tasks executed by
the already-created persistent HVX pool. Each row retains the existing
reduction order, reciprocal square root, gamma multiplication and selected
Crouton-native output contract. The bounded worker grid is identical for
F16F16 and W4F16.

The gate requires byte-exact output and non-regression of Input RMSNorm,
Input-Norm-plus-QKV and Host wall for both recipes at both repeat counts.

### Stage C — FP16 Post-residual plus RMSNorm persistent-pool rows

Apply the same row-task principle to the fused post-Attention residual and
RMSNorm boundary. Final residual remains unchanged because the current FP16
implementation is already materially faster than W4U8 and has no matching
optimization deficit.

The gate requires byte-exact output and non-regression of the complete
post-residual/norm-plus-Gate/Up boundary and Host wall for both FP16 recipes at
both repeat counts.

### Final synchronized comparison

Run F16F16, W4F16 and unchanged EXP-0079 W4U8 from one source commit and one
binary on one stable boot in interleaved order. Report both the common
canonical schedule and each recipe's best plan selected from equal search
budgets. PC-027 and PC-028 closure is mandatory. No result becomes a Selected
Baseline without explicit user promotion.
