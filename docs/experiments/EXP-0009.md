# EXP-0009 — Batch multiple down-projection HMX streams per ready boundary

## Approval

Approved by the user on 2026-08-27 under the continuing request to optimize the
standalone W4U8 implementation until it obtains an effective self-speedup.

## Objective

Close the remaining down-projection gap after EXP-0008 removed per-weight scale
multiplication. The down shape has K=6144, or 192 architectural K tiles. The
current 32-tile physical chunk crosses six expanded-ready semaphore, function,
overlap-metric, and consumer publication boundaries per output tile. The
Expanded-S8 control executes the same six 32-tile HMX streams inside one
consumer call. Formal EXP-0008 evidence attributes 64.6K HMX-compute ticks to
the chunked W4 path versus 18.5K to Expanded-S8 despite identical HMX execution
and stream counts.

The experiment groups two or three internal 32-tile HMX streams behind one
publication boundary by increasing the physical expansion chunk to 64 or 96 K
tiles. `qbh_hmx_accumulate_u8s8_projection` still emits the same 32-tile-deep
integer HMX streams internally. Only the number of producer/consumer handoffs
falls from six to three or two per output tile.

## Fixed contract

Only the down projection is tested: `M=64, K=6144, N=2048`. The EXP-0008
postscale arithmetic, asymmetric U8 zero point, signed W4 values, per-output
integer scales, HMX bias encoding, four compressed slots, eight expanded
slots, six HVX workers, User DMA, DDR boundaries, power vote, and output
saturation are unchanged. Expanded-S8 remains the observation control and the
32-tile postscale plan remains the parent control. No gate/up schedule or
quantization data changes are allowed.

The 64- and 96-tile buffers must fit within the existing 2 MiB VTCM request.
They may reduce task-level HVX exposure, so wall latency—not summed expansion
work—decides the result. HMX execution count and internal stream count must
remain identical across all variants.

## Gates

All four patterns must remain byte-exact with the independent Host reference,
with no resource error, fallback, hidden DDR intermediate, QNN dependency, or
device reboot. Static and runtime evidence must show raw-q4 HVX unpack,
post-accumulator HMX scaling, integer HMX, and the declared chunk count.

Formal timing uses repeat-10 Host wall latency in rotated order. The local gate
requires the fastest valid coarse-chunk candidate to beat the 32-tile
postscale parent. Beating Expanded-S8 is the explicit stretch target. HMX
compute ticks, ready wait, expanded-slot wait, and maximum active HVX workers
must be reported to explain whether batching saved more consumer overhead than
it lost in expansion parallelism.
