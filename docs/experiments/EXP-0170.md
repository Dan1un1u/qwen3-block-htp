# EXP-0170 — HVX-tiled W4U8 decode Softmax

## Decision and purpose

The user approved the highest-confidence optimization identified by EXP-0169:
replace only the M=1 dynamic U8 Softmax scalar scans with an HVX-tiled path.
EXP-0169 proved that 98.2% of the QK-Softmax-AV growth from L64-95 to L224-255
comes from dynamic Softmax, while cache traffic follows the expected segmented
ABI and QK/AV HMX costs remain small.

## Parent and direct control

The source parent is EXP-0169 commit
`f4722419596931035583e98e4b5a304b528d1cd2`, which contains the unchanged
selected EXP-0168 kernels plus the capacity-257 long-generation harness. The
direct control is the existing scalar
`qbh_attention_u8_requant_softmax_dynamic` path in the same binary. The
candidate is selected explicitly and may not silently replace the control.

## Allowed implementation

The candidate may change only M=1 W4U8 decode Softmax and its local VTCM
scratch, dispatch, telemetry and profiling. It should process one GQA group's
four query heads and one 32-token KV tile as a 128-byte HVX unit, vectorizing
maximum, log2-code/weight accumulation, LUT lookup and probability publication.
Probability must be published directly in the existing AV HMX activation
carrier. The current integer score requantization, log2 code, LUT construction,
rounding, probability values and mask behavior are immutable.

KV-cache contents and segmented-v4 ABI, cache DMA and seal lifecycle, QK and AV
integer HMX commands, projection/MLP/LM-head kernels, W4 values, scales, U8
qparams, prompt and feedback semantics are forbidden from changing. Prefill
continues to use its existing shuffle4 implementation. No QNN component may be
introduced.

## Gates and evidence

The functional gate requires byte-exact probability and final block outputs
against the scalar control across boundary lengths and the full 193-pass
generation/replay sequence, with exact selected tokens and U8 codes and zero
cache mismatch. The independent integer generation-head check remains required.

The physical gate remains exact 8 MiB VTCM, one FastRPC call per accelerator
pass, no QNN, zero timed inter-layer or full-logit DDR, zero spill/fill,
unchanged QK/AV HMX command and tile counts, synchronized cache lengths and zero
unattributed ticks.

Formal performance uses ten rotated scalar/candidate pairs, each containing one
M64 prefill and 192 continuous decode calls through L255. The primary gate is
strictly lower paired complete decode Host wall, equivalently higher directly
measured decode token/s. Prefill is a preservation diagnostic. Reports retain
all six 32-token buckets, additive ledgers, Softmax work, HMX/HVX/DMA/wait,
cache bytes, segment-seal events and complete physical evidence.

## Decision state

Approved by the user and completed on 2026-09-04. The timed DSP binaries were
built from runtime source commit
`23c00feaee20ccef30165d47ed03b5774c70e649`; report-only zero-row handling was
then fixed in source commit `042dbfd8907c23af255092a03ac28b13f8e740bc`.
Formal evidence is retained at
`D:/llm_exp/results/qwen3-block-htp/exp0170/20260904T_exp0170_23c00fe_formal`.
All correctness, physical, ledger, regression, stability and performance gates
pass. The user explicitly promoted this result on 2026-09-04. It is now the
Selected W4U8 token-generation and long-decode baseline under source tag
`baseline-w4u8-token-generation-exp0170`, superseding EXP-0168 for subsequent
W4U8 optimization.

Ten rotated pairs measure the scalar control at 60.025 ms/decode token or
16.660 token/s and the HVX-tiled candidate at 50.669 ms/token or 19.736 token/s.
The candidate reduces complete decode wall by 15.586%, increases direct decode
throughput by 18.464%, and wins all ten pairs. Prefill is unchanged within
noise: 1,294.944 versus 1,293.563 token/s.

The complete QK-Softmax-AV interval falls from 15.964 to 6.573 ms/token. The
dynamic Softmax telemetry itself falls from 9.878 to 0.545 ms, a 94.480%
reduction, while QK HMX, AV HMX, cache handling, projections, MLP and LM head
remain unchanged within noise. The implementation replaces three scalar score
scans with HVX quarter-tiled processing over two heads and two adjacent
32-token tiles, retains log2 codes in dead VTCM probability-carrier padding,
uses vector LUT lookup, and publishes probabilities directly in the AV HMX
carrier.

The benefit increases with cache length. Complete decode improves by 9.09% for
L64-95 and by 27.60% for L224-255. Scalar complete-wall growth is 62.673 us per
additional cache token, of which scalar Softmax contributes 60.591 us; the
candidate reduces those slopes to 4.042 and 1.992 us respectively. This proves
that EXP-0169's dominant long-cache slope was implementation structure rather
than an unavoidable KV-cache bandwidth cost.

The on-device audit compares candidate probabilities directly with the scalar
control for all 43,008 decode Softmax calls and reports zero byte mismatch. All
twenty timed sessions have identical per-step output hashes and token
sequences, all 193 independent integer-head checks pass, and the EXP-0163
transformer/cache regression passes. Every invocation retains exact 8 MiB
VTCM, one FastRPC call, no QNN, zero timed intermediate or full-logit DDR, zero
spill/fill, synchronized cache lengths and zero unattributed ticks. Semantic
quality remains disabled by contract and is not claimed.
