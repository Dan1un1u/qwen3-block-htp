# EXP-0162 — Full-stack dynamic segmented W4U8 KV-cache lifecycle

## Decision and purpose

The user promoted EXP-0161 as the Selected W4U8 Long-KV Segmented-Cache
Baseline and approved the next integration experiment on 2026-09-03.
EXP-0161 proves bounded-scratch segmented Attention only for independent
layer-14 snapshots whose sealed-segment count is fixed by each package. It does
not prove that one persistent cache can grow, seal a full 32-token tail, and be
consumed correctly across all 28 layers during continuous decode.

EXP-0162 integrates the segmented representation into the Selected Full-Stack
W4U8 runtime. One real M64 prefill is followed by forty continuous decode steps
at positions 64 through 103. This range exercises a full mutable tail, the
64-to-96-token segment-sealing transition, and reuse of the newly sealed
segment on later tokens.

## Execution and comparison boundary

The immutable source parent is EXP-0161 commit
`efea24712241dbcb62f468665b98c758c5ef5461`. The direct control is an
EXP-0160-compatible monolithic compact-base plus delta-journal cache rebuilt at
the same capacity and driven by the same inputs. The candidate uses immutable
32-token K/V segments, one mutable 32-token tail, dynamic sealed/tail counts,
and the EXP-0161 bounded-scratch Attention consumer in every layer.

The package extends the declared token stream and generates W4U8 inputs,
complete-stack outputs, per-layer K/V append references, and segment-carrier
references with an independent Host HMX/HVX simulator. Runtime K/V is never
imported. Both variants use the same W4 values, qparams, projection schedules,
integer QK/log2-Softmax/AV mathematics, one HMX owner, input sequence and
capacity.

## Gates

Before the full-stack run, a layer-14 boundary gate must cover tail lengths 1,
31 and 32 plus the first row after sealing. The candidate must match the
independent reference with zero U8 LSB error for every retained full-stack
output and every per-layer current K/V append. Sealed segments must remain
byte-stable after publication, each full tail must be sealed exactly once, and
only the active tail may change between seal events.

Formal execution requires exactly 8 MiB VTCM, zero intermediate DDR, zero
spill/fill, one FastRPC invocation per full-stack prefill/decode step, one HMX
owner and no QNN. Attention scratch must remain independent of total KV length;
the candidate may not reconstruct a full-prefix carrier.

The prefill Host wall may be at most 1.01 times the same-binary control. The
positions 64-71 early-decode window may not regress outside paired device
noise. The positions 96-103 post-seal window and the complete forty-token
decode average must be strictly faster than the same-capacity monolithic
control under ten rotated sessions. All complete profiling fields required by
PC-027 and the three-recipe overview required by PC-028 remain mandatory.

Any correctness, cache-lifecycle or physical-contract failure stops before
performance adoption. Passing does not change the Selected Full-Stack W4U8
Baseline without another explicit user decision.

## Implementation and formal result

The implementation extends the segmented V4 cache ABI from fixed snapshots to
one capacity-104 persistent cache per layer. Prefill publishes the first two
immutable segments. Decode derives the sealed-segment count and active-tail row
from `valid_length`, appends one K/V row per layer, seals row 31 into the next
reserved HMX-native slot, and consumes that slot on the following token. The
Host exact simulator generated all 41 complete-stack outputs and every physical
cache state without importing runtime cache data. The retained EXP-0152 prefix
and the old EXP-0161 L64/L256 snapshot paths remain byte exact.

The first correct device implementation exposed a 192.955 ms wall spike at the
position-95 seal. Its cause was not DMA or the segmented representation: the
seal path had accidentally called the scalar full-matrix K/V packers, consuming
about 143 ms for 28 layers. Reusing the bounded-tail Attention consumer's HVX
scatter/gather packers reduced the seal packing smoke measurement to about
5.5 ms while preserving every byte of the cache ABI and every output.

Ten complete order-rotated control/candidate session pairs then produced:

| Window | Equal-capacity delta control | Dynamic segmented V4 | Paired speed change |
|---|---:|---:|---:|
| M64 prefill | 43.605 ms | 43.596 ms | +0.323% |
| positions 64-71 | 48.693 ms/token | 48.285 ms/token | +0.740% |
| positions 72-94 | 50.298 ms/token | 50.290 ms/token | -0.540% |
| position 95 seal | 52.045 ms | 52.377 ms | -0.660% |
| positions 96-103 | 53.056 ms/token | 49.325 ms/token | +7.500% |
| all positions 64-103 | 50.521 ms/token | 49.715 ms/token | +1.261% |

All 41 outputs and all 28-layer cache lifecycle references are byte exact.
Every run uses exactly 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one
FastRPC invocation per full-stack step and no QNN. Each decode step appends once
per layer; exactly 28 segment seals occur at position 95; no full-prefix pack is
observed; the new segment remains immutable and is consumed correctly from
position 96 onward. The complete additive ledger, overlapping work counters,
three-recipe overview and evidence hashes are retained in
`D:/llm_exp/results/qwen3-block-htp/exp0162/20260903T045521Z_a3b9607dee88_formal`.
