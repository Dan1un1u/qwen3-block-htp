# EXP-0008 — Apply W4 per-channel scale in HMX accumulator conversion

## Approval

Approved by the user on 2026-08-27 as the next optimization of the standalone
Packed-W4 path. The requested outcome remains an effective self-speedup rather
than parity with Qualcomm QNN.

## Objective

Remove per-weight scale multiplication from the HVX W4 expansion kernel. The
EXP-0007 path expands each signed nibble `q4[k,n]` and immediately computes
`q4[k,n] * scale[n]`, which performs scale work over K-by-N elements. Because
the scale is constant for each output channel, the equivalent formulation is:

`sum_k (u8[k] - zp) * (q4[k,n] * scale[n])`

`= scale[n] * (sum_k (u8[k] - zp) * q4[k,n])`.

The candidate therefore expands W4 only to its signed S8 q4 carrier, accumulates
U8-by-S8 on integer HMX, applies the activation-zero-point correction in the
unscaled accumulator domain, and encodes the per-output scale in the HMX bias /
convert state. This changes scale work from the K-by-N expansion domain to the
M-by-N output-conversion domain and leaves stored packed-W4 bytes unchanged.

## Fixed contract

Gate/up remains `M=64, K=2048, N=6144`; down remains
`M=64, K=6144, N=2048`. Activations are asymmetric U8 with zero point 128,
weights are signed symmetric W4 in `[-7, 7]`, and the synthetic exact scales
remain positive integers in `[1, 18]`. The selected EXP-0007 physical plan is
fixed at four compressed slots, 32 K tiles per chunk, eight expanded chunk
slots, and six HVX workers. DDR boundaries, FastRPC scope, User DMA, VTCM
layout, HMX instruction family, output U8 saturation, clocks, and performance
vote are unchanged.

The Expanded-S8 observation control and the EXP-0007 HVX-prescaled Packed-W4
path are retained. The only candidate change is whether q4 scale is applied in
HVX before HMX or once per output channel by the HMX conversion state after
accumulation.

## Gates

Before model-shaped timing, a conversion micro-gate must demonstrate the HMX
scale encoding for every integer scale used by the four inherited patterns.
For both real projection shapes and all patterns, the HMX-postscale candidate
must be byte-exact with the independent Host reference, the Expanded-S8
control, and the HVX-prescale control. Resource errors, worker fallback, hidden
DDR intermediates, graph/QNN dependencies, or device reboot invalidate the
evidence.

Performance uses repeat-10 Host wall latency in rotated order. The local gate
requires HMX-postscale to improve over HVX-prescale for both gate/up and down.
Beating Expanded-S8 for both shapes is the explicit stretch target and is
reported independently. Stage timing must verify that any wall improvement is
consistent with reduced HVX expansion work rather than a clock or lifecycle
artifact.

## Result

Completed with valid evidence but failed the two-shape local performance gate.
The formal matrix contains 96 records: 24 correctness runs and 72 rotated
repeat-10 timing runs. All outputs are byte-exact with the independent Host
reference and with both controls for all patterns and both Qwen3 shapes. The
scale sweep covers integer scales 1 through 18. There was no fallback, reboot,
DMA/synchronization error, QNN dependency, or failed power vote.

The HMX-postscale carrier is the raw signed q4 value rather than q4 multiplied
by the per-output scale. Static disassembly confirms that its HVX unpack kernel
contains the nibble LUT and shuffle but no per-weight vector multiply or
saturating pack. HMX bias conversion applies `FP16(512 * scale)` and the
activation-zero-point correction in the unscaled accumulator domain. This
reduced summed expansion work by 53.13% for gate/up and 49.27% for down.

For gate/up, Host wall medians were 9.486 ms for Expanded-S8, 9.185 ms for the
EXP-0007 HVX-prescale control, and 9.288 ms for HMX-postscale. Postscale still
beat Expanded-S8 by 2.09%, but regressed 1.12% from the prescale parent because
its HMX-ready wait increased from 10.6K to 13.4K ticks. For down, medians were
7.566 ms for Expanded-S8, 8.579 ms for prescale, and 8.437 ms for postscale.
Postscale improved its parent by 1.66% but remained 11.51% slower than
Expanded-S8.

The remaining down gap is no longer per-weight scaling. Both paths execute the
same 384 HMX streams per repeat, but the 32-tile Packed-W4 schedule crosses six
consumer function/semaphore boundaries per output tile. Its HMX-compute median
is 64.6K ticks versus 18.5K for the Expanded-S8 path, which issues all six
streams inside one consumer call. A follow-up experiment should batch multiple
32-tile streams behind each ready signal while retaining the postscale
arithmetic. EXP-0008 remains unadopted pending user decision.
