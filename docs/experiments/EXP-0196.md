# EXP-0196 — Direct-n decode LM-head batch-thirty-two

## Decision and purpose

EXP-0195 is the fastest evidence-valid W4U8 decode candidate at 39.102150
token/s.  Its transformer projections already feed packed W4 directly to HMX,
but the decode LM head still expands every W4 tile to S8 in VTCM before integer
HMX.  The LM-head boundary costs about 4.15 ms/token and is the largest remaining
standalone non-transformer stage.  EXP-0196 tests whether direct packed-W4
`weight.n` with batch thirty-two removes that expansion and raises complete
decode throughput beyond the current candidate, ideally across 40 token/s.

The old EXP-0188 diagnostic used direct-n groups of only four tiles and was
slower than Expanded-S8 batch sixteen.  That result did not test the current
one-MiB phase-overlay slots or a competitive command granularity.  EXP-0196 is
therefore a new physical hypothesis rather than a repeat of the old schedule.

## Bounded implementation

One binary compares the unchanged EXP-0195 LM-head Expanded-S8 batch-sixteen
control with a decode-only direct-n batch-thirty-two candidate.  Candidate W4
groups use the two phase-dead one-MiB Expanded-S8 buffers; HMX output and argmax
scratch use dead transformer activation storage.  The resident per-token bias
table, ascending vocabulary traversal, first-index tie rule, quantization,
weights and full transformer path are unchanged.  M64 prefill must remain on
the EXP-0195 Expanded-S8 path.

Correctness requires byte-exact LM-head U8 codes where audited, selected token,
all hidden hashes and cache state.  The physical gate requires exact 8 MiB VTCM,
zero timed intermediate DDR, zero spill/fill, one FastRPC, one HMX owner, no
QNN, unchanged weight bytes and HMX tile pairs, and zero decode LM-head W4-to-S8
expansion.  A five-pair short gate must improve complete decode token/s and LM
head wall before ten formal rotated 193-step pairs.

## Decision state

Approved as part of the user's continuous decode optimization loop on
2026-09-05 and completed on the same day.  The first source revision was
rejected before execution by a stale capacity guard that described the old
activation overlay rather than the candidate's expanded-weight overlay.  The
guard was split by actual arena ownership and all retained evidence uses the
corrected implementation.

Five short and ten formal rotated 193-step pairs all passed.  Formal median
decode improves from 39.170758 to 41.403837 token/s (+5.700882%), while the
LM-head wall falls from 4.1419 to 2.7520 ms/token.  The candidate removes
3.0533 ms/token of explicit expansion, reduces LM-head commands from 297 to
149 and total weight-DMA descriptors from 4554 to 4406.  Weight bytes remain
866032640 and HMX tile pairs remain 1699840 per token.  All token IDs, selected
U8 codes, output hashes, audited hidden tensors and cache state are exact;
8 MiB VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC, one HMX
owner and no-QNN gates pass.
