# EXP-0063 — Fuse QK requantization into Softmax row loading

## Parent and scope

EXP-0062 is the direct source control. Preserve its QKV path, shared RoPE
cache, HMX QK and AV arithmetic, log2 Softmax approximation, qparams, mask,
probability encoding, residual equations, and MLP. Change only the physical
boundary between QK output requantization and the existing Softmax.

## Hypothesis

Each GQA group currently performs a complete in-place U8 requantization pass
over the 8 KiB QK score carrier, executes a barrier, and then reads the same
carrier row by row in Softmax. Applying the exact same HVX requantization to
the row immediately after Softmax loads it can remove the separate carrier
read and barrier. In performance mode the transient requanted score need not
be written back; numerical-audit mode must write every row back so the QK
boundary hash remains authoritative.

## Candidate and gates

Control and candidate must be selectable in one binary. Saturation telemetry,
causal masking, log2 codes, LUT division, probability bytes, AV input, and
final output must remain identical. Final output and QK/probability/AV audit
boundaries must be byte-exact to EXP-0062 and the independent reference.
Exactly 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one FastRPC
execution unit, one HMX owner, and no QNN are mandatory.

At repeat one and repeat ten, the combined QK-requant plus Softmax work,
Attention ledger, and complete Host wall must strictly improve in both
ordinary and paired medians. Seven interleaved paired rounds and PC-027/PC-028
complete profiling closure are required.

## Implementation refinement

The first row-fused implementation was slower because one 64-byte Softmax row
occupied only half of a 128-byte HVX vector. It therefore executed 1,024
half-full requant operations per block where the separate carrier pass needed
512 full-width operations. It also increased the candidate function's stack
frame. The final candidate packs the corresponding rows from both Q heads of
one GQA group into one 128-byte vector, applies the exact requantization once,
then computes independent maxima, denominators, LUTs, masks, and probability
sums for the two 64-byte halves. Performance mode does not write the converted
score back; audit mode writes both halves to their original physical score
tiles so the QK boundary hash remains authoritative.

## Result

Formal source head `9c7bd641ed8b671972f5a4d6e085d2112bd6a618`
passed seven interleaved paired rounds. Final output, QK, probability, and AV
hashes were byte-exact to the control, with zero mismatches and zero maximum
LSB error. Requested and acquired VTCM were exactly 8 MiB; intermediate DDR,
spill/fill, and QNN dependencies remained zero; one FastRPC Execution Unit and
one HMX owner were preserved.

At repeat one, combined QK-requant plus Softmax work fell 7.912%, the Attention
ledger fell 5.481%, and complete Host wall fell 1.587%; paired medians improved
7.821%, 5.607%, and 0.352%. At repeat ten, the corresponding ordinary gains
were 8.869%, 4.319%, and 0.523%, with paired gains of 8.726%, 4.381%, and
0.611%. Every local gate passed. The experiment is an adoption-eligible W4U8
candidate, but the Selected Baseline remains unchanged pending explicit user
promotion.
