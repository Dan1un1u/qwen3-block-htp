# EXP-0122 — W4U8 ring16 Gate/Up eight-bundle DMA chain

## Decision and scope

The user authorized a continuing W4F16/W4U8 recipe-specialization loop and
routine autonomous recovery. EXP-0122 branches from the locally passing
EXP-0120 ring16/worker3 candidate. It changes only the number of adjacent
Gate/Up weight bundles submitted in one linked DMA chain.

## Evidence and hypothesis

EXP-0120 provides sixteen compressed slots and consumes eight output tiles per
HMX command, but the producer still submits linked DMA in groups of four. Each
HMX command therefore requires two chain submissions and two groups of
descriptor completion/publication bookkeeping. EXP-0121 shows that adding HVX
concurrency is counterproductive. The new hypothesis is that one eight-bundle
chain can match the HMX command boundary, reduce producer control overhead and
improve readiness without changing decoder density or HVX/HMX contention.

## Gates

Control and candidate are runtime selectable from one binary. Both use ring16,
three persistent workers, batch-eight HMX, the original decoder and the
EXP-0112 single-fence path. Control preserves four descriptors per linked
chain; candidate uses eight. Weight bytes and descriptor count remain equal;
only DMA chain submission, wait and publication grouping may change.

Final output and existing stage audits must remain byte-exact. Exact 8 MiB
VTCM, zero intermediate DDR and spill/fill, one FastRPC unit, one HMX owner,
unchanged weights, descriptor count, HMX commands, tile pairs and peak VTCM are
hard gates. The candidate is eligible only if Gate/Up and complete Host wall
strictly improve in ordinary and paired repeat-one and repeat-ten medians over
five rotated rounds. PC-027 and PC-028 are mandatory. Only the user may promote
an eligible candidate.
