# EXP-0131 — W4U8 QKV post-DMA HMX-tail main-context Q/K preparation

## Decision and hypothesis

This bounded W4U8 specialization continues from EXP-0124's ring3 QKV path.
EXP-0130 proved that even one complete Q/K Norm+RoPE pair is longer than a V
weight-DMA flight window: doing that work in the producer loop delays DMA
completion publication and starves the ordered HMX consumer.

EXP-0131 moves the same existing pair kernel beyond the producer loop. Only
after all Q/K/V DMA submissions and publications are complete may the main HVX
context drain remaining Q/K preparation tasks while the independent HMX owner
finishes the V-projection tail. The hypothesis is that this otherwise idle
main-context interval can shorten the preparation-pool join without moving any
weight-readiness or HMX dependency boundary.

## Gates

The candidate must preserve ring depth, three expansion workers, two ordinary
Q/K preparation workers, one HMX owner, all DMA order and commands, projection
math, Q/K Norm+RoPE math and every later block stage. The main context uses the
existing pair kernel with its own scratch slot, and it may start only after the
last QKV DMA publication.

Both cells must be byte-exact to EXP-0124 and the independent audits, request
exactly 8 MiB VTCM, retain zero intermediate DDR/spill, one FastRPC Execution
Unit, one HMX owner, no QNN, and identical weight bytes, DMA descriptors, HMX
commands, tile pairs, qparams and peak plan. The candidate passes only if the
combined QKV plus Q/K Norm+RoPE interval and complete Host wall strictly
improve in ordinary and paired repeat-one and repeat-ten medians. Formal closure
requires PC-027 and PC-028. Only the user may promote a Selected Baseline.

## Result

Formal evidence is archived at
`D:/llm_exp/results/qwen3-block-htp/exp0131/20260901T011921Z_9b74c81651b9_formal`.
The physical contract passes: exact 8 MiB VTCM, zero intermediate DDR/spill,
one FastRPC unit, one HMX owner, and unchanged weight traffic, DMA commands,
HMX work, qparams and peak plan.

The candidate consistently takes two pair tasks per block. Allowing a third
Q/K pair context without synchronization corrupts the K carrier. Serializing
the K-scatter section restores zero fused-K mismatch, but the score,
probability and AV boundary hashes still differ from control, so the strict
correctness gate fails even though the final saturated block output happens to
remain byte-identical.

Serialization also destroys the intended overlap. Repeat-one QKV rises 82.09%
and Host wall rises 13.77%; repeat-ten QKV rises 79.48% and Host wall rises
18.23%. Pool-tail wait rises 29.76% at repeat ten, while HMX-ready wait changes
only -1.94%. The extra context therefore creates a non-reentrant Q/K execution
boundary and then pays a larger serialization cost than the work it removes
from the two-worker join.

EXP-0131 is rejected and EXP-0124 ring3 remains the W4U8 control. Reopen only
with a proven reentrant three-context Q/K kernel, or a partition that never
adds concurrent K scatter. No baseline is promoted.
