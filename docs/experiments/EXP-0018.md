# EXP-0018 — Interference-aware phased W4 pipeline

## Approval

Approved on 2026-08-27 by the user's continuing instruction to optimize the
standalone W4 implementation until it produces effective acceleration over the
project's own Expanded-S8 control.

## Objective

Recover the HMX throughput lost when raw-W4 HVX expansion runs concurrently
with integer HMX. EXP-0017 shows that paired gate/up at repeat ten spends about
80.0K aggregate ticks in HMX versus 37.4K for Expanded-S8, while the six HVX
workers perform about 189.1K aggregate expansion ticks. The current fine-grain
overlap hides expansion work but appears to more than double the observed HMX
section.

The candidate uses an Interference-Aware Phase Pipeline. Four output tiles are
staged as one group. Four HVX workers expand the complete group and reach a
barrier before HMX begins. While HMX consumes the ready group, linked User DMA
prefetches the next four packed bundles into the other half of an eight-slot
compressed ring. HVX and HMX therefore do not overlap, but DDR DMA remains
overlapped with the compute phase.

## Fixed contract

The paired gate/up shape remains `M=64, K=2048, N=12288`, and down remains
`M=64, K=6144, N=2048`. Both use asymmetric U8 activation with zero point 128,
signed W4 in `[-7,7]`, the EXP-0017 exact per-output integer scales, HMX
postscale, integer HMX, linked 2-D final-output DMA, a Prepared Runtime Session,
one FastRPC invocation, and exactly 2 MiB VTCM. The candidate changes only the
dependency order and VTCM ring balance: eight compressed slots, four expanded
slots, four HVX workers, linked-chain-four DMA, and one full-K publication per
output tile.

The current EXP-0017 six-worker fine-grain schedule and the shape-matched
Expanded-S8 control remain comparators. Stored weights, logical carrier,
activation, output, HMX tile/stream counts, repeat semantics, clocks, cache
scope, and legal DDR boundaries do not change. No expanded S8 weight may leave
VTCM.

## Gates

All inherited patterns must be byte-exact with the independent Host reference
and mutually identical across schedules. There may be no worker fallback,
descriptor timeout, resource, power, DMA, synchronization, backend, cache, or
device-reboot failure. Static evidence must identify raw-nibble HVX expansion,
integer HMX, a four-tile HVX completion barrier, linked next-group prefetch, and
the absence of a QNN/QAIRT dependency.

Formal selection uses rotated repeat-one and repeat-ten Host-wall medians. The
local performance gate requires the phased candidate to beat the current W4
schedule at repeat ten for both paired gate/up and down. HMX compute, weight
expansion, ready wait, phase wait, DMA time, and pipeline time explain the
result; Host wall decides it. W4 versus Expanded-S8 is reported in both
directions, including the `S8/W4 - 1` convention used in the earlier LPBQ
discussion. Only the user may adopt the result or promote a Selected Baseline.

## Result

Stopped at the diagnostic-stall hard gate on 2026-08-27. No formal matrix was
started, so evidence validity is `invalid` for project adoption and the local
gate fails.

The paired gate/up implementation did prove the intended physical contract in
two diagnostic runs. It was byte-exact, used four locked HVX workers, observed
HVX-to-HVX parallelism, reported `hvx_hmx_overlap_observed=0`, retained the
2 MiB VTCM allocation, and had no DMA, descriptor, resource, or backend error.
Separating the engines reduced repeat-ten HMX issue attribution from the
EXP-0017 median of 79.97K ticks to 14.14K ticks. That isolated improvement did
not reduce latency: four-tile barriers exposed 139.45K HMX-ready-wait ticks and
69.61K expanded-slot-wait ticks, increasing the pipeline from 98.79K to
159.68K ticks. The observed Host wall was 9.295 ms versus the 6.129 ms parent
median, a 51.66% regression.

The first attempt to extend the phase plan to down used two 96-K-tile chunks
per output because four complete 192-tile expanded weights cannot coexist with
the declared buffers in 2 MiB VTCM. That uncommitted diagnostic extension
stalled inside FastRPC. In accordance with the inherited hard gate, PID 14753
was not killed, no automatic retry or reboot was performed, and device boot ID
`283cc037-8da2-4e83-bf6f-05429beb7d90` remained connected at inspection time.

The retained source commit is the safe form of the experiment: it supports the
byte-exact paired gate/up probe and rejects the risky down two-chunk phase plan
before FastRPC. It is pushed at
`f428e2ca7de0b181077fa7ff38e85950760206ee`. Diagnostic facts, not a formal
result set, are retained at
`D:\llm_exp\results\qwen3-block-htp\exp0018\20260827T090902Z_f428e2c_inspection\inspection_summary.json`.

The result rejects strict HVX/HMX phase separation as a performance direction:
the current fine-grain overlap is imperfect, but replacing its interference
with a barrier makes the exposed expansion/synchronization path still worse.
Project adoption remains pending and only the user may change it. A manual
device restart is required before any new true-device experiment.

## Adoption decision

Rejected by the user on 2026-08-27. Strict HMX/HVX phase separation is not the
supported optimization direction. The diagnostic remains useful evidence that
concurrent HVX work can inflate HMX attribution, but replacing fine-grain
overlap with a whole-group barrier exposed still larger ready and slot waits.
Future work must preserve producer-consumer overlap: once HVX completes a
consumable partial weight region it must publish that region directly to HMX,
without waiting for all weights in the group or projection to finish.
