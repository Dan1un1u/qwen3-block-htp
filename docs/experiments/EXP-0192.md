# EXP-0192 — Direct-n decode Down batch-four

## Decision and purpose

The user authorized a continuous decode optimization loop.  EXP-0191 is the
evidence-valid fastest candidate at commit
`0cdd367f89475c73de4695bab9e9348dbd955aeb`; it reaches 37.739069 token/s by
using batch-sixteen direct-n Gate/Up commands.

EXP-0192 tests the same command-granularity hypothesis on Down projection.
The current direct-n Down path issues two output tiles per HMX command.  The
existing compressed-weight double buffer has enough capacity for four Down
tiles, so the candidate raises only Down from batch two to batch four without
adding VTCM or changing any weight, scale, qparam, arithmetic or other module.
The expected Down command count is 896 to 448 per token.

## Gates

One binary compares Down batch two and batch four.  Gate/Up remains batch
sixteen and all EXP-0191 non-Down modules remain unchanged.  Correctness
requires byte-exact hidden hashes, selected tokens and cache state.  Physical
gates remain exactly 8 MiB VTCM, zero timed intermediate DDR, zero spill/fill,
one FastRPC, one HMX owner, no QNN, unchanged weight bytes and zero Transformer
W4-to-S8 expansion.  Five rotated short pairs must improve direct complete
decode token/s and Down wall before ten formal pairs are allowed.
