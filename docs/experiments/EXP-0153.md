# EXP-0153 — Exact full-stack profiling closure

## Decision and purpose

The user stopped report preparation on 2026-09-02 because the EXP-0152 PC-028
table placed 22.7% to 55.1% of prefill Host wall in a combined `Host/RPC and
profiling closure remainder`. That bucket is too large to support module-level
interpretation. Read-only audit proved that actual Host minus DSP invocation is
only about 0.6 to 2.3 ms. The large remainder is DSP-resident work hidden by the
reporting schema.

EXP-0153 is an instrumentation-only child of EXP-0152 commit
`f64104da172510753be67056967e80770b181e76`. It must make that work explicit
before the project report uses the three-recipe module table.

## Initial diagnosis

`stage_boundary_ticks` is currently defined as the invocation time left after
subtracting the named stages, then included in `ledger_named_ticks`. The PC-028
module list omits this field and subtracts only its reduced module list from
Host wall, incorrectly labelling the result as Host/RPC closure.

For M64 prefill, the existing evidence reports stage-boundary time of about
27.091 ms for F16F16, 64.345 ms for W4F16 and 9.884 ms for W4U8. Cache-write DMA
accounts for only 0.565, 0.595 and 0.330 ms. Source audit locates the dominant
unmeasured interval between Q/K Norm-RoPE and Attention: K/V projection carriers
are unpacked or gathered into the persistent row-major cache before DMA. The
cost is strongly M-dependent and nearly uniform across all 28 layers, while the
same residual is small for M1 decode.

## Fixed implementation boundary

The experiment may add protocol fields, DSP timestamp intervals, Host JSON
publication, validation and report code. It may not change a kernel, recipe,
schedule, tensor layout, persistent-cache ABI, model package, execution scope or
selected baseline.

The explicit additive hierarchy must separate cache carrier conversion, cache
DMA, per-layer bookkeeping, runtime setup/teardown and true Host-minus-DSP
invocation time. Both complete DSP invocation and every per-layer ledger must
close within 0.1 percent for every recipe in prefill and continuous decode.
PC-028 must not retain a mixed Host/RPC-and-profiling remainder.

Correctness and physical gates are inherited unchanged from EXP-0152. Formal
closure requires ten rotated three-recipe rounds and a complete corrected
PC-027/PC-028 report. There is no speed gate and no baseline-promotion
authority.

## Result

EXP-0153 completed on 2026-09-02 at source commit
`21ea7dac13f6da7da3c22bb262fe5a7044ee96e9`. The implementation adds timing
and reporting fields only; model packages, kernels, recipe math, schedules,
tensor layouts, persistent-cache ABI and the 28-layer execution scope remain
those of EXP-0152.

Ten rotated three-recipe rounds passed the mapping, correctness, physical and
profiling gates. Across 270 replay records, the maximum DSP-invocation residual
was 0.0141 percent, the maximum per-layer residual was 0.0479 percent, and the
complete invocation ledger had zero unattributed ticks. These values satisfy
the fixed 0.1 percent limit without weakening the gate.

The old combined `Host/RPC and profiling closure remainder` was not Host/RPC
overhead. The corrected M64 prefill decomposition is:

| Metric | F16F16 | W4F16 | W4U8 |
|---|---:|---:|---:|
| Complete Host wall | 94,715.3 us | 118,135.2 us | 53,722.5 us |
| KV-cache carrier conversion | 26,494.2 us | 63,715.7 us | 9,489.0 us |
| KV-cache append DMA | 566.7 us | 588.0 us | 326.5 us |
| Block internal orchestration | 12.2 us | 13.8 us | 47.0 us |
| Layer bookkeeping | 16.8 us | 16.9 us | 16.2 us |
| DSP unattributed residual | 6.1 us | 6.5 us | 6.8 us |
| True Host-DSP boundary | 2,236.0 us | 557.2 us | 2,393.6 us |

The hidden interval is the DSP-side conversion of Q/K/V projection carriers
into the persistent row-major K/V-cache representation before the separately
timed append DMA. It is M-dependent and repeated across all 28 layers. W4F16
prefill spends 53.9 percent of Host wall in this conversion alone; therefore
the corrected evidence changes the optimization interpretation even though it
does not change any measured end-to-end speed.
