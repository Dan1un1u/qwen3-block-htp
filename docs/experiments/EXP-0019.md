# EXP-0019 — Streaming partial HVX expansion into HMX

## Approval

Approved by the user on 2026-08-27. The user explicitly rejected the
EXP-0018 strict phase-separation architecture and required a true pipeline:
HVX must hand a consumable partial result directly to HMX rather than waiting
for all expansion to complete before starting the next engine.

## Objective

Reduce time-to-first-HMX without restoring the high synchronization and
function-boundary cost of the early 32-K-tile schedule. EXP-0017 coalesces
gate/up into one 64-K-tile publication and down into two 96-K-tile
publications. That lowers publication overhead, but HMX cannot begin a
publication until HVX expands the complete region. EXP-0006 showed that a
32-K-tile region is already sufficient for one integer-HMX stream, while
EXP-0009 and EXP-0010 showed that returning through a semaphore and consumer
function for every region is too expensive.

The candidate keeps each current 64- or 96-K-tile expanded VTCM slot, but
publishes ordered 32-K-tile readiness generations inside it. A persistent HMX
consumer enters once per parent superchunk, waits only for the next required
generation, issues that HMX stream immediately, and continues inside the same
consumer call. The expanded slot is recycled only after all of its internal
streams have been consumed. There is no whole-group HVX barrier.

## Fixed contract

The numerical contract is inherited byte-for-byte from EXP-0017: asymmetric
U8 activation with zero point 128, signed W4 in `[-7, 7]`, the same exact
per-output integer scales, raw-nibble HVX unpack, HMX postscale, integer HMX,
and byte-exact Host reference. Paired gate/up remains
`M=64, K=2048, N=12288`; down remains `M=64, K=6144, N=2048`. Both retain one
prepared FastRPC invocation, exactly 2 MiB VTCM, linked 2-D output DMA, the
same legal DDR boundaries, weights, activations, output ordering, repeat
semantics, clocks, and resource lifetime.

Gate/up retains the parent eight-compressed/seven-expanded, 64-K-tile,
linked-chain-four allocation. Each expanded slot exposes two ordered 32-tile
regions. Down retains the parent four-compressed/eight-expanded, 96-K-tile,
contiguous-batch-two allocation. Each superchunk exposes three ordered
32-tile regions, and the two superchunks of an output preserve accumulator
order. DMA still moves complete stored-W4 bundles; only the in-VTCM expansion
and HMX publication order changes.

## Scheduling candidates

The EXP-0017 coarse-publication plan and shape-matched Expanded-S8 path remain
controls. The streaming implementation is searched with exactly 2, 3, 4, and
6 locked HVX workers. A derived interference-aware candidate locks all six
workers for startup, allows them to build the first consumable lead, and after
HMX observes its first ready region limits newly admitted HVX expansion to two
simultaneous workers. Already-running regions are not preempted. This creates
no phase or group barrier: HMX begins on the first region and both engines
continue concurrently under a steady-state producer credit.

Every worker writes a disjoint VTCM region. Readiness is generation-tagged so
a recycled slot cannot expose stale state. The producer
may stage current and future compressed bundles, but expanded work is bounded
by the unchanged slot ring; no full projection or group may be expanded before
HMX begins. A bounded readiness timeout is mandatory so a failed publication
returns an error instead of hanging inside FastRPC.

## Gates

Bring-up first runs one identity-pattern repeat for paired gate/up and down.
Both must complete without timeout, reboot, fallback, DMA, resource, or
synchronization failure before the remaining matrix is allowed. All inherited
patterns must be byte-exact with the independent Host reference and mutually
identical across the coarse and streaming W4 schedules. Static evidence must
identify raw W4 nibble unpack, generation-tagged partial publication, a
persistent ordered HMX consumer, integer HMX, and no QNN/QAIRT dependency.

Formal selection is per projection family. Rotated repeat-one and repeat-ten
Host-wall medians decide; HMX compute, first-ready latency, ready wait,
expansion, producer wait, slot wait, active-worker count, and overlap explain
the result. The fastest valid streaming candidate must beat the EXP-0017 W4
parent for a shape to replace that shape's plan; otherwise the parent remains
selected. The experiment-level local gate passes only if at least one family
improves without changing arithmetic, while both families and the W4 versus
Expanded-S8 comparison are reported. Work cycles alone never establish a
speedup. Only the user may adopt the result or promote a Selected Baseline.

## Result

Completed on 2026-08-27 with 616 formal device records: 56 correctness
records, 280 rotated repeat-one timing records, and 280 rotated repeat-ten
timing records. All seven physical plans, both real projection shapes, and all
four inherited input patterns were byte-exact with the independent Host
reference and mutually identical. All 32-tile readiness generations were
published and consumed without timeout. The boot ID and prepared HMX/VTCM
resource identity remained stable, and there was no worker fallback, DMA,
resource, synchronization, QNN, or backend failure.

The streaming hypothesis passes for paired gate/up. The two-worker plan is the
only stable winner: repeat-one Host wall fell from 1.263 ms for the EXP-0017
coarse-publication parent to 1.214 ms, an improvement of 3.86%; repeat-ten fell
from 6.075 ms to 5.021 ms, an improvement of 17.36%. Against the shape-matched
Expanded-S8 control, the selected packed-W4 stream is 26.16% faster at repeat
one and 36.02% faster at repeat ten.

This is a true producer-consumer pipeline, not EXP-0018 phase separation. Each
64-tile resident gate/up superchunk exposes two ordered 32-tile generations.
HMX enters one persistent consumer for the superchunk, starts on the first
generation, and accumulates the second as soon as it is published; HVX and HMX
overlap is observed in every W4 record. The parent performs the same integer
HMX work and moves the same stored weight and output bytes.

The counters show why two producers win. At repeat ten, pipeline time falls
from 100.1K to 81.9K qtimer ticks. Aggregate HMX compute attribution falls from
77.9K to 11.1K ticks and aggregate HVX expansion attribution falls from 191.8K
to 138.7K ticks, even though the number of 32-tile publications doubles. HMX
ready wait rises from 18.9K to 62.0K ticks because HMX now drains each region
faster than two HVX workers can produce it, but the reduced engine interference
more than repays that wait. Three, four, and six active HVX workers make both
engines slower. The six-worker startup/steady-cap candidate is also slow:
workers waiting in admission backoff still consume scheduling resources, so a
logical cap is not equivalent to creating only two workers.

Down does not pass the streaming selection gate. Its EXP-0017 96-tile parent
remains fastest at 0.766 ms repeat one and 2.544 ms repeat ten. The fastest
streaming candidates regress by 0.95% and 10.98%, respectively. For this
shape, the parent already amortizes one publication across three HMX streams;
splitting it into 32-tile generations lowers HMX compute attribution but turns
the critical path into repeated producer-ready waits. The selected operational
plans are therefore heterogeneous: two-worker 32-tile streaming for paired
gate/up, and the inherited 96-tile coarse publication for down.
