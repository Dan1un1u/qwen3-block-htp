# EXP-0005 — Qwen3 W4U8 per-channel projection substrate

## Approval

Approved by the user on 2026-08-27 by requesting the next implementation step
after EXP-0004 passed its real-shape projection gate.

## Objective

Extend both Qwen3 middle-block projection shapes from an S8 DDR weight carrier
to the canonical W4U8 project variant without QNN. The experiment must prove
that project-owned User DMA and HVX can move packed signed W4 weights into
VTCM, expand them into the exact S8 carrier consumed by integer HMX, apply one
scale per output channel, and preserve the exact EXP-0004 projection result.

## Fixed arithmetic scope

The shapes remain `M=64, K=2048, N=6144` for gate/up and
`M=64, K=6144, N=2048` for down. Activations remain asymmetric U8 with zero
point 128. Canonical W4 values are signed symmetric integers in `[-7, 7]`.
Each output channel has one positive integer expansion scale selected so that
`W4 value * scale` fits exactly in S8. This exactly representable subset is the
first per-channel-scale substrate; arbitrary real scales and output requant
are outside this experiment.

Two storage variants use byte-identical W4 values and channel scales:

- `expanded_s8_control` stores the already expanded `W4 * scale` S8 carrier at
  the Native DDR Boundary.
- `packed_w4u8` stores two signed W4 nibbles per byte and expands them with HVX
  inside VTCM before HMX consumption.

The HMX input bytes and asymmetric-zero-point correction must be identical
between the two variants. The authoritative Host reference is
`clamp(sum_k((activation - 128) * w4 * channel_scale), 0, 255)`. Both variants
must match it byte-for-byte and must match each other.

## Physical-plan scope

Both variants request the same 2 MiB project-owned VTCM allocation and use the
same activation, two expanded-weight slots, tiled output, and HMX schedule.
The W4 path additionally reserves two compressed slots. Each compressed bundle
contains packed W4 values, 32 canonical channel scales, and the precomputed
zero-point correction. A producer stages a compressed bundle with User DMA,
expands it with explicit HVX nibble lookup and signed byte scaling into the
corresponding S8 slot, executes a DMA Publication Barrier, and publishes the
slot to the HMX consumer. The two slots permit expansion of one bundle to
overlap HMX consumption of the other.

The complete activation and tiled output remain VTCM-resident. Legal DDR
boundaries are activation, stored weight bundles, final output, and compact
timing/status metadata only. The experiment records stored weight bytes,
expanded bytes, DMA, expansion, HMX, wait, pipeline, and Host wall timing.

## Hard gate

Both storage variants and both shapes must build for V79 with identifiable
User DMA, HVX W4 unpack/scale, and integer-HMX instructions and no QNN/QAIRT
dependency. Identity-like, signed, structured, and W4-boundary patterns at
repeat counts 1 and 10 must return exact output, valid counters and timings,
and zero DSP, resource, DMA, or synchronization errors. The W4 Native Boundary
must carry fewer weight bytes than the expanded-S8 control, and the device
must remain on the same boot identifier throughout formal collection.

There is no speed threshold. Passing establishes a real-shape W4U8 projection
substrate with an exact integer per-channel scale only. It does not establish
arbitrary real-scale requantization, W4F16, a complete MLP, a Qwen3 block,
performance superiority, or a Selected Baseline.

## Result

Execution completed and the local substrate gate passed on source commit
`5dce832f4f37e763ef2164af1154660be8b6f5d2`. The DSP binary contains the
declared User DMA, HVX nibble lookup, signed byte multiplication, saturated
packing, and integer-HMX instructions, with no QNN or QAIRT dynamic
dependency. Gate/up uses a 724,992-byte VTCM plan and down uses 1,118,208
bytes; both remain within the common 2 MiB request.

The formal 32-run matrix covered both storage variants, both real Qwen3
projection shapes, all four patterns, and repeat counts 1 and 10. Every run
reported zero output mismatches and zero DSP, HMX-resource, DMA, or
synchronization errors. For each shape and pattern, `packed_w4u8` and
`expanded_s8_control` produced identical reference checksums, ranges, expanded
carrier checksums, HMX execution counts, stream counts, and output-tile counts.
The device boot identifier remained
`283cc037-8da2-4e83-bf6f-05429beb7d90` throughout collection.

The Native DDR weight boundary was reduced as intended. Gate/up stores
6,389,760 bytes per projection repeat instead of 12,632,064, a 49.42% reduction.
Down stores 6,324,224 instead of 12,599,296, a 49.80% reduction. The expanded
S8 carrier presented to HMX remains byte-identical to the control; only its DDR
representation and the project-owned VTCM expansion path differ.

Performance characterization is negative for the current canonical plan. The
primary repeat-10 Host wall median across four patterns was 31.863 ms for the
gate/up S8 control and 67.076 ms for packed W4, making packed W4 2.105 times as
slow. Down was 24.640 ms versus 52.255 ms, or 2.121 times as slow. Explanatory
pipeline timing shows the same conclusion: gate/up was 413,088 versus
1,097,893.5 qtimer ticks, and down was 336,360 versus 887,150 ticks. The
gate/up packed path spent a median 817,945 ticks in expansion and the HMX
consumer waited 959,309 ticks; down spent 698,409 expansion ticks and waited
808,980.5. This shows that the current single producer serializes DMA
completion and a full-bundle HVX expansion before publication, so the nominal
two-slot plan does not hide expansion behind HMX consumption.
