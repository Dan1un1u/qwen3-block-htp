# SP2 的 A16 Down 对照：待讨论的实现合同

本轮只补 W16A16 浮点基线；下述对照尚未实现或测量。按既有论文占位，建议把 A16 明确命名为 **Uniform INT16 Down input**，避免与 FP16 Down 或整模 W4A16 混淆。

## 对照范围

冻结当前无旋、per-output-channel W4、FP32 残差主线。只有 SwiGLU 到 Down 的输入表示变化：普通均匀 A8、当前241级 SP2（mode8/radix256）、均匀 INT16。Gate/Up 的 A8 输出、attention/KV、其余线性层、embedding/head、调度选项与预算保持一致。这里不引入软件对齐分支的187级/radix257配置。

## 建议实现

复用现有256×256 Gate/Up 融合 LUT，使用同一冻结 Gate/Up 反量化及 SiLU/乘法参考生成值 z。给 INT16 使用与 SP2 相同的逐层对称裁剪端点 alpha，Delta16=alpha/32767，q16=clip(round(z/Delta16),-32767,32767)，并明确冻结 ties-to-even 舍入。不要重做校准来追逐该对照的速度/质量。既有 SP2 舍入合同原样保留。

LUT 直接生产 q16+32768 的低/高字节，与当前 SP2 的执行物理布局相同。消费者继续使用 v=low+256*high-32768 的两路 U8×packed-W4 整数点积和预计算权重和修正，重算相应 Down 输出缩放参数。Prefill 复用现有双分量流水；decode 复用同一 tile 的两行共装、一次权重遍历。无额外在线 INT16→两个字节转换；没有新增 FP16 HMX 权重展开路径。

这不是把离散 SP2 编号当普通 INT16；对照改变的确实是重构网格。两者都使用两字节执行 carrier，并给两者同等布局与流水优化。预期 SP2 和 INT16 性能接近，但须实测；不能预先声称 SP2 硬件更快。软件侧另行论证指定 SP2 表示的精度价值。

## 验证与测量

1. 穷举每层65536个 Gate/Up 码组合，验证 INT16 LUT 与独立参考、生产布局与消费者解码一致。检查整个 INT16 端点，而不只覆盖 SP2 的稀疏码本。
2. 原生整数点积对 INT64 oracle；特别验证合并高低位与零点修正的中间溢出、负值和舍入。Llama K8192/W4[-7,7] 的最终极值界虽在 INT32 范围内，中间表达式仍必须独立检查，不能仅凭最终界认定安全。
3. 单层/连续层/全模分别对各自参考验证。不同量化方案之间不要求输出逐字节相等；各方案内部的物理实现必须正确。
4. 主速度对照使用固定 token 轨迹、同一 M64+15 和完整 Host wall；补真实 greedy 速度，报告 A8/SP2/INT16 三组。逐层归因保留 LUT/Down、HMX工作量、权重与激活搬运量、VTCM峰值、FP32残差开销。

若想研究 FP16 Down，它应另命名为 FP16 activation / FP16 HMX Down，对应 W4 展开、激活载体及输出舍入合同都会变化。这回答的是混合后端部署成本，不再是只改变 SP2/均匀网格的同一路径对照。建议先完成上述 INT16 对照。

## Execution protocol

The above proposal is now authorized for implementation and measurement. Freeze latest no-rotation native-W4, FP32-residual baseline and all other boundaries/weights. Only uniform INT16 Down LUT and associated output scales change. Same binary, same resources and optimization flags for A8/SP2/INT16. No PPL/calibration/rotation or unrelated recipe changes. Exhaustive LUT and component INT64 reference/overflow checks, independently referenced selected layer prefill/decode, three-layer continuous slice, then full model own-reference audit. Original A8/SP2 controls must reproduce existing references. Shape M64+15; preserve Qwen cache128 and its original fixed token0 KV seed. Llama independently uses cache80. Fixed-token primary, greedy supplementary. One warmup per arm, auxiliary repeat1, five short repeat10 rounds, ten fixed rotated three-arm repeat10 formal rounds per trajectory. Bootstrap95 paired complete Host wall, no optional stopping. Slower diagnostic arms may finish; ten-percent gate reported, no automatic promotion. Preserve8MiB/oneRPC/oneHMXowner/zero timed intermediateDDR, full module ledgers and all original attempts. Llama device first, Qwen local preparation only until release. Routine owned repairs autonomous.

Protocol clarification before Qwen measurement: cache80 in the initial shared text applied to Llama. Qwen inherits cache128 and its frozen prefix KV exactly from EXP0282; no configuration change is introduced by this control.
