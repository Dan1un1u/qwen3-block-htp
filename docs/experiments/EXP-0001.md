# EXP-0001 — FastRPC U8 vector bring-up

## Approval

Approved by the user on 2026-08-27 by confirming creation of the independent
repository, Project Memory, and `EXP-0001-fastrpc-bringup` source branch.

## Objective

Prove that an Android Host process can open a long-lived FastRPC session to a
project-owned cDSP Skeleton on PJZ110/V79, map shared rpcmem, invoke one U8
vector Execution Unit, obtain deterministic device output, and collect Host
wall time plus DSP qtimer measurements without QNN.

## Scope

The device operation applies a fixed elementwise transform to a U8 vector. It
is a communication and resource-access probe, not a Qwen3 kernel or performance
candidate. VTCM allocation is required to prove the intended DSP substrate;
HMX is deliberately deferred.

## Hard gate

The isolated Host and DSP builds must succeed; the DSP Skeleton must load on
PJZ110; one Host invocation must execute the transform on cDSP; output must be
byte-exact against the independent Host reference; the DSP must report a valid
qtimer interval and VTCM availability; and the executable dependency/runtime
audit must contain no QNN execution library. A failure is retained and stops
before an HMX experiment.
