# EXP-0001 — FastRPC U8 vector bring-up

## Approval

Approved by the user on 2026-08-27 by confirming creation of the independent
repository, Project Memory, and `EXP-0001-fastrpc-bringup` source branch.

## Objective

Prove that an Android Host process can open a long-lived FastRPC session to a
project-owned cDSP Skeleton on PJZ110/V79, map shared rpcmem, invoke one U8
vector Execution Unit, obtain deterministic device output, and collect Host
wall time plus DSP qtimer measurements without QNN.

## Scope

The device operation applies a fixed elementwise transform to a U8 vector. It
is a communication and resource-access probe, not a Qwen3 kernel or performance
candidate. VTCM allocation is required to prove the intended DSP substrate;
HMX is deliberately deferred.

## Hard gate

The isolated Host and DSP builds must succeed; the DSP Skeleton must load on
PJZ110; one Host invocation must execute the transform on cDSP; output must be
byte-exact against the independent Host reference; the DSP must report a valid
qtimer interval and VTCM availability; and the executable dependency/runtime
audit must contain no QNN execution library. A failure is retained and stops
before an HMX experiment.

## Result

Execution completed on PJZ110 / SM8750 on 2026-08-27 from source commit
`4d7c466ecdafdbe7960623cb50a8ac61d5b8691e`. Android arm64 Host and Stub and a
V79 DSP Skeleton built successfully with the isolated SDK 6.6.0.0, Tools
19.0.07, and NDK r26c environment. Nine formal device runs covered vector
lengths 257, 4097, 65536, and 262144. Every run returned FastRPC result zero,
DSP status zero, a positive qtimer interval, the requested VTCM allocation,
and byte-exact output; aggregate mismatches were zero.

The 65536-byte default case was repeated six times. Median Host wall latency
was 4,003,724 ns; median DSP qtimer was 56,721 ticks (approximately 2,954.219
microseconds at the documented 19.2 MHz qtimer frequency). These timings are
bring-up diagnostics, not a model-kernel performance claim.

Host and DSP dependency audits found no QNN or QAIRT dependency. Formal results
are stored in `D:\llm_exp\results\qwen3-block-htp\exp0001`; retained binaries
are stored in `D:\llm_exp\models\qwen3-block-htp\exp0001`.

Execution state is `completed`, evidence validity is `valid`, and the local
gate is `pass`. Adoption remains `pending` until the user explicitly decides.
