# EXP-0037 — Head-aligned Q/K/V Batch-4

## Approval and status

Approved by the user on 2026-08-29 after EXP-0036 made Gate/Up a valid W4F16
speedup and left Q/K/V as the largest anomalous projection scope. The source
starts from EXP-0036 commit `a959219dfa95d6b7b1b45aa18d4e03f3d60d656c`.
This source choice does not accept EXP-0036 or promote a Selected Baseline.

## Evidence basis

EXP-0034 showed that W4F16 Q is the only regressing Q/K/V projection: at
repeat ten Q is 26.61 percent slower than F16F16, while K and V are 14.48 and
13.03 percent faster. EXP-0035 moved the first packed-Q transfer before input
RMSNorm and reduced Q wall by only 1.69 percent without reducing complete-block
Host wall. Moving that transfer again is therefore a rejected hypothesis.

The retained generic W4F16 projection consumes two 32-channel output tiles per
HMX command while its DMA bundle contains four tiles. Qwen3 head dimension 128
also equals four 32-channel tiles. EXP-0037 tests whether aligning one DMA
bundle, one HVX expansion group, one HMX command, and one Q/K head-readiness
publication removes command, handoff, and tail overhead inside Q.

## Fixed contract

- The Execution Unit is the real Qwen3-1.7B layer-14 complete block at `M=64`,
  measured with repeat one and repeat ten in one FastRPC invocation.
- The immutable W4 control is EXP-0036 W4F16 Crouton-native Gate/Up Batch-8.
  Attention mathematics, QK Norm, RoPE, Softmax, AV, O, MLP, residuals, W4
  values and scales, FP16 arithmetic, and output layouts are fixed.
- Every mode requests exactly 8,388,608 VTCM bytes. Additional QKV expanded
  tiles must use a lifetime-proven phase-local overlay; the formal plan may not
  exceed the grant or displace the retained 64 KiB GQA scratch reservation.
- Intermediate DDR, spill/fill, a second FastRPC Execution Unit, a second HMX
  owner, QNN, and QAIRT are failures.
- Q, K, V and final block outputs must remain byte-identical to their paired
  control and pass the independent Implementation Reference.
- Equivalent-scope Host wall is primary. Projection wall is an exclusive
  ledger interval; DMA, HVX and HMX work counters overlap and are diagnostic.

## Ordered milestones

### Stage A — Q-only Batch-4

Keep K and V at Batch-2. Change only Q so each four-tile packed-weight DMA
bundle is expanded as one four-tile group, consumed by one HMX command, and
publishes exactly one complete Q head. Q HMX commands should fall from 32 to
16. Collect one audit-on correctness run and five alternating audit-off
repeat-one and repeat-ten runs for control and candidate in one stable boot.

Stage A passes only if the candidate is byte-exact, strictly reduces Q
projection wall and complete-block Host wall at both repeat counts, retains
zero intermediate DDR and zero spill/fill, and satisfies the fixed VTCM and
single-owner contracts. If any condition fails, stop before Stage B.

### Stage B — Full Q/K/V Batch-4 and fair F16 control

Only after Stage A passes, apply the same four-tile boundary to K and V so QKV
HMX commands fall from 64 to 32. Give F16F16 the same QKV Batch-4 schedule
opportunity and select its fastest valid control. Preserve Stage A mathematics
and physical contracts. The W4 candidate must strictly improve aggregate QKV
and complete-block Host wall over the Stage A control at repeat one and repeat
ten; F16 results determine the fair W4-versus-F16 comparison but do not replace
the incremental W4 gate.
