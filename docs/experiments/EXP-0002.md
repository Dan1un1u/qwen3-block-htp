# EXP-0002 — Standalone U8×S8 integer HMX tile gate

## Approval

Approved by the user on 2026-08-27 by requesting continuation of the next
experiment after EXP-0001 completed and the public remote was configured.

## Objective

Prove that the Standalone HTP Runtime can acquire HMX on PJZ110/V79 and execute
one project-owned integer matrix tile without QNN. The probe must make the
physical activation, weight, bias, output, and VTCM contracts explicit before
multi-tile projection or Qwen3 block work begins.

## Fixed arithmetic and physical scope

The initial tile uses the V79 integer-HMX contract already verified in the
historical QHPI feasibility experiment: one 64×32 U8 activation crouton, one
32×32 S8 weight tile in native K4/N packing, and one 64×32 saturated U8 output
crouton. The activation load is `activation.ub ... :cm`, the weight load is
`weight.b`, and the output is written with `after:cm` saturated-U8 conversion.

Inputs originate in shared rpcmem but are copied and packed into project-owned
VTCM regions before the timed HMX core. The HMX bias table encodes identity
accumulator conversion and asymmetric activation zero-point correction. The
first implementation uses scale 1 and zero point 128 so that an independent
Host reference can evaluate `clamp(sum((a - 128) * w), 0, 255)` exactly.

## Hard gate

The isolated V79 DSP build must contain identifiable integer-HMX activation,
weight, accumulator-clear, bias, and saturated-output instructions. A single
FastRPC invocation must acquire VTCM and HMX, execute the tile on cDSP, and
return byte-exact output for deterministic identity, signed, structured, and
boundary patterns. DSP qtimer and Host wall measurements must be valid. The
Host and DSP artifacts must have no QNN or QAIRT execution dependency, and no
Host reference computation may substitute for the claimed DSP kernel.

Failure stops before multi-tile, DMA-overlap, W4 expansion, or Qwen3 projection
work. Passing this gate establishes only the integer-HMX substrate; it is not a
performance candidate or Selected Baseline, and it has no speed threshold.

## Result

The gate passed on source commit
`86843728e63d6add2eff7efa94d5d772a8545c1c`. Static disassembly contains the
integer HMX bias load, accumulator clear, U8 activation load, S8 weight load,
saturated U8 output store, and the HVX VTCM-to-rpcmem boundary copy. Dynamic
dependency scans found no QNN or QAIRT execution dependency.

Eight formal device runs covered the identity, signed, structured, and
boundary patterns at repeat counts 1 and 1000. Every run returned DSP status 0
and byte-exact output, for a total of zero mismatches. Across the four
1000-repeat runs, the timed HMX core averaged 2383.75 qtimer ticks and 47665.25
processor cycles. Host wall time was approximately 3.88--4.07 ms, but it also
contains the complete FastRPC call, power/resource lifecycle, worker creation,
and output-boundary copy and is therefore not a projection benchmark.

The decisive standalone bring-up requirement was explicit HMX power control.
Resource acquisition and lock calls could report success while the first read
of HMX-written VTCM still blocked when HMX had not been powered. Calling
`HAP_power_set_HMX` before resource use, with matching teardown, made the tile
complete deterministically. The final probe also executes HMX on a dedicated
QuRT worker and performs the shared-memory boundary copy after joining it; the
worker's independent performance contribution has not been isolated.
