# EXP-0013 — Rebalance VTCM rings for batch-four overlap

## Approval

Approved by the user on 2026-08-27 under the continuing request to optimize the
standalone Packed-W4 path until it produces a useful speedup over the project's
own Expanded-S8 implementation.

## Objective

Recover the bandwidth benefit of four-bundle User-DMA transactions without the
group-sized slot barrier observed in EXP-0011 and EXP-0012. Batch four reached
the highest stored-weight bandwidth, but the four-slot compressed ring was
exactly one transaction deep. The producer therefore had to wait until every
slot from the previous group was released before it could start the next DMA.

The candidate rebalances the existing 2 MiB project-owned VTCM allocation from
four compressed and eight expanded slots to eight compressed and seven expanded
slots. Eight compressed slots form a true two-group buffer for batch four.
Seven expanded slots retain capacity for six HVX workers plus the ordered HMX
consumer. Both contiguous batch-four and linked-chain-four publication are
tested. A four-compressed/seven-expanded batch-two control isolates any effect
from reducing the expanded ring by one slot.

## Fixed contract

Gate/up remains `M=64, K=2048, N=6144` with a 64-K-tile W4 publication and down
remains `M=64, K=6144, N=2048` with a 96-K-tile publication. Raw signed W4,
per-output integer scale in HMX conversion, asymmetric U8 zero-point correction,
six HVX workers, integer HMX, output saturation, DDR graph boundaries, clocks,
power votes, logical weight traffic, and HMX work are unchanged. No weight may
be cached across repeats. The VTCM request remains exactly 2 MiB; there may be
no spill, hidden DDR intermediate, QNN dependency, or fallback.

The EXP-0011 four-compressed/eight-expanded batch-two path is the performance
parent. Expanded-S8 batch one, contiguous batch two, and linked chain two remain
the fairly searched storage controls. Candidate plans use eight compressed and
seven expanded slots with batch four. All layouts and actual acquired VTCM
bytes must be reported at runtime.

## Gates

All four patterns and both shapes must remain byte-exact with the independent
Host reference and mutually equivalent. HMX execution and stream counts must
be identical. There may be no worker fallback, descriptor timeout, resource,
power, DMA, synchronization, or device-boot failure.

Formal timing uses repeat-10 Host wall latency in rotated order. The local gate
requires the fastest eight-compressed/seven-expanded W4 batch-four plan to beat
the inherited four/eight W4 batch-two plan for both shapes. The same formal
matrix reports the fastest fairly searched Expanded-S8 plan; beating it for
both shapes remains the stretch target. Producer wait, HMX ready-wait, DMA
bandwidth, and pipeline time explain the result but cannot replace Host wall
latency.

## Result

Completed with valid evidence but failed the two-shape local Host-wall gate.
The authoritative clean-commit matrix contains 224 records: 56 correctness
runs and 168 rotated repeat-10 timing runs. Every result is byte-exact with the
independent Host reference and mutually equivalent. HMX execution and stream
counts are unchanged, VTCM requested and acquired bytes remain exactly 2 MiB,
and there was no fallback, descriptor timeout, QNN dependency, resource, power,
DMA, synchronization, or device-boot failure.

Gate/up selected the eight-compressed/seven-expanded linked-chain-four plan.
Host wall median fell from the four/eight batch-two parent at 7.875 ms to
7.573 ms, a 3.84% improvement. Producer slot wait fell from 8.20K to 0.90K
ticks and pipeline time from 56.46K to 50.07K ticks. This confirms that the
second compressed group removes the intended cross-group barrier.

Down selected the analogous linked-chain-four plan, but Host wall regressed
from 6.194 ms to 6.368 ms, or 2.80%, so the required two-shape local gate
failed. Its accelerator pipeline did improve from 36.09K to 34.53K ticks and
HMX ready-wait fell from 5.52K to 2.97K. However, reducing the expanded ring
from eight to seven independently regressed down Host wall by 4.16%, and the
candidate still paid 4.07K expanded-slot wait ticks. The ring rebalance
therefore trades one bottleneck for another on the down shape.

Both selected candidates still beat the fairly searched Expanded-S8 controls:
16.28% for gate/up and 16.19% for down. A prior complete run from source commit
`f0d1b70` was superseded because its validator incorrectly applied W4 expanded-
ring reuse accounting to the S8 control. Re-validating its raw records showed
the same gate/up benefit but only a 1.05% down benefit, underscoring that the
down Host-wall effect is small and not robust. Only the clean `c8933de` run is
authoritative. Adoption remains pending and EXP-0013 does not replace the
successful EXP-0011 projection candidates.
