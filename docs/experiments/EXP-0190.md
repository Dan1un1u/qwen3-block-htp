# EXP-0190 — Direct-n decode Gate/Up batch-eight phase overlay

## Decision and purpose

The user started an autonomous decode optimization loop after promoting
EXP-0189.  EXP-0189 is the immutable direct control at source commit
`15becf9cf8bda0d9320d8cdcb43fab108c865ef8`.  Its remaining largest decode
stage is Gate/Up plus SwiGLU at about 10.096 ms/token, of which about 9.608 ms
is direct-n Gate/Up projection work.

The accepted direct-n implementation processes four output-channel tiles per
HMX command.  During decode its Expanded-S8 VTCM buffers are phase-dead because
HMX reads packed W4 directly.  Each expanded buffer is large enough to carry
eight packed-W4 tiles for the real Gate/Up shape, and the existing bias arena
already supports eight tiles per slot.  EXP-0190 tests whether aliasing those
dead buffers as a two-slot packed-W4 ring and doubling Gate/Up batch size from
four to eight reduces command and DMA granularity on the full-token critical
path.

## Direct control and candidate

One runtime-selectable binary compares the exact EXP-0189 Gate/Up batch-four
path with a decode-only batch-eight candidate.  Candidate Gate and Up use
`buffers->expanded_weight` and `buffers->expanded_weight_alt` as packed-W4
phase overlays.  Down, Q/K/V/O, Attention, row-four SwiGLU, cache, LM head and
M64 prefill remain unchanged.

Weights, scales, qparams, projection mathematics and valid outputs may not
change.  The candidate must read the same packed-W4 and bias bytes, retain zero
Transformer W4-to-S8 expansion and halve Gate/Up direct-n HMX command count.

## Gates

Correctness requires byte-exact hidden hashes, log2 codes, selected tokens and
cache state against the same-binary batch-four control, with existing
independent references retained.  The physical gate remains exactly 8 MiB
VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC call, one HMX
owner and no QNN.

A five-pair rotated short gate precedes the ten-pair formal run over one real
M64 prefill and 192 continuous decode steps through valid length 256.  The
candidate must increase directly measured complete decode tokens/s and reduce
Gate/Up plus SwiGLU wall.  Failure of correctness, the physical contract or
short end-to-end speed stops this experiment before formal profiling.

## Decision state

Approved and started on 2026-09-05 by the user instruction to begin the decode
optimization loop.  Implementation and formal validation completed on
2026-09-05 at source commit
`fb6e6617daa42e2942c762968459e1c47e382465`.  Evidence is valid, the local gate
passes and adoption remains pending; no baseline changes automatically.

## Formal result

The five-pair short gate improved direct decode from 34.578 to 36.791 token/s
(+6.40%).  Ten rotated formal pairs then measured 34.535391 token/s for the
batch-four control and 36.725046 token/s for batch eight, a +6.340322 percent
gain.  Decode Host wall fell from 28.955807 to 27.229374 ms/token and all ten
pairs favored the candidate.  Gate/Up projection fell from 9.608707 to
7.843832 ms/token while SwiGLU remained unchanged near 0.489 ms/token.

Gate/Up HMX commands fell from 2,688 to 1,344 per token; total direct-n HMX
commands fell from 4,928 to 3,584 and weight-DMA descriptors from 10,154 to
7,466.  HMX tile pairs remained 1,699,840 and weight reads remained
866,032,640 bytes/token.  All hidden hashes, tokens and cache state were exact,
and the 8 MiB VTCM, zero timed intermediate DDR, zero spill/fill, one FastRPC,
one HMX owner and no-QNN gates passed.
