# EXP-0135 — W4F16 Gate/Up worker-3 streaming drain

## Decision and hypothesis

EXP-0134 proves that dispatching the previously idle worker 3 as a fourth
W4-to-FP16 expansion context lowers repeat-ten expansion elapsed 10.103%, HMX
wait 8.814%, Gate/Up 1.660%, and complete Host wall 1.763%. It nevertheless
fails the strict repeat-one Host gate because worker 3 returns idle when the
streaming SwiGLU backlog is drained: worker 2 streams during projection, then
workers 0/1 and the main context join it, while worker 3 does no drain work.
The resulting stream-join wait doubles.

EXP-0135 keeps the complete EXP-0134 four-context expansion path and changes
only the final streaming drain. The control retains workers 0/1/2 plus main;
the candidate additionally dispatches already-created and already-locked
worker 3 over the existing atomic streaming queue. No new worker is created,
and all expansion, HMX, DMA, layout, arithmetic, and output contracts remain
unchanged.

## Gates

Both cells must produce byte-exact output `f18b9abbe1487231`, pass expansion
audits, request exact 8 MiB VTCM, retain zero intermediate DDR/spill, one
FastRPC unit, one HMX owner, no QNN, and identical weight/DMA/HMX work. The
candidate must dispatch worker 3 only after Gate/Up expansion has completed and
must join workers 0/1/2/3 before Down begins. It passes only if Gate/Up plus
SwiGLU and complete Host wall strictly improve in ordinary and paired
repeat-one and repeat-ten medians. Formal closure requires PC-027 and PC-028;
only the user may promote a Selected Baseline.
