# EXP-0089 — Gate/Up-to-Down VTCM dependency stream

## Decision and motivation

The user authorized continuing the profiling-guided loop on 2026-08-31. The
direct source parent is the accepted EXP-0084 fair W4U8 baseline. EXP-0088 is
retained as a rejected Softmax-local experiment and is not the source parent.

In the latest repeat-ten profile, Gate/Up plus SwiGLU occupies about 679.9 us
and Down occupies about 316.2 us, together 51.1% of complete Host wall. The
current W4U8 implementation nevertheless executes the complete Gate/Up
pipeline, joins every SwiGLU pair, tears down that projection phase, and only
then starts Down DMA, W4 expansion and HMX. The first Down K chunk depends only
on the first 96 of 192 ordered middle-activation tiles, so the full barrier may
hide an addressable producer window.

## Fixed contract

The Execution Unit is the real Qwen3-1.7B layer-14 complete block at M=64. The
Project Variant is W4U8 and the direct control is
`W4U8-EXP0084-FAIR-CANONICAL`. Preserve byte-identical W4 values, scales,
asymmetric U8 qparams, Gate/Up, SwiGLU and Down arithmetic, projection order,
output codes, logical weight and activation traffic, HMX tile work, all
Attention stages, residuals and numerical-audit rules.

The candidate may change only the VTCM lifetime and dependency schedule across
Gate/Up, SwiGLU and Down. Intermediate Gate/Up output may never enter DDR. The
first Down chunk may consume only after middle tiles 0 through 95 are published;
the second may consume only after tiles 96 through 191 are published. One HMX
owner serializes all matrix commands. Formal runs require one FastRPC per block,
exactly 8,388,608 acquired VTCM bytes, zero intermediate DDR, zero spill/fill,
no QNN, unchanged weight bytes, and unchanged per-block HMX command and tile-pair
counts. Any additional Down prestage ring is declared in peak VTCM evidence.

## Serial milestones

### Stage A — audit-only timeline and capacity gate

On the untouched EXP-0084 control, record the first, 96th and 192nd middle-tile
publication, Gate/Up first and last HMX activity, final Gate/Up join, Down first
DMA publication, first expansion, first HMX start and completion. Prove that
the timeline is disabled in ordinary performance mode. Compute a static VTCM
overlay for the smallest useful Down first-chunk compressed/expanded ring.
Stop before candidate implementation if the first-half activation readiness is
not earlier than Gate/Up completion by a repeatable useful window, or the ring
cannot fit within exact 8 MiB without aliasing live Gate/Up data.

### Stage B — producer-only overlap gate

If Stage A passes, prestage the first Down K chunk while Gate/Up continues,
using only otherwise-idle HVX capacity and a separate VTCM ring. Keep all Down
HMX commands after the Gate/Up HMX sequence for this first candidate, so the
single variable is producer overlap rather than HMX reordering. Validate every
middle-activation dependency and require byte-exact output plus zero mismatch
and zero max LSB. Run five interleaved control/candidate rounds at repeat one
and repeat ten. Gate/Up may not regress in ordinary or paired medians; combined
Gate/Up-plus-Down and complete Host wall must strictly improve at both repeats.

### Stage C — dependency-driven HMX interleave and formal closure

Only if producer-only overlap passes and profiling still exposes HMX idle gaps,
allow ready Down chunk commands to enter the existing serialized HMX queue
without blocking an unready Gate/Up command. Down chunk zero waits for the first
96 middle tiles and chunk one waits for all 192. Run seven interleaved paired
rounds at repeat one and repeat ten, then complete PC-027 and PC-028. A local
pass remains a candidate until the user explicitly promotes it.

## Result

Stage A passed. Seven audit-only runs place the first-half middle-activation
readiness 6,245 to 6,540 ticks before the Gate/Up join, with a median 6,426
ticks. The current Down phase needs only 152 to 168 ticks from phase start to
its first HMX command, with a median 160 ticks. The ordinary path emits no
timeline record and preserves output hash `69f22eeb035e5ec5`, exact 8 MiB VTCM,
zero intermediate DDR, 176 HMX commands and 49,408 U8xS8 tile pairs.

The current complete-block VTCM plan leaves 3,082,528 bytes spare. A
conservative first-chunk prestage ring retaining the existing four compressed
slots and eight expanded slots requires 1,183,744 bytes, so the capacity gate
passes without aliasing the live Gate/Up arena.

Stage B implemented that ring as a phase overlay and prestaged the first
96-K-tile chunk for four Down output tiles. It preserved exact 8 MiB VTCM,
zero intermediate DDR and spill/fill, one HMX owner, 25,444,352 weight bytes,
512 weight-DMA descriptors, 176 HMX commands and 49,408 U8-by-S8 tile pairs.
The final output, middle activation, Down output, QK, probability and AV
boundaries remained byte exact with zero mismatch and zero maximum LSB.

Five interleaved paired rounds show that prestaging does shorten Down, by
3.29% at repeat one and 1.47% at repeat ten in ordinary medians. It does not
shorten the MLP critical path: Gate/Up regresses by 0.79% and 0.62%, while the
combined Gate/Up-plus-Down interval improves only 0.40% and 0.04%. Complete
Host wall improves 1.02% at repeat one but regresses 0.17% at repeat ten; the
paired Gate/Up medians also regress at both repeats. Profiling attributes this
to higher HMX-ready and producer-slot waits while the prestage work borrows the
same DMA/HVX capacity. Stage B therefore fails, Stage C is not run, and the
candidate is rejected. EXP-0084 remains the selected W4U8 baseline.
