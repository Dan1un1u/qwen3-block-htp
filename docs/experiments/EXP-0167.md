# EXP-0167 — W4U8 deterministic token-generation boundary

## Decision and purpose

The user approved completing the input and output boundary for W4U8 on
2026-09-04. The selected EXP-0163 W4U8 implementation already executes the real
Qwen3 layers 0-27 with segmented persistent KV cache through six seals, but it
starts from a prepared hidden tensor and ends at the layer-27 hidden output.
EXP-0167 closes the real token-to-token boundary so W4U8 obtains directly
measured full-stack prefill and decode throughput rather than projected
tokens/s.

## Source and implementation scope

The source parent is the selected EXP-0166 repository state at
`8e0dcf82cb22851a767418805431490fe3699ad2`. That source retains the accepted
EXP-0163 W4U8 transformer and segmented-cache path as well as the proven W4F16
token-generation boundary. The candidate adds only the W4U8-specific token
embedding/input quantization, final model U8 RMSNorm, streamed W4-to-S8 integer
HMX LM head, real-domain online greedy argmax, selected-token return and token
feedback package.

Layers 0-27, projection and nonlinear kernels, Attention mathematics, the
EXP-0163 segmented KV-cache ABI and lifecycle, existing W4 values and qparams,
the F16F16 and W4F16 paths, tokenizer and fixed prompt are immutable. The timed
path may return only the selected token and may not materialize full logits in
DDR. An explicitly untimed audit path may expose bounded logits or
intermediates for reference validation.

## Gates and reporting

There is deliberately no model-accuracy or semantic-quality gate. W4U8 is not
required to select the same tokens as W4F16, match a higher-precision teacher,
or generate readable text. Generated tokens and decoded text remain visible as
diagnostics and an unusable string does not stop implementation or performance
measurement.

Implementation correctness remains mandatory: selected tokens and declared
integer/quantized audit intermediates must agree with an independent W4U8
software implementation, and the existing EXP-0163 zero-LSB transformer-output
and cache regression must continue to pass. Physical execution retains exactly
8 MiB VTCM, one FastRPC call per pass, no QNN, zero inter-layer or timed
full-logit DDR tensors, and zero spill/fill.

The initial implementation has no minimum speed gate. Formal reporting uses ten
rotated complete sessions with the same M64 prompt and fifteen continuous
decode tokens as EXP-0166. It reports directly measured full-stack prefill and
decode tokens/s together with their exact Host-wall denominators. EXP-0166 is
the same-scope W4F16 performance comparator; transformer-only or single-layer
measurements may not be extrapolated into token/s.
