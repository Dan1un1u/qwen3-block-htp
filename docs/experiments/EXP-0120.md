# EXP-0120 — W4U8 Gate/Up double-buffered ring

## Decision and scope

The user authorized a continuing W4F16/W4U8 recipe-specialization loop and
routine autonomous recovery. EXP-0120 returns to the largest current W4U8
module after EXP-0118 and EXP-0119 closed the Q-expansion worker-lending
family. It branches from the combined EXP-0112 provisional source parent and
changes only the W4U8 Gate/Up compressed and expanded VTCM ring capacity.

## Evidence and hypothesis

The accepted batch-eight Gate/Up consumer requires all eight expanded slots
for its in-flight command, so the current eight-slot ring cannot hold a fully
prepared next command. The current path still reports substantial HMX-ready
and expanded-slot waits. The hypothesis is that sixteen compressed and sixteen
expanded slots allow DMA and three persistent HVX workers to prepare the next
eight-output command while HMX consumes the current command, reducing the
Gate/Up critical interval without changing command cardinality or arithmetic.

## Gates

Control and candidate are runtime selectable from one binary. The control uses
the EXP-0112 `single_fence` path with eight slots; the candidate uses the same
path with sixteen slots. HMX batch size, worker count, stream-region size,
pair-slot count, W4 values, qparams, activation LUT, Gate/Up ordering, Down,
QKV, Attention, residuals and the frozen public layer remain unchanged.

Final output and existing W4U8 stage audits must remain byte-exact. Exact 8 MiB
VTCM, zero intermediate DDR and spill/fill, one FastRPC unit, one HMX owner,
unchanged weight bytes, DMA descriptor count, HMX commands and tile pairs are
hard gates. The candidate peak-used VTCM may increase only by the declared
Gate/Up ring delta and must remain below the fixed grant. A candidate is
eligible only if Gate/Up and complete Host wall strictly improve in ordinary
and paired repeat-one and repeat-ten medians over five rotated rounds. PC-027
and PC-028 are mandatory. Only the user may promote an eligible candidate.

Both cells preserve output hash `69f22eeb035e5ec5`, zero mismatches and zero
maximum LSB. Static and physical gates pass: the runtime selects exactly eight

three persistent HVX workers and the EXP-0112 single-fence publication path.
Both cells request and acquire exactly 8 MiB VTCM, use zero intermediate DDR
and spill/fill, one FastRPC unit and one HMX owner, and retain identical weight
bytes, DMA descriptors, HMX commands and tile work. The local MLP plan grows
from 1,708,032 to 2,142,208 bytes, but phase overlay keeps the complete-block
peak unchanged at 5,306,080 bytes.

At repeat ten, complete Host wall falls from 1740.891 us to 1607.682 us and
Gate/Up-plus-SwiGLU from 672.198 us to 541.245 us. The candidate reduces
HMX-ready wait about 27.0% and expanded-slot wait about 88.4%. Producer-slot
wait rises about 157%, but it moves off the critical path and is substantially
smaller than the removed starvation interval. This confirms the hypothesis:
the original eight-slot ring forced all expanded slots to be consumed by one
HMX command and could not stage the next command, while ring sixteen creates a
real next-command buffer for DMA/HVX/HMX overlap.

pending user adoption, and does not silently replace a Selected Baseline.
