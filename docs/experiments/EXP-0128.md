# EXP-0128 — W4U8 Gate/Up half-region streaming publication

## Decision

The user authorized the continuing W4F16 and W4U8 specialization loop and
routine source-control repair without interruption. EXP-0128 follows the
closed W4F16 QKV batch-width axis by returning to the dominant W4U8 Gate/Up
pipeline. It does not promote a baseline.

## Hypothesis

The accepted local EXP-0120 ring16 plan removed most expanded-slot starvation,
but its HMX consumer still spends about 6.5 thousand qtimer ticks per block
waiting for expanded regions. Each current publication covers 32 K-tiles, or
64 KiB of expanded S8 carrier per output. Publishing exact 16-K-tile regions
may allow HMX to start each stream earlier while three HVX workers continue the
remaining expansion. This changes readiness granularity, not weights, decoder
arithmetic, HMX tile work or output mathematics.

## Variants

- `ring16_stream32_control`: EXP-0120 ring16 with two 32-K-tile regions.
- `ring16_stream16_candidate`: the same ring, batch-eight HMX consumer and
  three expansion workers with four 16-K-tile regions.

The source parent is EXP-0127 commit
`b3afdc39a5b58fb6cdd45d103b8325eb973a5465`; the logical W4U8 performance
parent remains EXP-0120 ring16.

## Gates

Both cells must be byte-exact with output `69f22eeb035e5ec5`, preserve existing
stage audits, request exact 8 MiB VTCM, use zero intermediate DDR and spill,
one FastRPC Execution Unit, one HMX owner and no QNN. Weight bytes, DMA
descriptors, expanded bytes and HMX tile pairs must remain identical; only
stream-region task/publication counts may change.

The local speed gate requires Gate/Up plus SwiGLU and complete Host wall to
strictly improve in ordinary and paired repeat-one and repeat-ten medians.
PC-027 and PC-028 are mandatory. Only the user may promote a Selected Baseline.

## Result

Formal evidence is archived at
`D:/llm_exp/results/qwen3-block-htp/exp0128/20260901T002210Z_7f9641c6a389_formal`.
Both cells are byte-exact (`69f22eeb035e5ec5`, zero mismatch, zero max LSB),
retain the exact 8 MiB VTCM grant, zero intermediate DDR/spill, one FastRPC
Execution Unit and one HMX owner. The intended physical change is observed:
HMX stream count rises from 768 to 1536 per block.

The finer publication is a clear regression. At repeat one, Gate/Up rises
24.42% and complete Host wall rises 5.89%; paired changes are 22.59% and
6.54%. At repeat ten, Gate/Up rises 21.90% and complete Host wall rises 7.88%;
paired changes are 22.02% and 7.30%. The candidate also raises HMX ready wait
13.49%, HMX compute attribution 7.89%, expansion work 2.97% and producer-slot
wait 26.86% at repeat ten.

The hypothesis is rejected. Sixteen-tile readiness arrives earlier, but
doubling the number of HMX streams and HVX publication tasks costs more than
the saved first-region latency and worsens the consumer/producer schedule.
The selected cell remains the 32-tile control. Reopen only with a mechanism
that aggregates multiple readiness regions into one HMX issue or otherwise
avoids doubling stream-command overhead. No baseline is promoted.
