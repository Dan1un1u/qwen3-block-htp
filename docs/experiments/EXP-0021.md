# EXP-0021 — VTCM-resident Qwen3 W4U8 MLP

## Approval

Approved by the user on 2026-08-27. The user accepts moving beyond isolated
projection tuning and makes zero intermediate DDR traffic a non-negotiable
hard gate.
Gate/Up results and the activated intermediate must remain on chip through
project-owned pipeline scheduling; a functionally correct implementation that
materializes either tensor in DDR does not pass bring-up.

## Objective

Compose the accepted EXP-0019 projection-v1 substrate into one Qwen3 middle-
block W4U8 MLP Execution Unit for `M=64`, hidden size 2048, and intermediate
size 6144:

```
gate = W4U8_gate(x)
up = W4U8_up(x)
middle = quantize(SiLU(dequantize(gate)) * dequantize(up))
y = W4U8_down(middle)
```

The first implementation establishes an explicit local fixed-point contract
and an independent Host reference; whole-model accuracy is not a gate. The
experiment must show that the projection substrate composes without giving
back its weight-traffic advantage at hidden activation boundaries.

## Legal physical boundary

The only legal DDR tensors are the input activation `[64, 2048]`, packed W4
Gate/Up/Down weights and their quantization metadata, and the final output
`[64, 2048]`. Protocol counters and compact checksums are metadata, not tensor
workspaces. Gate tiles, Up tiles, the SiLU-gated product, the complete Down
activation, and partial Down state may exist only in HMX accumulator state,
HVX registers, or declared VTCM regions.

The following are hard failures regardless of correctness or speed: any
intermediate rpcmem offset or graph output; any User-DMA descriptor between an
MLP intermediate and DDR; any scalar or vector load/store of an intermediate
through a DDR pointer; any spill/fill, fallback, second FastRPC run invocation,
or an undeclared workspace used to evade accounting. Final evidence must report
zero intermediate DDR read bytes, zero intermediate DDR write bytes, zero
intermediate DMA descriptors, and zero intermediate spill/fill count. Static
pointer provenance and DMA descriptor audits must agree with runtime counters.

## Initial physical plan

Derive from accepted source commit
`7fa7f280964978b334e25a2c76f1133ed458bf10`, not from the losing EXP-0020
candidates. Preserve asymmetric U8 inputs, byte-identical signed W4 values,
per-output integer scales, HMX postscale, integer HMX, the two-producer
32-K-tile Gate/Up handoff, linked User DMA, one prepared FastRPC invocation,
and the 2 MiB VTCM request.

Gate and Up weight/output tiles are physically paired by intermediate-channel
tile. HMX produces only the current bounded Gate/Up tile pair. HVX consumes it
immediately, applies the declared fixed-point SiLU and Gate-by-Up requantization,
and writes the resulting Down-input tile into its final location in a 384 KiB
VTCM tensor. Raw Gate and Up outputs are never materialized as complete
tensors. Ping-pong tile generations bound producer lead and prevent stale-slot
reuse.

After all Down-input generations are ready, Down uses that VTCM tensor directly
as its HMX activation source and retains the accepted 96-K-tile coarse W4
weight schedule. This bounded phase boundary is required by the current HMX
output-tile accumulator order: each Down output tile must traverse all 6144 K
channels. It does not permit DDR materialization and does not reintroduce the
rejected EXP-0018 policy of separating HVX weight expansion from HMX within a
projection.

## Milestones and stop conditions

First, define and exhaustively validate the scalar fixed-point SiLU and product
requantization, then prove an HVX implementation is byte-identical for all U8
input pairs. Second, bring up one Gate/Up tile pair through HVX into a VTCM Down
activation tile. Third, run the complete MLP once and validate every final byte
against the independent Host reference. Only after all residency and numerical
gates pass may repeat-one and repeat-ten profiling begin.

If the 2 MiB VTCM map cannot contain the activation, bounded Gate/Up tile ring,
384 KiB Down input, W4/DMA rings, and final-output tile, stop and discuss a new
tiling contract with the user; do not silently request more VTCM or spill to
DDR. Any residency-gate failure also stops the experiment before performance
optimization. There is no speed gate for the first complete implementation,
but equivalent-scope Host wall is reported and no result may be called a
Selected Baseline without explicit user approval.

## Result

Completed on 2026-08-27 at source commit
`23f51b37efbd6e16e7e0249a17505264f1684d0d`. The hard residency gate passes.
The formal matrix contains one correctness run, ten warmed repeat-one timing
runs, and ten warmed repeat-ten timing runs. Every final byte matches the
independent Host reference, and the HVX Gate-by-Up activation is byte-identical
to its scalar definition for all 65,536 possible U8 input pairs. The device
boot ID remained stable.

Gate and Up are not materialized as complete tensors. HMX publishes 192 paired
output-tile generations per MLP into an eight-slot, 32 KiB VTCM ring. HVX
consumes every generation and writes the activated product directly into the
384 KiB Down-input tensor in VTCM. Down then reads that VTCM tensor directly.
Formal repeat-one and repeat-ten records observed matching publication and
consumption counts, HMX/HVX overlap in Gate/Up and Down, a 1,708,032-byte peak
plan inside the fixed 2 MiB VTCM allocation, and no fallback or reboot.

Static pointer-provenance and ABI audits expose only four legal shared-memory
buffers: input, packed Gate/Up weights, packed Down weights, and final output.
Runtime evidence agrees: intermediate DDR reads and writes are 0/0 bytes,
intermediate DMA descriptors are 0, spill/fill count is 0, Gate/Up output DMA
descriptors are 0, and middle-tensor DMA descriptors are 0. The only output
transfer is the final 64-descriptor VTCM-to-DDR assembly.

The warmed repeat-one Host-wall median is 1.415 ms. The repeat-ten median is
1.096 ms per complete MLP. Median per-MLP DSP time is 17,132 qtimer ticks at
repeat one and 16,551 ticks at repeat ten. For diagnostic context, the
integrated Gate/Up and Down phases are still more expensive than the isolated
EXP-0019 projection phases, and the activation adds about 2,000 ticks. Thus
this result establishes the required physical composition and removes the DDR
intermediate boundary; it does not establish that the integrated engine
schedule is final or optimal. There was intentionally no speed gate.
