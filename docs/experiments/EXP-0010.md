# EXP-0010 — Batch both gate/up HMX streams behind one ready boundary

## Approval

Approved by the user on 2026-08-27 under the continuing request to optimize the
standalone W4U8 implementation toward a useful self-speedup.

## Objective

Apply the consumer-boundary result from EXP-0009 to gate/up. The real gate/up
shape has K=2048, or 64 architectural K tiles. Its current 32-tile Packed-W4
schedule publishes two chunks and invokes the HMX consumer twice per output
tile, while Expanded-S8 emits the same two internal HMX streams inside one
consumer call. The candidate expands all 64 K tiles into one ready slot and
lets `qbh_hmx_accumulate_u8s8_projection` issue both 32-tile streams without an
intermediate semaphore, function return, overlap-metric barrier, or accumulator
handoff.

## Fixed contract

Only gate/up is tested: `M=64, K=2048, N=6144`. The candidate retains the
EXP-0008 raw-q4 HVX unpack and HMX post-accumulator per-channel scale, four
compressed slots, eight expanded slots, six requested HVX workers, asymmetric
U8 zero-point correction, User DMA, DDR boundaries, clocks, power vote, and
output saturation. The Expanded-S8 control, EXP-0007 32-tile HVX-prescale path,
and EXP-0008 32-tile HMX-postscale path remain explicit comparators.

Only the candidate chunk changes from 32 to 64 K tiles, reducing publications
per output from two to one. The HMX tile-pair count and two internal streams per
output remain unchanged. The larger VTCM plan must remain below the existing
2 MiB request. Reduced task-level HVX parallelism is allowed and must be
reported; equivalent Host wall latency is the primary metric.

## Gates

All four patterns must remain byte-exact with the independent Host reference
and all controls. There may be no resource error, fallback, hidden DDR
intermediate, QNN dependency, power failure, synchronization error, or device
reboot. Runtime evidence must retain integer HMX, raw-q4 carrier, postscale,
User DMA, and equal internal HMX execution/stream counts.

Formal timing uses repeat-10 Host wall latency in rotated order. The local gate
requires the 64-tile postscale candidate to beat the faster of the two inherited
Packed-W4 controls. Beating Expanded-S8 is the stretch target. HMX compute,
ready wait, expansion work, pipeline time, and active HVX workers explain the
result but do not replace Host wall latency.

## Result

Completed with valid evidence and a passed local gate and stretch target. The
formal matrix contains 64 records: 16 correctness runs and 48 rotated repeat-10
timing runs. All outputs are byte-exact with the independent Host reference and
all variants are mutually equivalent. Every timing variant executes the same
122,880 HMX tile pairs and 3,840 internal HMX streams. There was no worker
fallback, device reboot, QNN dependency, resource error, power error, DMA
error, or synchronization failure.

The selected plan is four compressed slots, eight expanded slots, six requested
HVX workers, raw-q4 unpack with HMX post-accumulator scale, and all 64 K tiles
behind one publication boundary. Its Host wall median is 8.219 ms. This is
9.78% faster than the best inherited Packed-W4 control at 9.110 ms and 13.19%
faster than the byte-identical Expanded-S8 control at 9.468 ms.

The evidence supports the consumer-boundary hypothesis. Coalescing the two
internal HMX streams reduced pipeline time from 76.6K ticks in the fastest
32-tile Packed-W4 control to 61.6K ticks. HMX compute attribution fell from
62.6K to 36.2K ticks, while expanded-slot wait fell from 2.04K to 1.06K ticks.
Only four HVX workers were simultaneously active instead of six, but removing
one semaphore/publication/function boundary per output tile saved more than the
lost task-level parallelism. The number of HMX streams and mathematical work
did not change.

Together with EXP-0009, this establishes stable Packed-W4 wins over the strict
Expanded-S8 control for both real Qwen3 middle-block projection families:
gate/up uses 64-tile publications and down uses 96-tile publications. This is a
successful local projection experiment, not a Selected Baseline or a complete
Qwen3 block; adoption remains pending user decision.
