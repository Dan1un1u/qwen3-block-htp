# EXP-0172 — Decode-M1 Gate/Up direct HVX GEMV feasibility

## Decision and purpose

The autonomous decode loop proceeds from selected EXP-0170 after EXP-0171
proved that reducing overlapped SwiGLU work does not shorten the critical
path. EXP-0172 targets a structural source of wasted decode computation:
`logical_m=1` still executes projection HMX carriers with 64 physical rows.
The first feasibility target is W4U8 Gate/Up because it is the largest decode
module and its K=2048 projection has one 64-K-tile streaming chunk.

## Direct control and candidate

One binary provides the selected EXP-0170 HMX Gate/Up control and a decode-only
direct GEMV candidate. Both retain the same W4 DMA and HVX W4-to-S8 expansion
pipeline, output-tile order, per-channel bias/conversion words, SwiGLU, Down,
cache and all other modules. The candidate changes only the expanded-S8
consumer for M1 Gate/Up:

1. wait for each published 32-K-tile region;
2. use HVX `vrmpyacc` to accumulate the sole valid activation row against the
   existing 32-by-32 HMX weight carrier into 32 S32 output lanes;
3. add those lanes to the existing HMX upper-bias words;
4. use a bias-only HMX store for the existing per-channel U8 conversion; and
5. publish the same valid row to the unchanged SwiGLU handoff.

This first experiment intentionally keeps weight expansion unchanged. It
isolates whether eliminating the 63 invalid HMX spatial rows is useful before
attempting a direct packed-W4 GEMV.

## Gates and evidence

The short gate requires the direct row-zero projection result to be byte exact
against HMX for real layer-14 Gate/Up values, correct command and call
telemetry, no deadlock and a lower Gate/Up wall in repeated M1 decode. Failure
at this gate rejects the expanded-S8 direct-GEMV consumer without a costly
formal full-stack run.

If the short gate passes, formal evidence uses ten rotated full-stack pairs,
each with M64 prefill and 192 continuous L64-L255 decode tokens. It requires
byte-identical hidden hashes, caches, U8 logit codes and token sequences,
independent reference and retained EXP-0163 regression success. The physical
contract remains exact 8 MiB VTCM, one FastRPC call per pass, no QNN, zero
timed intermediate/full-logit DDR, zero spill/fill and zero unattributed ticks.
Eligibility requires higher direct decode token/s and lower Gate/Up wall;
prefill must remain on the selected HMX path.
