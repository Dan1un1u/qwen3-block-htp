# EXP-0050 — W4U8 Down two-chunk HMX command fusion

## Approval and parent

Approved by the user on 2026-08-29 after EXP-0049 reduced Gate/Up worker
commands from 768 to 48 and moved the remaining repeat-ten ledger toward QKV,
Down, and Attention. The implementation parent is EXP-0049 source commit
`b37d208d262d5a45365d6efe32c03786a5c3a2d3`. The source branch is
`codex/exp-0050-w4u8-down-command-fusion`.

## Hypothesis and bounded scope

The current Down projection has K=6144, represented as two ordered 96-K-tile
chunks for each of 64 output tiles. Each chunk is currently submitted to the
single integer-HMX owner through a separate synchronous worker command. The
arithmetic is one accumulation: chunk zero initializes the accumulator and
chunk one continues it before the final U8 store. Therefore the worker-command
boundary between the two chunks is scheduling overhead, not a mathematical
boundary.

EXP-0050 tests whether one worker command can consume both ordered chunks while
retaining producer-consumer overlap: HMX may begin chunk zero as soon as it is
ready, while HVX expands chunk one, then the same command waits for and consumes
chunk one before storing the unchanged U8 output. A diagnostic that waits for
both chunks before submitting one command may be used only to isolate command
overhead; it is not adoptable if it destroys useful HVX-HMX overlap.

The direct control is `W4U8-EXP0049-GATE-UP-BATCH8`. QKV, integer Attention,
O, Gate/Up batch eight, SwiGLU, activation boundaries, W4 values and scales,
activation qparams, and numerical arithmetic remain fixed. The bounded search
contains at most two candidates: pre-ready two-chunk command as a diagnostic,
and generation-safe in-command second-chunk readiness as the primary schedule.

## Gates

- The Execution Unit is the real Qwen3 layer-14 complete block at M=64.
- The device final output must remain byte-exact to EXP-0049 and the independent
  implementation reference must report zero mismatches and maximum error 0 LSB.
- One FastRPC invocation, one HMX owner, exactly 8 MiB VTCM, zero intermediate
  DDR, zero spill/fill, and no QNN path are mandatory.
- HMX U8xS8 tile-pair count, Down W4 weight bytes, qparams, and output codes must
  remain unchanged. Down worker-command count is expected to fall from 128 to
  64 commands per block; no claim is accepted unless telemetry proves it.
- A candidate passes locally only if both the Down additive/pipeline interval
  and complete Host wall are strictly lower than EXP-0049 at repeat one and
  repeat ten.
- The formal comparison uses seven interleaved paired rounds on one stable boot
  and closes every PC-027 profiling field, keeping additive ledger rows separate
  from overlapping HMX, HVX, DMA, wait, byte, command, and VTCM counters.
- A local pass creates only a candidate. Baseline promotion remains a user
  decision.

## Implementation and formal result

Source commit `67c112e298b49e96cbaa1a78b5223dad54040c42` implements the
generation-safe candidate. Down still begins HMX consumption when chunk zero
is ready. The same worker command then waits for chunk one's generation tag,
consumes it into the existing accumulator, and performs the unchanged final U8
store. This reduces Down commands from 128 to 64 and total block HMX commands
from 320 to 256 without changing the 49,408 U8-by-S8 tile pairs, 512 weight DMA
descriptors, or 25,444,352 weight bytes per block.

Seven interleaved paired rounds on stable boot
`77ccafe0-8817-4976-bdae-15af5608d4ff` passed every gate. The candidate final
output is byte-exact to EXP-0049 (`69f22eeb035e5ec5`) and the independent
implementation reference reports zero mismatches and maximum error 0 LSB.
Exactly 8,388,608 bytes of VTCM were requested and acquired, peak live planning
remained 5,306,080 bytes, and intermediate DDR, spill/fill, QNN dependency, and
additional HMX ownership all remained zero.

At repeat one, Down pipeline ticks fell 31.720% and complete Host wall fell
3.905% (paired median 3.109%). At repeat ten, Down pipeline ticks fell 31.007%
and complete Host wall fell 4.657% (paired median 4.497%). Down additive ticks
fell 28.804% and 28.110%, respectively. The local gate therefore passes and the
result is locally adoption-eligible, but it remains a candidate until the user
explicitly promotes it.
