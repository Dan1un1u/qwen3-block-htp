# EXP-0011 — Batch contiguous projection weight bundles per User-DMA submission

## Approval

Approved by the user on 2026-08-27 under the continuing request to optimize the
standalone W4U8 path until packed weights produce a useful speedup over the
project's own Expanded-S8 control.

## Objective

Convert the remaining producer bottleneck into useful W4 bandwidth. EXP-0009
and EXP-0010 made Packed-W4 faster than Expanded-S8 for both real Qwen3
projection shapes, but the selected W4 pipelines still spend substantial time
waiting for expanded weights. Each output tile currently transfers one bundle
with a separate `dmstart` and synchronous idle wait. A W4 bundle is about 33 KB,
so descriptor and wait overhead prevent it from reaching the bandwidth seen by
the 66 KB Expanded-S8 bundle.

The candidate waits for a contiguous group of ring slots, transfers two or four
contiguous W4 bundles with one 1-D User-DMA descriptor, then publishes the
individual output-tile expansion tasks in order. The strict S8 control receives
the analogous one-versus-two-bundle search. W4 batch four and S8 batch two both
move about 130 KB per submission, giving both storage formats a comparable DMA
transaction size while retaining their native byte counts.

## Fixed contract

Both Qwen3 middle-block shapes are tested: gate/up is `M=64, K=2048, N=6144`
with the EXP-0010 64-K-tile HMX publication, and down is
`M=64, K=6144, N=2048` with the EXP-0009 96-K-tile publication. Raw signed W4,
per-output integer scales applied by HMX conversion, asymmetric U8 zero-point
correction, six requested HVX workers, four compressed W4 slots, User DMA,
integer HMX, output saturation, DDR boundaries, clocks, and power votes remain
unchanged. The HMX execution and internal stream counts must remain identical.

Batching may only coalesce adjacent bundle transfers into adjacent VTCM slots.
It may not cache weights across repeats, omit output tiles, insert a hidden DDR
intermediate, or change arithmetic. Batch one remains the inherited control.
Batch sizes two and four are tested for W4; batch sizes one and two are tested
for Expanded-S8. The S8 and W4 searches use the same approximately 130 KB
maximum transaction size.

## Gates

All four patterns and both shapes must remain byte-exact with the independent
Host reference and mutually equivalent across storage variants. There may be no
resource error, worker fallback, QNN dependency, CPU fallback, power failure,
DMA or synchronization error, or device reboot. Static evidence must retain
raw-q4 HVX unpack and integer HMX; runtime evidence must show the declared DMA
batch, reduced submit/wait counts, equal logical bundle count, and unchanged HMX
work.

Formal timing uses repeat-10 Host wall latency in rotated order. The local gate
requires the fastest W4 batch to beat inherited W4 batch one for both shapes.
The same formal matrix reports the fastest fairly searched Expanded-S8 control;
beating it for both shapes is the stretch target. Weight-stage time, HMX
ready-wait, pipeline time, and effective stored-weight DMA bandwidth explain the
result but do not replace Host wall latency.
