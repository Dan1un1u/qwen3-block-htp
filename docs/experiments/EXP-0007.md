# EXP-0007 — Deeper packed-W4 prefetch and task-exposure search

## Approval

Approved by the user on 2026-08-27 with the requirement that the standalone
Packed-W4 path continue toward an effective speedup, informed by the prior QNN
LPBQ observation that W4 beat a plain per-tensor W8A8 control by roughly 40%.

## Objective

Remove the task-exposure and producer back-pressure limit observed in
EXP-0006. The primary target is gate/up, where two compressed bundles and two
32-tile K chunks expose at most four independent HVX expansion tasks despite
the device providing six 128-byte HVX contexts. The experiment asks whether a
deeper compressed-weight ring and, if necessary, a finer K-chunk depth can
hide W4 expansion behind User DMA and integer HMX sufficiently for Packed-W4
to beat the byte-identical Expanded-S8 observation control.

## Fixed contract

The EXP-0006 numerical and storage contract is unchanged: gate/up is
`M=64, K=2048, N=6144`, down is `M=64, K=6144, N=2048`, activation is
asymmetric U8 with zero point 128, stored weights are signed packed W4 in
`[-7, 7]` with the same exact positive per-output integer scales, and HMX sees
the same S8 carrier and produces the same U8 output. No real-scale
quantization, block integration, QNN, or QAIRT change is allowed.

Only the physical schedule may vary. The EXP-0006 two-compressed-slot,
32-K-tile, six-worker plan remains the control. Candidates increase the
compressed ring to three or four slots at 32 K tiles per task. A secondary
search uses 16-K-tile tasks with two or three compressed slots to reduce
time-to-first-HMX and expose more independent expansion work. All candidates
use six requested HVX workers and the same ordered HMX accumulation.

## Gates

Validity requires byte-exact equality with the independent Host reference and
Expanded-S8 control for both shapes and all inherited patterns, no resource,
DMA, synchronization, or DSP errors, no worker fallback, stable device boot
identifier, no hidden DDR intermediate, identifiable User DMA/HVX/HMX code,
and observed HVX/HMX overlap.

The primary metric is repeat-10 Host wall time collected in rotated order.
The local performance gate requires the selected valid Packed-W4 candidate to
improve over the EXP-0006 two-slot control for both shapes. Matching or beating
Expanded-S8 is the explicit stretch target and must be reported independently
for gate/up and down; it is not assumed in advance. A candidate that only
reduces summed work without improving Host wall is not accepted as a speedup.

## Result

Completed with valid evidence and a passed local scheduling gate. The formal
matrix contains 192 successful records (48 correctness runs and 144 rotated
repeat-10 timing runs), with zero mismatches, no worker fallback, stable device
boot identity, a successful DSP/core/bus performance vote, and observed
HVX/HMX overlap for both Qwen3 projection shapes.

The selected plan is four compressed-weight slots, 32 K tiles per expansion
task, and six HVX workers. For gate/up, Host wall median fell from 11.311 ms for
the inherited two-slot control to 9.042 ms, a 20.06% improvement. It also beat
the byte-identical Expanded-S8 observation control at 9.739 ms by 7.16%. The
deeper ring exposes all six HVX contexts, cuts the Packed-W4 weight stage to
45,748 ticks versus 61,957 ticks for Expanded-S8, and leaves only 1,028 ticks
of producer wait in the selected run.

For down, the same plan improved the two-slot Packed-W4 control only from
8.545 ms to 8.527 ms (0.21%) and remained 9.83% slower than Expanded-S8 at
7.764 ms. Down already exposes six independent expansion tasks with two slots;
therefore deeper prefetch cannot remove its dominant costs. Its Packed-W4
pipeline median was 80,324 ticks versus 50,103 ticks for Expanded-S8, with
64,405 HMX-compute ticks and 25,438 expanded-slot-wait ticks. The stretch target
is therefore passed for gate/up and failed for down.

The experiment establishes that Packed-W4 can produce a real end-to-end speedup
when weight transfer, HVX expansion, and HMX consumption are sufficiently
overlapped. It also isolates the next bottleneck: the current HVX expansion
multiplies every unpacked W4 value by its per-output scale before HMX. The down
shape cannot hide this K-by-N work through additional prefetch alone. Moving
per-output scale application to the HMX accumulator conversion is a distinct
future experiment; adoption of EXP-0007 remains pending user decision.
