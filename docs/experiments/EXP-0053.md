# EXP-0053 — Parallel W4U8 native residual flow

## Approval and parent

Approved by the user on 2026-08-30 after the latest three-variant wall-time
summary showed that W4U8 spends about 162.7 microseconds in the
Post-Attention Residual-plus-RMSNorm boundary and 72.0 microseconds in the
Final Residual boundary. The implementation parent is the latest locally
passing W4U8 candidate, EXP-0052 source commit
`f2d07a2727f316ad641ce2e7b423be804a6a3c1a`. The source branch is
`codex/exp-0053-w4u8-residual-pool`.

## Evidence-driven hypothesis

EXP-0026 removed the original scalar FP16 residual bottleneck with contiguous
HVX vector addition. EXP-0041 reused that structure for asymmetric-U8 residual
arithmetic using the accepted lane-preserving Q14 implementation. That
arithmetic is still active and correct in EXP-0052.

The present cost has a different source. EXP-0048 keeps O-projection output in
native integer-HMX tile order, and EXP-0046 does the same for Down output.
Each residual consumer therefore gathers native output tiles, applies the Q14
sum, and emits either the next native activation carrier or the legal
row-major block output. Removing the old full-tensor unpack was a net win, but
the fused gather/residual traversals currently execute on one HVX context even
though the persistent three-worker Attention pool is idle at both boundaries.

EXP-0053 reuses the existing arithmetic and persistent workers. Rows are split
into bounded tasks consumed by the main HVX context and the three already
created worker contexts. The native HMX output, row-major skip tensor,
asymmetric qparams, Q14 rounding and saturation, Post-Attention RMSNorm, native
Gate/Up carrier, and final row-major output remain byte-identical.

## Fixed contract and gates

- The Execution Unit is the real Qwen3 layer-14 complete block at M=64.
- The direct control is `W4U8-EXP0052-QK-PREP-HEAD-SCHEDULER`.
- QKV, Q/K preparation, integer Attention, O, Gate/Up, Down, weights, qparams,
  HMX commands, DMA traffic and every non-residual schedule are immutable.
- The candidate may reuse the three persistent HVX pool workers and the main
  HVX context only after preceding work has joined. It may not create another
  FastRPC invocation, HMX owner, persistent tensor, or intermediate DDR
  boundary.
- Post-Attention residual/RMSNorm tasks and Final Residual tasks operate on
  disjoint complete rows. Every row must be claimed exactly once.
- Q14 arithmetic, rounding, saturation, output codes and tensor layouts remain
  unchanged. Final block output must be byte-exact to EXP-0052 and the
  independent implementation reference must report zero mismatches and
  maximum error 0 LSB.
- Exactly 8 MiB VTCM, zero intermediate DDR, zero spill/fill, one FastRPC
  Execution Unit, one HMX owner and no QNN path remain hard gates.
- The local speed gate requires the combined two-residual ledger and complete
  Host wall to improve strictly over the paired control at repeat one and
  repeat ten. Each individual residual boundary is reported even if only the
  combined gate is decisive.
- Formal selection uses seven interleaved paired rounds on one stable boot and
  closes every PC-027 profiling field. A local pass creates only a candidate;
  baseline promotion remains a user decision.

## Implementation

Source commit `0eff58cc2291c6883324ec31dc8174a8e089b6bd` retains the
EXP-0052 serial control and adds one `hvx_fused_post_norm_pool4` candidate.
The 64 rows at each residual boundary become sixteen four-row tasks. The main
HVX context and the three persistent Attention workers atomically claim those
tasks only after preceding work has joined. Post-Attention tasks perform the
unchanged native-output gather, Q14 residual sum and U8 RMSNorm/native Gate-Up
store. Final tasks perform the unchanged native-output gather and Q14 sum into
the row-major block output. Telemetry proves sixteen completed tasks per
boundary per block.

The first complete collection at
`D:/llm_exp/results/qwen3-block-htp/exp0053/20260829T171736Z_0eff58cc2291_formal`
is excluded from formal evidence. All device runs completed, but the validator
referenced the fixed Q/K task count without adding that field to its summary
set. Commit `668a9145ef434abf0ea04567d9dea6b8b863d627` fixes only that
evidence-validator bookkeeping issue; a fresh complete formal run was used.

## Decision and interpretation

The local gate passes and EXP-0053 is the latest eligible W4U8 candidate. It
does not change the Selected Baseline because promotion remains a user
decision.

This result confirms that the earlier residual problem was only partly the
scalar-arithmetic issue solved by EXP-0026 and EXP-0041. Once O and Down stay
in native HMX output order, the remaining cost is the single-context gather
plus residual traversal. Reusing already-resident HVX workers removes that
serial tail without giving back the native-layout boundary wins from EXP-0046
and EXP-0048. The full PC-027 report is retained in
`docs/experiments/EXP-0053-PROFILING.md`.
