# EXP-0004 — Qwen3 middle-block U8×S8 projection shapes

## Approval

Approved by the user on 2026-08-27 by requesting implementation of the real
Qwen3 projection shapes proposed after EXP-0003 passed.

## Objective

Extend the proven Projection Probe to the two distinct Linear shapes in the
Qwen3-1.7B middle-block MLP without QNN. This experiment must prove that the
project-owned runtime can tile, stage, accumulate, and assemble model-shaped
gate/up and down projections while retaining explicit VTCM ownership and an
independent exact arithmetic reference.

## Fixed arithmetic scope

The execution-row scope remains the native integer-HMX `M=64`. The two
projection variants are:

- `gate_up`: `K=2048, N=6144`, representing both gate_proj and up_proj.
- `down`: `K=6144, N=2048`, representing down_proj.

Both use asymmetric U8 activation with zero point 128, signed S8 weights with
zero point 0, S32 accumulation, and one saturated U8 output conversion. The
authoritative Host reference is
`clamp(sum_k((activation[m,k] - 128) * weight[k,n]), 0, 255)` over the complete
row-major shape. Identity-like, signed, structured, and saturation-boundary
patterns must match byte-for-byte for both variants.

This is a W8-carrier substrate experiment. It does not introduce W4 storage,
per-channel scales, RMSNorm, activation functions, residuals, or a complete
Qwen3 block.

## Physical-plan scope

The complete activation is staged once and remains in VTCM for all N tiles.
The complete physical output also remains in VTCM until one final row-major
Native Boundary copy. DDR weight bundles are streamed through two VTCM slots
with explicit ownership, User DMA completion, DMA Publication Barriers, and
producer/consumer semaphores.

K depth is represented as continuous integer-HMX `deep:cm` streams. A single
stream may cover at most 32 architectural K tiles; larger K dimensions are
split into ordered stream chunks while retaining the same accumulator until
the output tile is converted. The declared VTCM plan must fit both variants
inside one 1 MiB project-owned allocation without using DDR intermediates.

Timing must record activation staging, weight staging, HMX compute, producer
and consumer waits, output assembly, full DSP scope, and Host wall time. The
timing run uses repeat count 10 to exercise sustained slot reuse without
turning the bring-up into a long benchmark. There is no speed threshold.

## Hard gate

Both shapes must build for V79, retain identifiable integer-HMX and User DMA
instructions, and execute through one FastRPC invocation per run with no QNN
or QAIRT dependency. For each shape, all four patterns at repeat counts 1 and
10 must return exact output, valid counters and timings, correct shape
metadata, and zero DSP, DMA, resource, or synchronization errors.

The expected logical HMX tile-pair count is 12,288 per projection repeat for
both variants. Buffer reuse and DMA counts must agree with the declared K/N
tile counts. Any FastRPC stall is inspected without killing the device process
or entering an automatic reboot loop.

Passing establishes model-shaped U8×S8 Projection Probes only. It is not a
complete MLP, a W4 implementation, a performance winner, or a Selected
Baseline.
