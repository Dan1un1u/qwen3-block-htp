# EXP-0163 — Full-stack W4U8 continuous decode through six dynamic cache seals

## Decision and purpose

The user promoted EXP-0162 as the Selected Full-Stack W4U8 Cache-Native
Baseline and approved the next experiment on 2026-09-03. EXP-0162 proves one
dynamic 32-token tail seal across all 28 transformer layers. EXP-0163 tests
whether the same physical and lifecycle contract remains correct and useful
over a materially longer continuous session rather than only near the first
transition.

One real M64 prefill is followed by 192 continuous decode steps at positions
64 through 255. Capacity is 257 rather than 256 so the final append at position
255 can publish the eighth immutable segment while retaining a valid empty
tail slot. The run crosses six new seal boundaries at positions 95, 127, 159,
191, 223 and 255.

## Execution and comparison boundary

The immutable source parent is EXP-0162 commit
`a3b9607dee88719341763204566bac8a9ed5e3cd`. The direct control is the same
EXP-0160-compatible monolithic compact-base plus delta-journal cache rebuilt at
capacity 257. The candidate is the promoted EXP-0162 dynamic segmented cache,
unchanged except for generalized capacity and replay length.

Both variants use identical inputs, W4 values, qparams, projection schedules,
integer QK/log2-Softmax/AV mathematics, one HMX owner and output boundary. The
Host generator independently computes all 193 complete-stack outputs, every
per-layer current K/V append and every dynamic segment state. Runtime K/V is
not imported.

## Gates

Correctness requires zero U8 LSB error for all 193 outputs and all retained
per-layer cache references. Every one of the six transitions must produce
exactly one seal per layer; each sealed segment is published once, remains
immutable, and is consumed correctly on subsequent steps. Only the active
tail may be modified.

Formal execution requires exactly 8 MiB VTCM, zero intermediate DDR, zero
spill/fill, one FastRPC invocation per full-stack step, one HMX owner and no
QNN. Attention scratch remains bounded independently of valid length, and no
full-prefix carrier reconstruction is permitted.

The candidate prefill must remain within one percent of the same-binary
control. Positions 64-71 must not regress outside paired device noise. The
complete positions 64-255 window and the final positions 224-255 window must
both be strictly faster under ten order-rotated sessions. Every seal step and
its following amortization window are reported separately; an individual seal
step is not required to beat the control because sealing is the deliberate
one-time cost being amortized.

Any correctness, lifecycle, structural or physical failure stops before
performance adoption. Passing does not automatically promote a new baseline.
