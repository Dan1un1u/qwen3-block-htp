## 当前证据及其边界

权威来源：[EXP-0242 results](experiments/EXP-0242-RESULTS.md)。已重新核对 evidence ledger 5c6e1f92088a9e7ff49aa27cf1ab6a59f13ace3b46ef34f997474ec022d92977 及 summary、outlier_mechanism、calibration、run_manifest 的原有哈希。

固定复核面板 PPL：F16 24.774821，C64 W4A16 26.296039，全部边界静态 minmax A8 151935.950477，最佳静态裁剪 A8 32468.413936。第 3 层 L02 的 SwiGLU 尖峰集中在 128/128 校准窗口的第 0 个 token，最大绝对值 16688，单通道占 99.992% 平方能量。进入 Down/残差后，残差 minmax 步长 54.55 对应 |x| 中位数 0.281，至少 99.989% 校准元素进入零码区间。

这些窗口是正文截取，不能直接等同真实聊天模板或持续 KV 会话；尚未比较 F16 激活分布，也未验证 attention-sink 因果机制。残差-only A8 崩坏；保留残差 A16 的软件归因对照仍为 PPL160.43，所以单独修残差不保证完整模型恢复。低全张量 MSE 不能作为质量验收替代物。当前软件 QDQ 也不是 HMX/DSP 的逐位复现。

## 顺序 1：先确认首位置效应及真实输入形态

冻结 C64 的全部 W4 codes/scales、norm、embedding、head。增加 F16 参照激活，形成 F16/C64 与正文窗口/真实 Qwen3 chat template 的对照。使用平衡中英文 Wiki/news 的校准或诊断数据，改变窗口起点、首 token 内容、有限上下文长度，观察尖峰跟随 token 身份、窗口相对位置还是新建 KV 会话。增加 prefill 后逐 token 读取/更新 KV 的连续路径；不能只用 use_cache=False 的整段前向声称 cache 已验证。

先看 L00–L03、SwiGLU→Down→残差，再检查全层是否仍有其它尖峰。图与指标同时区分首 token、正文 token、通道、饱和率、零码率和逐 token 误差；除全张量 MSE 外，保留普通 token 的统计和 PPL。若 F16 不出现而 C64 出现，优先检查 W4 造成的异常放大；若真实模板已隔离峰值，则优先修正校准/服务输入的一致性。这些分支均需结果支持，不能预设结论。

## 顺序 2：主线采用 PrefixQuant 风格的固定前缀/KV 隔离消融

学术依据：[PrefixQuant v2](https://arxiv.org/html/2410.05265v2) 的核心是把易出现异常的固定前缀离线预填充，保存并复用 KV，隔离正文中的 token 异常；其完整算法还包括旋转和训练成分。[官方实现](https://github.com/ChenMnZ/PrefixQuant) 提供前缀、旋转、量化与可选微调开关。我们优先只借鉴前缀机制，测试其独立贡献，不照搬整套 recipe 或宣称论文收益会迁移到 Qwen3。

限定少量、预先冻结的短前缀候选，候选来自校准数据，开发集用于选择。保留自然聊天前缀和同长度普通前缀对照。首次先不训练、不旋转、不修改 C64 权重。可缓存的是由固定前缀独立计算的 KV，不得混入当前用户正文、评分目标或未来 token。

前缀条件下重新校准正文静态 A8。前缀中间激活离线处理不能成为无依据排除在线异常的借口；正文所有真实在线激活必须纳入观察与量化。必须记录并实际测试前缀 KV 的目标量化格式、scale/zero-point、RoPE position、有效长度、mask 和会话复制/复用语义；不以未量化前缀 cache 的理想结果代替设备可行候选。如果现有统一 KV 载体无法容纳前缀，先报告这个兼容性障碍，不默认增加高精度旁路或 K 分组重缩放。

每个前缀都配套 F16 与 C64 A16 参照，报告两类变化：前缀本身相对原输入的质量变化，以及相同前缀下 A8 相对 A16 的额外损失。仅对相同正文 targets 评分，前缀不计入 PPL 分母，原正文上下文不能为腾出前缀空间被悄悄截短。至少验证整段前向与 prefix-cache+prefill/decode 两条路径。阶段目标是同时消除正文范围支配和恢复 PPL，不能以峰值变小或几万 PPL 降到几千就算可用。

选择规则与预算在新实验开始前冻结。继续用约 16K 校准 tokens / 2K 开发 targets 的轻量规模；最终新候选用另行冻结、未参与选择的约 8K targets，保留 EXP0242 面板作已暴露回归证据。分别报告 A8 增量损失和相对 F16 的总损失。现有总体验收仍为 PC050 整体5%/分域10%；C64 在 EXP0242 面板已比 F16 高6.14%，因此即使 A8 接近 C64 也不能自动宣布整套 recipe 通过既有最终门槛。这里没有新增或放宽验收阈值。

## 顺序 3：根据剩余异常决定后备方案

如果前缀能去掉位置相关尖峰、但普通 token 仍存在通道不均衡，再评估温和的通道缩放或局部 A8 校准优化。任何需要重新缩放/旋转权重的候选必须分开报告 W4A16 的损失与 A8 的增益，避免把损失迁移到仅4bit的权重后误判成功；C64 原包继续作为冻结对照。

如果残差中的巨大值仍是主因，后备旋转需要覆盖残差坐标 R1；只有 SwiGLU→Down 输入仍是瓶颈时才加入局部 R4。按行向量记号，R4 的理想等价关系为 (xH)(H^T W)=xW，所以它可改变 Down 输入的分布，却不自动改变 Down 输出/原残差坐标的巨大值。只加 R4 无法从等价变换本身消除该残差主因。[QuaRot](https://arxiv.org/abs/2404.00456) 同时处理残差和其它激活位置，是覆盖范围的参考。以前 W4A16 R1/R2 的负结果不等价于 A8 下无效，但也不构成重启大规模旋转训练的依据。先验证未量化等价性、最终 per-channel W4 格式和 A8 的净收益，再考虑学习矩阵。

本阶段不默认采用残差 A16、异常通道高精度旁路或分组权重部署；若后续证据迫使放宽表示方式，应单独讨论。现有残差 A16 实验仅是归因证据。

## 设备阶段与保持的约束

优先候选需保留原生 HMX packed-W4 的 signed codes、per-output scale 及 U8 zero-point 修正，不引入 K-group 权重尺度。固定前缀方案在算法上不要求改变线性权重格式，这是选择它优先验证的硬件理由；具体 KV 格式兼容性和性能仍需实测，不能声称零开销。

软件准确性恢复后，单独登记 HMX/DSP 数值验证与单层完整 Host-wall gate。保持五轮 short、十轮 formal，以及 prefill/decode 任一稳定慢超过10%就停止全模型测试的约束。前缀初始化、拷贝、增加的 attention 长度及 KV 容量都进入成本账；同时报告首次会话和缓存复用场景，不能只报隐藏初始化成本的热路径。全模型只能在该 gate 通过后开展，E2E 必须实测。

暂停继续扫通用 clipping、大规模学习旋转和 LPBQ/per-group 性能改造。其它 recipe 冻结，不改变 Selected Baseline。本次只更新方向，不注册 active experiment、不生成权重、不运行新模型或设备。
